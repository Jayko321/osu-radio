# T06. Previous: порог 3 секунды для кнопки и системных контролов

Состояние: выполнено, проверено (тесты клиента с подменённым движком; реальный звук не проверялся).
Источники: [спецификация](../../specs/shuffle-repeat.md), R9;
[решение: Previous](../shuffle-repeat.md#клиент-osu-radio-client).
Зависимости: нет (серверное поведение «первая запись не переходит к последней»
проверяется в T03). Меняет те же `controller.rs`/`view_models/player.rs`, что T05:
выполнять после T05 или сверить его изменения перед работой.

## Результат

Previous (кнопка и системный `Event::Previous`) при позиции звучащего трека больше
3 с перематывает его в 0 локально, без серверной команды, без `Started` и с
сохранением паузы; иначе отправляет обычный Previous.

## Границы и контекст

- Владение: `crates/osu-radio-client` ([view_models/player.rs](../../../crates/osu-radio-client/src/view_models/player.rs),
  [controller.rs](../../../crates/osu-radio-client/src/controller.rs)); тесты там же.
- `AppCommand::Previous` сейчас вызывает `queue_playback(Previous)`, системный
  `Event::Previous` в `system_event()` — тоже. Свести оба к одному методу
  `PlayerViewModel`: если текущий запуск звучит в рабочем потоке
  (`system_worker_current`, есть источник) и показанная позиция больше 3 с
  (с учётом скорости, как в `presentation()`) — `playback::Command::Seek` в 0 с
  текущим token; иначе обычный Previous. Ровно 3 с — обычный Previous.
- Переиспользовать `seek_selected()`/`system_seek()`: локальный seek в
  [playback.rs](../../../crates/osu-radio-client/src/playback.rs) проверяет token,
  не меняет паузу и не шлёт `Started`. Новую логику паузы не писать.
- Клавиатурной привязки Previous в QML нет: «клавиатура» — медиаклавиши
  через `system_event`.

## Проверка и приёмка

Клиентские тесты с подменённым движком (в стиле существующих тестов
`PlayerViewModel`):

- позиция 5 с: в движок уходит Seek(0) с текущим token, на сервер ничего не
  отправлено, `Started` не отправлен, пауза сохранена (на паузе остаётся пауза);
- позиция 2 с и ровно 3 с: на сервер уходит Previous, Seek нет;
- ускорение/замедление: порог сравнивается с показанной, а не сырой позицией;
- трек не звучит в рабочем потоке (загрузка, нет источника, устаревший token):
  обычный Previous;
- те же сценарии для системного `Event::Previous` (5 с и 2 с).

`cargo test -p osu-radio-client --lib --locked` (с `--features mock` и без),
Clippy из матрицы клиента. Реальное воспроизведение этой карточкой не доказывается.

## Отчёт о выполнении

Изменённые файлы (2026-10-24), `crates/osu-radio-client/src/`:

- `view_models/player.rs`: `PlayerViewModel::previous()` — единое правило. Если
  запуск звучит в рабочем потоке (`system_worker_current()`, есть источник, нет
  загрузки и ошибки, состояние Playing/Paused) и показанная позиция
  (`scaled(position, 100, speed_percent)`, как в `presentation()`) строго больше
  3 с — эффект `Command::Seek` в 0 с `expected_id` и token текущего назначения;
  иначе `queue_playback(Previous)`. Системный `Event::Previous` (при
  `capabilities.previous`) вызывает тот же метод.
- `controller.rs`, `controller/coordinator.rs`: `AppCommand::Previous` → `previous()`.
- Тесты в `controller/system_media/tests.rs`: перебор «5 с, 5 с на паузе, ровно 3 с,
  2 с, 5 с при 2x (показано 2,5 с), 3,5 с при 0,5x (показано 7 с)» для кнопки и
  системного события — на сервер уходит Previous или ничего; не звучит (загрузка,
  нет источника, чужой token) — всегда Previous; ни одного POST на сервер в
  локальных случаях; с фейковым рабочим потоком — Seek в 0 увеличивает
  `seek_serial`, позиция 0, состояние воспроизведения прежнее, `commands` и
  `pending_start` пусты.

Проверки (выполнены): `cargo test -p osu-radio-client --lib --locked` — 235 passed,
4 ignored; с `--features mock` — 253 passed, 4 ignored; Clippy `-D warnings` в обоих
вариантах и `cargo fmt --check` чисты. Тест на настоящем `AppCommand::Seek` как
подготовка позиции использует существующий путь.

Наблюдение (вне объёма): `can_previous` из сервера ложен на первой записи, поэтому
кнопка Previous (QML `canPrevious`) и системный `capabilities.previous` там
отключены, и локальный рестарт на первой записи при позиции > 3 с недостижим.
`AppCommand::Previous` сам по `can_previous` не блокируется. Включать Previous по
позиции — решение о поведении, не принималось.

Не проверено: реальный звук и устройство (T10/T11); сервер на «первой записи»
проверяется в T03.
