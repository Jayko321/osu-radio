# T03. Repeat All и Repeat One на сервере

Состояние: выполнено, проверено (SQLite, PostgreSQL).
Источники: [спецификация](../../specs/shuffle-repeat.md), R3, R4, R7, R9 (сервисная
часть); [решение: Repeat All/One](../shuffle-repeat.md#сервис-очереди-radio-services).
Зависимости: T02 — команда `SetRepeat`, поля режимов в состоянии и назначении.

## Результат

Очередь повторяет трек или весь список по режиму; повтор Repeat One не пишет
прослушивание; ошибки и недоступные записи не приводят к зацикливанию;
`can_next` отражает обход по кругу.

## Границы и контекст

- Владение: `crates/radio-services` ([queue.rs](../../../crates/radio-services/src/queue.rs):
  `apply`, `forward`, `launch`, `exhaust`, `assignment`, ветка `Started`),
  тесты очереди. Не менять БД-модель (поля есть из T01) и сервер.
- Repeat All: `forward()` при `All` после поиска от `start` до конца продолжает
  с `0` до `start`; нет доступных — `exhaust()`. Применимо ко всем продвижениям:
  Finished, Next, Failed, удаление текущей, неудачная проверка источника. После
  Failed поиск не возвращается к упавшей записи (одна запись не зацикливается).
  Previous не переходит к последней; на первой записи — прежний перезапуск первой.
  `can_next` при `All` — есть ли хоть одна доступная запись.
- Repeat One: Finished при `One` и доступной текущей → `launch()` той же позиции
  (новый token, клиент перезапускает трек) и `repeat_launch = true`; любой другой
  `launch()` сбрасывает признак; `Started` при `repeat_launch` историю не пишет
  (`ListeningHistoryRepository::record_started` дедуплицирует только по последнему
  token, поэтому нужен этот признак). Next/Previous/Failed идут по списку без
  перехода по кругу.
- Порядок записей при Repeat All не меняется (повторного shuffle нет).

## Проверка и приёмка

Сервисные тесты на SQLite и PostgreSQL:

- One: Finished перезапускает ту же запись с новым token; `Started` нового token
  не обновляет дату прослушивания (история до и после совпадает), а `Started`
  обычного запуска после Next — обновляет; Next/Previous переходят, режим One
  сохраняется; Finished при недоступной текущей идёт дальше;
- All: Finished и Next на последней доступной → первая доступная, порядок прежний
  (в том числе при включённом shuffle); недоступные пропускаются; `can_next` на
  последней записи `true`; Previous на первой записи перезапускает первую;
- R7: Failed при One уходит на следующую запись; при All без доступных записей —
  `Stopped`; единственная запись, пометившаяся недоступной при All, не
  зацикливается; удаление текущей последней записи при All переходит к началу;
- при Off поведение переходов совпадает с прежним (существующие тесты).

`cargo test -p radio-db -p radio-services --locked`, PostgreSQL и Clippy по матрице.

## Отчёт о выполнении

Изменено:

- [queue.rs](../../../crates/radio-services/src/queue.rs): `forward_except()` —
  при `All` поиск после конца продолжается с `0` (`forward()` его вызывает без
  исключения); `Failed` исключает упавшую запись, поэтому одна запись не
  зацикливается, даже если не помечена недоступной (устаревший launch);
  `Finished` при `One` и доступной текущей → `launch()` + `repeat_launch = true`;
  `launch()` сбрасывает признак; `Started` при `repeat_launch` историю не пишет;
  `can_next` при `All` ищет по всему списку.
- Тесты: новый [queue_repeat.rs](../../../crates/radio-services/src/tests/queue_repeat.rs)
  (подключён в `tests.rs` и `tests/queue.rs`); в `queue_modes.rs` хелперы
  `cmd`/`shuffle`/`start`/`entry_ids` стали `pub(super)`.

Покрыто (SQLite и PostgreSQL, один контракт): One — перезапуск той же записи с
новым token, дата прослушивания не меняется на `Started` повтора и меняется на
`Started` после Next, Next/Previous сохраняют режим, недоступная текущая → дальше,
Failed → дальше, Next в конце не переходит по кругу; All — Finished/Next на
последней → первая, порядок прежний (с shuffle и без), недоступные пропускаются,
`can_next` на последней, Previous на первой перезапускает первую; R7 — Failed при
All переходит к началу, без доступных → `Stopped`, одна запись (в том числе с
устаревшим launch) → `Stopped`, удаление текущей последней и неудачная проверка
последней записи → начало. Off — существующие тесты без изменений.

Проверки:

- `cargo test -p radio-db -p radio-services --locked` — успешно (SQLite).
- `cargo clippy -p radio-db -p radio-services --all-targets --locked -- -D warnings`
  и то же с `--no-default-features --features postgres` — без замечаний.
- PostgreSQL: `cargo test -p radio-db` и `-p radio-services` с `--no-default-features
  --features postgres -- --include-ignored` (services с `--skip synthetic_search_timings`)
  на одноразовом кластере (порт 54329, БД `radio_db_test_*`) — успешно; кластер удалён.
- Мутации: без `!state.repeat_launch` и без `except` в `forward_except` новые
  тесты падают.

Непроверено: серверные и клиентские пути (T04+), `osu-radio-server` не собирался.
Расхождений с планом нет. Руководства не обновлялись (по плану — T10).
