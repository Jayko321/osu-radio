# T08. Крейт медиаконтролов: shuffle и repeat в MPRIS и SMTC

Состояние: выполнено на Linux; Windows-часть не собиралась и не проверялась.
Источники: [спецификация](../../specs/shuffle-repeat.md), R10;
[решение: медиаконтролы](../shuffle-repeat.md#медиаконтролы-osu-radio-media-controls-r10).
Зависимости: нет (независим от клиентских карточек; подключение — T09).

## Результат

Крейт принимает режимы в снимке, публикует их в MPRIS и SMTC и сообщает
запросы системы на их изменение событиями. Клиент о режимах ещё не знает.

## Границы и контекст

- Владение: `crates/osu-radio-media-controls` ([lib.rs](../../../crates/osu-radio-media-controls/src/lib.rs),
  [linux/player.rs](../../../crates/osu-radio-media-controls/src/linux/player.rs),
  [windows/mod.rs](../../../crates/osu-radio-media-controls/src/windows/mod.rs)).
  Клиент не менять; правила воспроизведения остаются за клиентом.
- Собственный нейтральный `Repeat { Off, One, All }`; `Snapshot { shuffle, repeat }`,
  `Capabilities { set_modes }`, `Event::SetShuffle(bool)`, `Event::SetRepeat(Repeat)`.
  Проверить всех, кто строит `Snapshot`/`Capabilities` (в том числе клиент и тесты),
  и сохранить их компилируемость с прежним поведением.
- MPRIS: `Shuffle` и `LoopStatus` (None/Track/Playlist) читаются из снимка (сейчас
  возвращают unsupported); сеттеры отправляют события; изменения публикуются через
  PropertiesChanged; при `!set_modes` сеттеры возвращают ошибку.
- SMTC: `SetShuffleEnabled`/`SetAutoRepeatMode` из снимка; обработчики
  `ShuffleEnabledChangeRequested`/`AutoRepeatModeChangeRequested` → события; снятие
  обработчиков в существующем cleanup. Фича `Media` в `windows 0.62` уже включена.

## Проверка и приёмка

- Тесты MPRIS-адаптера на Linux: свойства отражают снимок (все три значения
  `LoopStatus`), сеттеры порождают нужные события, PropertiesChanged при изменении
  снимка, ошибка сеттера при `!set_modes`, неизвестное значение `LoopStatus`
  отвергается;
- Windows: логика сопоставления режимов вынесена в тестируемую на Linux функцию,
  если это возможно без новой инфраструктуры; сама сборка под Windows и SMTC —
  не проверяются на Linux, критерий остаётся непроверенным до T11.

`cargo test -p osu-radio-media-controls --locked`; Clippy крейта с `-D warnings`.
Физический `playerctl` — в T11.

## Отчёт о выполнении

**Изменённые файлы** (`crates/osu-radio-media-controls`):

- `src/lib.rs`: `Repeat { Off, One, All }`, `Snapshot { shuffle, repeat }`,
  `Capabilities { set_modes }`, `Event::SetShuffle`, `Event::SetRepeat`.
- `src/linux/player.rs`, `src/linux/transform.rs`: `Shuffle`/`LoopStatus` читаются из
  опубликованного снимка; сеттеры шлют события и при `!set_modes` возвращают
  `NotSupported`; `changes` публикует `Shuffle` и `LoopStatus`. Отображение
  `Repeat` ↔ `LoopStatus` лежит в `transform.rs`, а не в `conversion.rs`: тот файл
  подключается в `tests/linux.rs` на любом хосте, где `mpris-server` нет.
- `src/windows/mod.rs`: `SetShuffleEnabled`/`SetAutoRepeatMode` при публикации,
  обработчики `ShuffleEnabledChangeRequested`/`AutoRepeatModeChangeRequested`,
  снятие токенов в `close`; `repeat_to_native`/`repeat_from_native`.
- Тесты: `src/linux/transform/tests.rs` (отображение, diff), `src/windows/tests.rs`
  (отображение, неизвестный режим игнорируется), `tests/linux/protocol.rs`
  (`modes_follow_snapshot_and_requests_become_events`).
- Клиент (только компилируемость, поведение прежнее):
  `crates/osu-radio-client/src/view_models/player.rs` — `shuffle: false`,
  `repeat: Repeat::Off`, `set_modes: false` в `system_media_snapshot`; `system_event`
  новые события игнорирует через существующую ветку `_`. T09 подключает их по-настоящему.

**Проверки (Linux)**

- `cargo test -p osu-radio-media-controls --locked` — успешно (4 модульных/интеграционных
  теста; протокольные помечены `ignored`).
- `cargo test -p osu-radio-media-controls --test linux --locked -- --ignored` (приватный
  `dbus-daemon` создаёт сам харнесс) — 6 из 6 успешно, включая новый протокольный:
  свойства для трёх `LoopStatus`, события сеттеров, `PropertiesChanged`, ошибка
  сеттеров при `!set_modes`, `LoopStatus="Bogus"` отвергнут и ничего не ставит в очередь.
- `cargo clippy -p osu-radio-media-controls -p osu-radio-client --all-targets --locked -- -D warnings` — чисто.
- `cargo test -p osu-radio-client --locked system_media` — 21 успешно.

**Не проверено**

- Сборка под Windows и SMTC: цели `windows` нет, код сверен только с исходниками
  `windows 0.62.2` (имена методов и типов). Критерий остаётся открытым до T11.
- Физический `playerctl` — T11.

**Расхождения**

- На Windows обработчики не сверяются с `set_modes` (у SMTC нет флага доступности
  режимов, а кнопки транспорта в адаптере тоже не фильтруются); ограничение по
  `set_modes` остаётся за клиентом в T09, как и для `Play`.
- Правка клиента вышла за «клиент не менять» минимально и вынужденно: иначе его
  литералы `Snapshot`/`Capabilities` перестают компилироваться.
