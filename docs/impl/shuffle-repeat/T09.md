# T09. Клиент ↔ системные медиаконтролы: режимы

Состояние: выполнено, проверено (юнит-тесты); нативные виджеты не проверялись.
Источники: [спецификация](../../specs/shuffle-repeat.md), R10;
[решение: клиент](../shuffle-repeat.md#клиент-osu-radio-client).
Зависимости: T05 (презентация и команды режимов), T08 (`Repeat`, `Snapshot`,
`Capabilities.set_modes`, `Event::SetShuffle/SetRepeat`). Меняет `player.rs`,
как T05 и T06: сверить их результаты перед работой.

## Результат

Системные виджеты видят актуальные shuffle и repeat и могут их переключать; запрос
системы проходит тот же путь, что кнопки приложения.

## Границы и контекст

- Владение: `crates/osu-radio-client` ([view_models/player.rs](../../../crates/osu-radio-client/src/view_models/player.rs):
  `system_snapshot()`, `system_event()`). Крейт media-controls не менять.
- `system_snapshot()` передаёт режимы из последнего назначения и `set_modes`
  по готовности (как другие capabilities); `system_event()` превращает
  `SetShuffle(enabled)`/`SetRepeat(mode)` в команды из T05 только при готовности,
  иначе игнорирует. Сопоставление `RepeatMode` ↔ `Repeat` — в одном месте.

## Проверка и приёмка

Клиентские тесты (уже есть проверки `system_snapshot`/`system_event`):

- снимок отражает Off/All/One и shuffle, `set_modes` выключен без соединения;
- `Event::SetShuffle(true)` и `SetRepeat(One)` ставят соответствующие команды
  в полосу очереди; при неготовности — нет команды;
- после ответа сервера следующий снимок содержит новое значение.

`cargo test -p osu-radio-client --lib --locked` (с `mock` и без), Clippy клиента
и `cargo test -p osu-radio-media-controls --locked`. Нативные виджеты — в T11.

## Отчёт о выполнении

**Изменённые файлы** (`crates/osu-radio-client`):

- `src/models.rs`: `From<RepeatMode> for Repeat` и обратно — единственное место
  сопоставления.
- `src/view_models/player.rs`: `system_snapshot()` берёт `shuffle`/`repeat` из
  последнего назначения (без него — Off) и ставит `set_modes = ready && assignment`;
  `system_event()` превращает `SetShuffle`/`SetRepeat` в `PlaybackCommand::SetShuffle`/
  `SetRepeat` только при `capabilities.set_modes`, иначе событие отбрасывается
  существующей веткой `_`. Заглушки T08 (`false`/`Off`) заменены.
- `src/controller/system_media/tests.rs`: `modes_reach_snapshot_and_system_requests_become_commands`.
- Крейт media-controls не менялся.

**Проверки**

- `cargo test -p osu-radio-client --lib --locked` — 236 успешно, 4 ignored; с
  `--features mock` — 254 успешно, 4 ignored.
- Новый тест: снимок отражает Off/All/One и shuffle; `SetShuffle(true)` и
  `SetRepeat(One)` дают команды в очереди; без назначения `set_modes` выключен и
  команд нет.
- `cargo clippy -p osu-radio-media-controls -p osu-radio-client --all-targets --locked -- -D warnings` — чисто.
- `cargo test -p osu-radio-media-controls --locked` — успешно.

**Не проверено / расхождения**

- Критерий «после ответа сервера следующий снимок содержит новое значение» проверен
  косвенно: снимок читает `assignment`, а его обновление ответом сервера — путь T05;
  тест выставляет `assignment` напрямую, без HTTP-ответа.
- Условие «не соединён» покрыто отсутствием назначения (без него выключены и
  `can_change_modes`); `connected = false` отдельным кейсом не проверялся.
- Нативные виджеты MPRIS/SMTC и `playerctl` — T11.
