# T05. Клиент: режимы в моделях, командах, презентации и моке

Состояние: выполнено, проверено (юнит-тесты клиента, без реального сервера).
Источники: [спецификация](../../specs/shuffle-repeat.md), R2 (логика цикла), R6, R8;
[решение: клиент](../shuffle-repeat.md#клиент-osu-radio-client).
Зависимости: T04 — JSON команд `set_shuffle`/`set_repeat` и поля `shuffle`/`repeat`.

## Результат

Общий клиент знает режимы, переключает их командами и показывает в презентации
плеера; офлайн-мок хранит и переключает те же режимы. Qt и медиаконтролы
подключаются позже (T07, T09).

## Границы и контекст

- Владение: `crates/osu-radio-client` ([models.rs](../../../crates/osu-radio-client/src/models.rs),
  [controller.rs](../../../crates/osu-radio-client/src/controller.rs),
  [view_models/player.rs](../../../crates/osu-radio-client/src/view_models/player.rs),
  [mock.rs](../../../crates/osu-radio-client/src/mock.rs),
  [mock/queue.rs](../../../crates/osu-radio-client/src/mock/queue.rs)). Qt и
  media-controls не менять.
- `models.rs`: `RepeatMode`, поля `shuffle`/`repeat` в `PlaybackAssignment` с
  `#[serde(default)]` (как `current_playlist_item_id`: старый внешний сервер даёт
  Off/Off), варианты `PlaybackCommand::SetShuffle/SetRepeat`; проверить место,
  где разбираются ответы и строки потока.
- `AppCommand::ToggleShuffle` и `AppCommand::CycleRepeat`: `PlayerViewModel`
  вычисляет цель из последнего назначения (Off → All → One → Off) и ставит команду
  в `queue_playback`; логика остаётся toolkit-free. Известное ограничение
  (двойной клик до ответа) не исправляется.
- `PlayerPresentation`: `shuffle`, `repeat`, `can_change_modes` (есть соединение
  и назначение). UI-классы и иконки в клиентские модели не добавлять.
- Мок: `MockQueue` хранит `shuffle`/`repeat`, новые `Action` переключают их офлайн;
  записи не перемешиваются (R8 — показ и переключение, не серверный алгоритм).
  Действия из QML разбираются в `apps/osu-radio-qt/src/bridge.rs` — его правит T07;
  опубликовать в отчёте имена новых `Action`.

## Проверка и приёмка

Клиентские unit-тесты (контроллер и view-model с подменённым транспортом):

- цикл Off → All → One → Off порождает ожидаемые команды и значения; toggle
  shuffle инвертирует; команда ставится в ту же полосу, что Next/Previous;
- без соединения или без назначения `can_change_modes == false`, команды
  не отправляются;
- ответ без полей режимов разбирается как Off/Off;
- мок: переключение режимов меняет состояние презентации без сервера.

`cargo test -p osu-radio-client --lib --locked` и с `--features mock`;
`cargo clippy -p osu-radio-client --all-targets --locked -- -D warnings` (в обоих
состояниях feature). Сборка этих крейтов может потребовать `LIBCLANG_PATH`.

## Отчёт о выполнении

Изменённые файлы (2026-10-24), все в `crates/osu-radio-client/src/`:

- `models.rs`: `RepeatMode` (`Off/All/One`, serde snake_case, `cycled()`); в
  `PlaybackAssignment` поля `shuffle`, `repeat` с `#[serde(default)]`;
  `PlaybackCommand::SetShuffle { enabled }`, `SetRepeat { mode }`.
- `controller.rs`, `controller/coordinator.rs`: `AppCommand::ToggleShuffle`,
  `AppCommand::CycleRepeat`.
- `view_models/player.rs`: `PlayerViewModel::toggle_shuffle`/`cycle_repeat`
  (цель от последнего назначения, нет назначения — ничего; без соединения
  `queue_playback` сообщает ошибку и не ставит команду); `PlayerPresentation`
  получила `shuffle`, `repeat`, `can_change_modes` (= соединение и назначение).
- `mock/queue.rs`, `mock.rs`: `MockQueue.shuffle`/`repeat` (публичные поля, список
  не меняется); новые `mock::Action::ToggleShuffle` и `mock::Action::CycleRepeat`
  (для `bridge.rs` в T07; отключаются флагом `gallery.disabled`, как остальные
  действия очереди).
- Тесты: `models.rs` (JSON команд, разбор ответа без режимов = Off/Off и с режимами),
  `controller/system_media/tests.rs` (цель из назначения, цикл Off→All→One→Off,
  порядок в полосе после Next, без сети/назначения команда не ставится),
  `controller/view_model_tests.rs` (`can_change_modes` по соединению и назначению),
  `mock/queue.rs` (переключение офлайн). В фикстурах `PlaybackAssignment`
  добавлены `shuffle: false, repeat: Off` (4 файла тестов).

Проверки (выполнены):

- `cargo test -p osu-radio-client --lib --locked` — 233 passed, 4 ignored.
- `cargo test -p osu-radio-client --lib --features mock --locked` — 251 passed, 4 ignored.
- `cargo clippy -p osu-radio-client --all-targets --locked -- -D warnings` — чисто,
  также с `--features mock`; `cargo fmt` применён.
- `cargo check -p osu-radio-qt --all-targets --locked` — собирается без правок Qt
  (литералы `PlayerPresentation` там используют `..Default::default()`).

`LIBCLANG_PATH` не понадобился. Не проверено: работа с настоящим сервером
(T10); Qt-свойства и кнопки (T07). Расхождений с планом нет; `QueueState` клиента
поля режимов не получил (карточка требовала только назначение).
