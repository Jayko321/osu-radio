# T11. Ручная приёмка на Linux и Windows

Состояние: приложение собрано, ожидает ручной приёмки; ни один пункт ещё не проверен.
Источники: [спецификация](../../specs/shuffle-repeat.md), R1–R10;
[сквозной сценарий](../shuffle-repeat.md#проверка-результата).
Зависимости: T10 — собранное приложение и список непроверенных критериев.

## Результат

Записано, какие критерии подтверждены на реальном звуке, окне и системных
виджетах, а какие остаются открытыми. Реализация карточкой не меняется.

## Границы и контекст

Собрать приложение по [development](../../agent/development.md); тестовая
библиотека с несколькими треками и плейлистом. Windows-машина нужна для SMTC;
без неё R10 на Windows остаётся неподтверждённым.

## Проверка и приёмка

Linux, реальное приложение:

1. Shuffle при игре: текущий трек не прерывается, порядок после него изменился;
   Next идёт по панели; выключение возвращает исходный порядок.
2. Repeat One: трек доигрывает и начинается заново; дата прослушивания не растёт;
   ручной Next уходит дальше, режим остаётся.
3. Repeat All: с последней записи звучит первая; Previous на первой записи
   перезапускает её, а не переходит к последней.
4. Previous на 0:05 перематывает в начало (пауза сохраняется), на 0:02 — к
   предыдущей записи; то же с медиаклавишей.
5. Иконка и подсказка кнопок для Off/All/One, акцент включённых режимов; галерея
   переключает режимы офлайн.
6. Перезапуск приложения сохраняет режимы; «Очистить всё» не сбрасывает.
7. `playerctl shuffle` и `playerctl loop` читают и меняют режимы, кнопки приложения
   отражают изменение.

Windows: пункты 1–6 и SMTC (запрос shuffle/repeat из системного виджета). Результаты
фиксировать отдельно по каждому пункту: подтверждено, не подтверждено, не проверялось.

## Отчёт о выполнении

**Подготовлено (2026-10-24, агент; реализация не менялась)**

- Окружение сборки: Linux (Arch), fish. В оболочке агента `LIBCLANG_PATH` пуст, и
  `cargo build -p osu-radio-qt -p osu-radio-server --release --locked` прошёл без
  обходов за 1 мин 8 с — с уже собранным кэшем `signalsmith-stretch`. На чистой
  сборке или после смены профиля bindgen может не найти libclang: тогда нужен
  `sudo pacman -S clang` либо
  `LIBCLANG_PATH=/opt/rocm/lib/llvm/lib` и
  `BINDGEN_EXTRA_CLANG_ARGS=-resource-dir=/opt/rocm/lib/llvm/lib/clang/22`
  (пути рабочей станции, в репозиторий не заносятся).
- Бинарники `target/release/osu-radio-qt` и `target/release/osu-radio-server`
  собраны из текущего рабочего дерева со всеми изменениями T01–T10.
  Запуск: `cargo run -p osu-radio-qt --release`.
- `playerctl` на машине не установлен (`sudo pacman -S playerctl`); без него пункт 7
  можно проверить через `busctl --user` по имени `org.mpris.MediaPlayer2.osu_radio.*`.
- Дату прослушивания видно через сортировку «недавно проигранные»
  (`RecentlyPlayed`, [описание](../../agent/frontend.md#track-sorting-and-listening-dates)).
- Использовать копию или отдельную базу: `SQLITE_DATABASE_URL` на одноразовый файл,
  чтобы не менять режимы очереди основной библиотеки.
