# T04. HTTP-контракт режимов очереди

Состояние: выполнено, проверено (SQLite; PostgreSQL — только Clippy).
Источники: [спецификация](../../specs/shuffle-repeat.md), R6;
[решение: HTTP](../shuffle-repeat.md#http-osu-radio-server).
Зависимости: T02 — `PlaybackCommand::SetShuffle/SetRepeat`, поля `shuffle`/`repeat`
в снимке и назначении (поведение Repeat из T03 для контракта не нужно).

## Результат

Клиенты могут менять режимы командами плеера и получают их в ответах команд,
в `QueueResponse` и в каждой строке NDJSON `/api/playback/events`.

## Границы и контекст

- Владение: `apps/osu-radio-server` ([routes/playback.rs](../../../apps/osu-radio-server/src/routes/playback.rs),
  тесты `playback_tests.rs`, `queue_transport_tests.rs`). Новых маршрутов нет:
  команды идут в `POST /api/playback/commands`.
- `CommandRequest`: `set_shuffle { enabled: bool }`, `set_repeat { mode }` с
  `mode` = `off` | `all` | `one` (snake_case), как остальные варианты. Команды
  идут существующей полосой `PendingPlayback` и упорядочены с Next/Previous.
- `PlaybackResponse` (ответы и строки потока) и `QueueResponse` получают
  `shuffle: bool` и `repeat`. Схемы OpenAPI — под фичей `docs`; оба варианта
  роутера (с `docs` и без) остаются согласованы. Существующие поля не менять.
- Сверено с кодом после T02 (2026-10-24): `radio_services::{PlaybackCommand::SetShuffle,
  SetRepeat, RepeatMode}` и поля `shuffle`/`repeat` в `QueueSnapshot` и
  `PlaybackAssignment` уже есть. `RepeatMode` — тип `radio-db` без serde/`ToSchema`,
  поэтому нужен серверный wire-enum `RepeatMode` (`Serialize + Deserialize`,
  `rename_all = "snake_case"`, `cfg_attr(docs, ToSchema)`) с конвертацией в обе
  стороны — по образцу `PlaybackMode` в `playback.rs`. `CommandRequest` имеет
  `deny_unknown_fields`: лишние поля тоже 4xx. Новые поля ответов — обязательные,
  не nullable.
- Опубликовать точный JSON команд и полей для T05, например
  `{"command":"set_shuffle","enabled":true}`, `{"command":"set_repeat","mode":"all"}`;
  ответ/строка потока/очередь содержат `"shuffle":false,"repeat":"off"`.
- OpenAPI-проверку расширять в существующем
  `openapi_queue_contract_matches_required_nullable_fields_and_statuses`
  (`queue_transport_tests.rs`); тесты команд — рядом с существующими в
  `playback_tests.rs`.

## Проверка и приёмка

Тесты маршрутов поверх реального сервиса и временной SQLite:

- каждая команда меняет режим, ответ содержит новое значение; повтор того же —
  без новой revision; недопустимый `mode` и неверный тип `enabled` — 4xx без
  изменения состояния;
- первая строка NDJSON-потока и `GET` очереди содержат режимы; после команды
  поток публикует строку с новым значением; `Clear` режимы сохраняет;
- режимы переживают пересоздание приложения на той же базе.

`cargo test -p osu-radio-server --locked`;
`cargo test -p osu-radio-server --no-default-features --features sqlite --locked`;
Clippy: стандартный, `--no-default-features --features sqlite`, и
`--features postgres,docs` из [матрицы](../../agent/development.md#repository-and-backend-checks).
OpenAPI-документ содержит новые поля и команды (проверка в тестах docs-варианта
или по сгенерированной схеме).

## Отчёт о выполнении

Изменённые файлы (2026-10-24):

- `apps/osu-radio-server/src/routes/playback.rs`: wire-enum `RepeatMode`
  (`off`/`all`/`one`) с конвертацией в обе стороны; `CommandRequest::SetShuffle
  { enabled }` и `SetRepeat { mode }`; обязательные поля `shuffle: bool`,
  `repeat` в `PlaybackResponse` и `QueueResponse`; `allow(struct_excessive_bools)`
  на `PlaybackResponse` (четвёртый bool).
- `apps/osu-radio-server/src/routes/playback_tests.rs`: тест
  `mode_commands_update_every_response_and_reject_invalid_input_without_changes`
  (ответы команд, первая строка и обновления NDJSON, `GET /api/queue`, no-op без
  новой revision, 422 на неверные `mode`/`enabled`/лишнее поле/пропуск поля без
  изменения состояния, `DELETE /api/queue` сохраняет режимы); тест
  `queue_modes_survive_application_restart_on_the_same_database` (файловая SQLite,
  новый `AppState`); в docs-тест добавлены `set_shuffle`/`set_repeat` в
  `CommandRequest` и `RepeatMode.enum == ["off","all","one"]`.
  Существующий `openapi_queue_contract_…` сам сверяет ключи реальных ответов
  `QueueResponse`/`PlaybackResponse` с `required` схемы, поэтому покрывает новые поля.

Контракт для T05:

- команды `POST /api/playback/commands`: `{"command":"set_shuffle","enabled":true}`,
  `{"command":"set_repeat","mode":"off"|"all"|"one"}`;
- `PlaybackResponse` (ответы, строки NDJSON) и `QueueResponse`: `"shuffle": bool`,
  `"repeat": "off"|"all"|"one"`, всегда присутствуют; ошибка ввода — 422.

Проверки (фактически выполнены):

- `cargo test -p osu-radio-server --locked` — 79 passed, 2 ignored; startup 6 passed.
- `cargo test -p osu-radio-server --no-default-features --features sqlite --locked` —
  71 passed, 2 ignored; startup 6 passed.
- Clippy `-D warnings`: стандартный, `--no-default-features --features sqlite`,
  `--features postgres,docs` (`--all-targets`) — без замечаний. `cargo fmt --check` — ок.

Не проверено: тесты сервера на PostgreSQL не запускались (в матрице для сервера
на PostgreSQL только Clippy); внешним клиентом и реальным процессом сервера
контракт не проверялся — это T10. Расхождений с планом нет.
