# T10. Сквозная проверка с настоящим сервером и руководства

Состояние: выполнено, проверено; ручная приёмка — T11.
Источники: [спецификация](../../specs/shuffle-repeat.md), R1–R10;
[план: проверка результата](../shuffle-repeat.md#проверка-результата).
Зависимости: T01–T09.

## Результат

Режимы проверены от HTTP до клиента на настоящем встроенном сервере с
подменённым движком; общий набор проверок проходит; руководства описывают
реализованное поведение и границы проверок.

## Границы и контекст

- Расширить существующие opt-in пробы
  (`real_server_queue_and_fake_engine_preserve_launches_across_edits_and_reimport`
  в клиенте и `real_backend_queue_survives_restart_and_preserves_exact_entry_actions`
  в Qt, см. [матрицу](../../agent/development.md#verification-matrix)) вместо новой
  инфраструктуры. Если сценарий в них не укладывается, зафиксировать в отчёте.
- Руководства: `docs/agent/database.md` (v16, `shuffle_order`, `repeat_launch`,
  downgrade), `backend.md` (команды и поля), `frontend.md` (режимы, правило
  Previous, медиаконтролы, галерея), `development.md` (строка матрицы и пробы).
  Опираться на отчёты T01–T09; ссылки, символы и команды сверить с кодом,
  выполненное отделить от предлагаемого. Если план `docs/impl` или спецификация
  потребуют правки статусов, обновить таблицу карточек.

## Проверка и приёмка

Проба на настоящем сервере и реальном клиенте с fake engine: включение shuffle
в игре → порядок меняется только после текущей, Next идёт по новому порядку,
выключение возвращает исходный; Repeat One: Finished перезапускает ту же запись,
дата прослушивания не меняется; Repeat All: с последней на первую; перезапуск
сервера и клиента сохраняет режимы, `Clear` их не сбрасывает; Previous на 5 с
— без серверной команды, на 2 с — серверный переход.

Затем scoped-проверки матрицы без `--all-features`: `cargo fmt --check`;
radio-db/radio-services на SQLite и PostgreSQL; server с `docs` и без; client
с `mock` и без; media-controls; Qt offscreen и QML lint; Clippy. Прежние
известные падения (artwork-проба Qt, metadata suite) указать как прежние.
Непроверенные критерии (физический звук, нативные виджеты, Windows) явно
перечислить — они передаются в T11.

**Сквозная проба (выполнена, Linux, настоящий SQLite-сервер, fake engine)**

`cargo test -p osu-radio-client --lib --locked real_server_modes -- --ignored` — успешно.
Шесть записей `A B C A B C`: shuffle при игре — текущая, token и история прежние,
хвост — то же множество; Next идёт по новому порядку; выключение возвращает исходный
порядок оставшихся; Repeat One — Finished даёт ту же запись с новым token, `history_len`
прежний, дата прослушивания после `Started` повтора прежняя; Repeat All — с последней
на первую и по Finished, и по Next, порядок не меняется; после перезапуска сервера
и свежего движка режимы на месте, `Clear` их сохраняет.
Чувствительность: временная замена `!state.repeat_launch` на `true` в
`radio-services/src/queue.rs` роняет пробу на сравнении даты; код восстановлен.
Qt: `real_backend_queue_survives_restart_and_preserves_exact_entry_actions` — успешно;
подмена ожидаемого `repeat` в `verify` на `one` роняет пробу (режимы читаются у нового
сервера). Существующая клиентская проба очереди — успешно.
