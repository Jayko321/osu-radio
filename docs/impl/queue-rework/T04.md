# T04. Очередь переживает удаление и повторный импорт источников

Состояние: реализовано; автоматические проверки SQLite/PostgreSQL выполнены. Пользовательская приёмка отдельно.
Источники: [спецификация](../../specs/queue-rework.md), R8, R10;
[план](../queue-rework.md#34-фоновая-проверка-доступности), §3.2–3.4, §5.
Зависимости: T03 — зафиксированы полные снимки и ключи плейлистовых записей;
T02 через неё — guarded-результаты проверок и полная проекция.

## Результат

Изменение библиотеки атомарно обновляет разрешённые ссылки и доступность очереди.
Удалённые источники оставляют видимые записи; повторный импорт разрешает ключи
и ставит новую проверку, сохраняя ID, порядок и подписи без исходного плейлиста.

## Границы и контекст

Дополнение согласованного плана: `QueueState.launch_source` хранит audio-ID,
точный `SourceType` и поколение назначенного запуска. Миграция 14 добавляет четыре
nullable-поля singleton без FK; миграции 1–13 сохранены. Перенос выводит привязку из
полной текущей записи активного запуска без ожидания; downgrade запрещает потерю
привязки. Новый token очищает её, проверенное назначение/успех ожидания фиксируют,
recovery назначает по актуальной записи без автозапуска. Согласование очереди
сохраняет прежние источник/token назначенного запуска. Started, дата и громкость
assignment относятся к этому источнику, даже удалённому. Failed меняет доступность
только при совпадении привязки и поколения запуска с текущей записью.

При согласовании источника различать `waiting_for_check` и availability: текущий уже назначенный запуск можно перевести в checking без ожидания, сохранив token. Для ожидания при утрате источника применить переход с сохранением намерения; новое поколение и точный ключ должны инвалидировать старый `QueueCheck`.

- Начать с `delete`, `replace_snapshot`, `replace_imported_snapshot` и общего
  внутреннего workflow в [OsuInstallationService](../../../crates/radio-services/src/osu_installation.rs),
  вызывающих [folder_selection.rs](../../../crates/radio-services/src/folder_selection.rs),
  [AudioSourceRepository](../../../crates/radio-db/src/repositories/audio_source.rs),
  репозиториев очереди и плейлистов. Сверить итоги T01–T03 перед изменением.
- Встроиться в существующие singleton writer lock и outer-only commit импорта/
  удаления, включая cleanup shared rows. Все запросы — transaction-bound;
  scanner по-прежнему только читает источник и возвращает snapshot.
- Отвязать исчезнувшие ссылки, сохранить ключ и подпись, обновить поколение проверки,
  чтобы результат старой привязки не воскресил источник. Повторно разрешать
  библиотечные `(kind, location)` и плейлистовые ключи с hash kind из самой записи;
  не зависеть от наличия исходного playlist item. Учитывать shared audio, разные
  installation kind, пустой snapshot и новые числовые ID после reimport.
- Восстановленный источник получает `checking`, а не `available`. Записи
  проверенных неизменившихся источников не отправлять на массовую перепроверку.
  Обновление доступности не прерывает локально звучащее аудио; новый запуск
  руководствуется актуальными состояниями и намерением из T02.
- Зафиксированные изменения очереди имеют revision для будущей публикации T05/T06;
  до commit никаких уведомлений. Отсутствие Play, в том числе после полностью
  недоступного плейлиста, остаётся отсутствием намерения запускать музыку.
- Обновить [database guide](../../agent/database.md). Аудиофайлы не копируются
  и не удаляются; даты, настройки громкости и исходные пользовательские плейлисты
  сохраняют существующий контракт.

## Проверка и приёмка

Дополнить [сервисные тесты](../../../crates/radio-services/src/tests.rs), прежде всего
[queue](../../../crates/radio-services/src/tests/queue.rs),
[playlists](../../../crates/radio-services/src/tests/playlists.rs) и
[collections](../../../crates/radio-services/src/tests/collections.rs).
Удалить установку с повторяющимися аудио и двумя сложностями: все записи остаются
со своими ID/подписями, ссылки/доступность меняются атомарно. Удалить исходный
плейлист, затем импортировать источник: записи разрешаются независимо от него
и требуют новой проверки. Проверить библиотечную запись без playlist-item-ID,
shared source другой установки и отсутствие смешения hash kind.

Искусственная ошибка позднего шага импорта/cleanup должна откатить библиотеку,
очередь, поколения, коллекции и timestamp вместе. Из независимого подключения
невозможно прочитать промежуточное сочетание. Старый результат проверки после
удаления/reimport/смены привязки ничего не меняет; источник без Play не запускается.

`cargo test -p radio-db -p radio-services --locked`, `cargo test -p osu-radio-cli --locked`;
сервисные контракты на отдельной временной PostgreSQL-БД по
[матрице](../../agent/development.md#repository-and-backend-checks).
Использовать синтетические snapshots и явные временные корни; реальные установки
не сканировать. Файловые проверки и серверные уведомления принимаются в T05/T06.

## Отчёт о выполнении

Реализовано 2026-10-16 поверх существующих незакоммиченных T01–T03; коммит не создавался.

- [QueueService](../../../crates/radio-services/src/queue.rs): `reconcile_sources_in`
  использует только переданную транзакцию; [installation workflow](../../../crates/radio-services/src/osu_installation.rs)
  вызывает его после shared cleanup при delete и общем replace, до timestamp/commit.
  Оба replace API, регистрация с импортом и reimport идут через этот workflow.
- [PlaylistRepository](../../../crates/radio-db/src/repositories/playlist.rs): общий
  пакетный `resolve_sources` для сохранённых ключей, без playlist-item-ID; выбор
  минимального beatmap-ID с Local/Copied и разделение installation/native/MD5 сохранены.
  Библиотечная запись разрешается по точному `(kind, location)`; numeric evidence
  не восстанавливает утраченный ключ. Исчезнувшие audio/map/set/cover-ссылки очищаются,
  ID/порядок/item-ID/подписи/ключи сохраняются. Поколение меняется при смене/утрате
  привязки; восстановленный источник checking. Неизменный источник сохраняет
  availability/generation при обновлении map/cover. Изменение даёт один revision,
  no-op не вызывает save (проверено запрещающим запись trigger).
- [Модель](../../../crates/radio-db/src/model/queue.rs),
  [entity](../../../crates/radio-db/src/entities/queue.rs),
  [repository](../../../crates/radio-db/src/repositories/queue.rs),
  [миграция 14](../../../crates/radio-db/src/migrations/m20261016_000014_queue_launch_source.rs)
  и экспорты сохраняют launch-source независимо от библиотеки. Assignment читает
  прежние audio-ID/дату/громкость; callbacks защищают восстановленную привязку.
- [Контракты T04](../../../crates/radio-services/src/tests/queue_t04.rs) проверяют
  повторы, две сложности, удалённый плейлист, библиотечную запись, новые числовые ID,
  shared audio, installation/hash/audio kind, пустой snapshot, поздние checks и callbacks,
  recovery, playing/paused-ожидание и восстановление без Play. Ошибки queue save,
  timestamp, cleanup, revision/generation overflow, удаления и регистрации откатывают
  связанные данные. Барьер общего workflow до commit и независимое подключение
  подтверждают старый snapshot; после commit виден новый. Отмена после всех записей
  откатывает очередь/библиотеку/коллекции/timestamp.
- [Migration fixtures](../../../crates/radio-db/src/tests/queue.rs) покрывают
  v13→v14 для playing/paused/waiting/stopped/неполного ключа, reopen/reset,
  ограничения SQL и guarded downgrade. Обновлены исторические version/count fixtures
  в repository lifecycle/playlists/tests и ожидания T02/T03/listening-history.
- Обновлены [database](../../agent/database.md), [backend](../../agent/backend.md),
  [coverage inventory](../../agent/test-coverage.md), общий план и T05–T07/T10.
  T05 подбирает проверки из актуальных queue entries, не из launch-source;
  T06/T07 должны сохранять различие assignment и актуальной записи очереди.

### Непроверенное и границы

Файловый worker, post-commit уведомления о библиотечных изменениях и клиентская
интеграция остаются T05–T07. Qt, Windows, реальные osu! источники/Realm, физический
звук и пользовательская приёмка не проверялись. Исходные аудиофайлы не копировались
и не удалялись. Общая спецификация ещё не завершена.
