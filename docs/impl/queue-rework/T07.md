# T07. Полная Queue VM и безопасное клиентское проигрывание

Состояние: реализовано; клиентская и Qt offscreen матрица проверена. Пользовательская приёмка отдельно.
Источники: [спецификация](../../specs/queue-rework.md), R1–R11 на клиенте;
[план](../queue-rework.md#36-общий-клиент-qt-и-моки), §3.3–3.6, §5.
Зависимости: T06 — согласованные wire DTO/ApiClient, entry-ID/доступность
в assignment, полный GET и все операции.

## Результат

QueueViewModel владеет полной проекцией, статусами и ошибками операций.
Действия очереди идут через существующую последовательную полосу команд.
PlayerViewModel различает записи по ID/token, ждёт проверку и сохраняет
работающий движок при редактировании списка. Моки воспроизводят новые действия офлайн.

## Границы и контекст

Контракт T04: старый назначенный audio-ID/source/token сохраняются при reimport,
а запись очереди получает новую привязку и поколение checking. При прежнем token и
снятом waiting сохранять движок/позицию даже если queue-entry audio-ID уже другой.
Загрузка нового источника относится к новому назначению; восстановление без Play не
выбирает запись и не запускает звук. Повторить stale download/Started/Failed, дату и
громкость старого запуска после удаления/возврата библиотеки и recovery в paused.

Загрузку и новый запуск удерживает `waiting_for_check` из assignment. Не прерывать уже назначенное аудио только из-за availability=checking/unavailable при прежнем entry-ID/token и снятом ожидании.

## Отчёт о выполнении

Окончательные контракты, результаты проверок и ограничения приведены ниже.

### Реализация и контракт для T08/T09 (2026-10-16)

- `QueueView.entries: Vec<QueueRow>` — весь серверный порядок, включая историю,
  повторы и строки без audio-ID. Строка содержит `id: QueueEntryId`, `position`,
  nullable `audio_source_id`/`playlist_item_id`, `availability` и `track: Track`.
  Track сохраняет ordinary/Unicode подписи, difficulty suffix, cover/date/volume
  и известную длительность. Отсутствующий источник обозначен nullable ID строки;
  внутренний display Track использует существующий unavailable sentinel `-1`.
- View передаёт `current_entry_id`, `history_len`, `mode`, `waiting_for_check`,
  `revision`, `playback_token`; `loading` относится к GET, `busy` к операциям,
  `message` к ошибке загрузки, `operation_error` к ошибке операции. Ошибка не
  очищает подтверждённые строки. Нового владельца состояния или полосы нет.
- `AppCommand::Queue(QueueAction)` принимает Refresh, Play/Remove(entry-ID),
  Move `{ id, before_entry_id: Option<_> }`, ClearUpcoming, ClearAll и
  Insert `{ items: Vec<QueueItemRef>, placement: QueuePlacement }`.
  Nullable anchor означает конец. Все mutations добавляются в `PendingPlayback`,
  рядом с transport/playlist/token-bound callbacks. Только прежние callbacks
  повторяются автоматически; вставки не повторяются. Whole-playlist append
  вызывает `append_playlist_to_queue` без GET и клиентской фильтрации.
- Success обновляет assignment и перечитывает открытую панель, в том числе
  successful no-op. Закрытая панель GET не делает; close отменяет запрос и
  увеличивает epoch. Stale GET/revision/assignment не заменяют актуальное состояние.
- `Playback`, Player presentation и worker Assign передают current entry-ID и
  waiting. Новый entry/token отменяет старую загрузку и начинает новый запуск;
  прежний entry/token со снятым waiting сохраняет движок, позицию и seek.
  Источник берётся из assignment, поэтому новая audio-привязка queue row после
  reimport не подменяет старый запуск, его дату или громкость.
- Waiting не скачивает аудио, не создаёт engine, не отправляет Started/Failed
  и не допускает seek. Снятие waiting разрешает запуск только в Playing.
  Paused ждёт явного Play. Первый восстановленный Paused assignment не меняет
  выбор библиотеки или пункта плейлиста; это уточнение синхронизировано со
  спецификацией и общим планом. Старые token-bound retries/device pause сохранены.
- `SetVisibleQueueMedia(Vec<(QueueEntryId, bool)>)` заменяет снимок спроса;
  bool означает отсутствие обложки. IDs разрешаются по актуальной Queue VM;
  дубли объединяются по audio-ID вместе с библиотекой/selection. Планировщик
  сохраняет четыре слота, cancellation/ACK и общий кэш. Закрытие снимает спрос;
  само чтение полной истории медиазапросов не создаёт.
- До T08 `QueueView::upcoming()` отсекает историю и текущую для старого Repeater.
  Qt сохраняет полный view, удерживает artwork строки по entry-ID, передаёт ID строкой и сообщает спрос своих
  отрисованных будущих строк. Новая панель/виртуализация остаётся T08, меню — T09.
- `MockQueue` работает только в памяти: история, независимые IDs, повторы,
  checking/unavailable, все QueueAction, append плейлиста, пауза и результат
  проверки. Ошибка сохраняет состояние/счётчик IDs; добавления не запускают
  музыку. MockBridge проецирует queue snapshot; Session/БД/I/O/engine отсутствуют.

  смешанные операции, оба item/placement, whole-playlist без GET, ошибка без

  reimport assignment source/date/volume, waiting Play/Pause без локального source.
- Три новых worker-теста и прежние callback/download/seek/shutdown/device retry:
  при шести обновлениях неизменного назначения `load/play/seek = 1/1/1`,
  позиция остаётся 17 с. Другой entry того же аудио создаёт новый engine:
  его счётчики `1/1/0`, позиция 0. Старые seek/download/assignment не принимаются.
  Waiting даёт ноль downloads/engine/Started/Failed; Playing release запускает
  один load/play, Paused release — ноль до явного Play.
- 5000 прошлых и семь видимых строк с одним повтором: GET создаёт ноль jobs;
  шесть уникальных аудио дают 12 HTTP requests — cover/duration по одному на audio.
  Первая волна — 4 pipeline/8 requests, вторая — 2/4. Ни одного запроса из истории.
  Снимок с двумя видимыми дублями использует общую загрузку; замена/close снимает
  прошлый спрос. Лимит и decoder ACK не расширялись.
- Три memory-only mock-теста проверяют порядок, идентичность, обе вставки,

  Qt проверяет прежнюю будущую панель, paused recovery, галерею и artwork cache.

  без audio-ID после eviction; отдельный повтор четырёх Qt library tests прошёл.

### Границы и открытое

T07 реализован и проверен автоматически в указанном объёме. Пользовательская
приёмка не отмечена. Нативный Linux desktop/GPU/input, Windows, физический звук,
живой Discord и реальная osu!/Realm library не проверялись. Серверная матрица,
PostgreSQL runtime и два opt-in Qt real-backend probes в T07 не повторялись.
Новая панель/ListView, её виртуализация/drag-and-drop и меню вставки остаются
T08/T09; интегральная ручная приёмка — T10. Проекция будущих строк старого
Repeater не подтверждает UI R1 и не ограничивает число его будущих делегатов.
