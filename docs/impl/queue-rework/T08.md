# T08. Управляемая Qt-панель с виртуализацией истории

Состояние: реализовано; Linux automated/Qt offscreen матрица проверена. Пользовательская приёмка отдельно.
Источники: [спецификация](../../specs/queue-rework.md), R1, R2, R4–R6, R8, R10, R11;
[план](../queue-rework.md#36-общий-клиент-qt-и-моки), §3.2, §3.6, §5.
Зависимости: T07 — полная QueueView, команды по ID, visible media demand,
ожидание проверки, сериализация и офлайн-моки.

## Результат

Панель показывает прошлые, текущую и следующие записи, позволяет Play, удаление,
перетаскивание и две очистки. ListView создаёт ограниченное число карточек;
видимые строки сохраняют обложки/прокрутку при обновлениях, ID не теряют точность.

## Границы и контекст

- Изменять [QueuePanel.qml](../../../apps/osu-radio-qt/qml/components/QueuePanel.qml),
  привязки [PlayerPanel.qml](../../../apps/osu-radio-qt/qml/PlayerPanel.qml),
  `QueueViewModelRust`, `TrackListModelRust`, `Row` и `ROLES` в
  [qt_view_models.rs](../../../apps/osu-radio-qt/src/qt_view_models.rs),
  доставку/кэш [app_bridge.rs](../../../apps/osu-radio-qt/src/app_bridge.rs),
  [runtime](../../../apps/osu-radio-qt/src/runtime.rs) и
  [view_models.h](../../../apps/osu-radio-qt/src/view_models.h) при необходимости.
  Использовать отдельный экземпляр существующего TrackListModel с queue-ролями,
  а не новый класс модели. AppBridge сохраняет QObject ownership и delivery.
- На старте T08 очередь — QVariantList/Repeater, а ключи существующей модели используют
  audio-ID и playlist-item-ID. Для очереди ключ — только entry-ID, включая повторы
  одинаковых пар audio/item. Расширить роли текущей/прошлой позиции и доступности;
  библиотечные и плейлистовые экземпляры модели должны сохранить поведение.
  Entry-ID передавать без JS Number округления и без сужения до i32.
- Сохранить стиль карточек. Показать `checking`/`unavailable` и снимки при null
  источнике. Play checking ждёт сервер; unavailable остаётся видимой и удаляемой.
  Drag past/current/future отправляет before-entry-ID, null для конца, а не индекс;
  обновлённый сервером список остаётся источником истины при отказе операции.
- При открытии позиционировать на текущей записи без selection/Play. Обновление
  доступности/длительности/обложек не сбрасывает прокрутку и видимые изображения.
  Следить за in-place обновлением ролей и кэшем при дубликатах; существующее
  `audio_rows: HashMap<i32, usize>` не является уникальным ключом очереди.
- Передавать медиаспрос лишь видимых делегатов в существующий ограниченный
  планировщик T07, сохранив shared cache/повторное использование одного аудио.
  Снятие делегата/закрытие панели снимает спрос; история не запускает запросы
  длительности/обложек для всех 5000 строк.
- Сохранить Escape/backdrop, клавиатурное управление, доступные имена, порядок
  фокуса и возврат фокуса после закрытия. Действия/drag не должны случайно запускать
  Play из-за bubbling. Новые компоненты регистрировать в ресурсах при их появлении.
- Обновить галерею: [Store.qml](../../../apps/osu-radio-qt/qml/Store.qml),
  [Gallery.qml](../../../apps/osu-radio-qt/qml/Gallery.qml),
  [bridge.rs](../../../apps/osu-radio-qt/src/bridge.rs) и mock-привязки;
  она остаётся офлайн без звука/БД. Обновить [frontend guide](../../agent/frontend.md).
  Для Qt API следовать [Context7 procedure](../../agent/development.md#context7-and-source-evidence),
  опорные официальные материалы уже указаны в §3.6 плана.

## Проверка и приёмка

Расширить Qt model/adapter unit checks, [AdapterProbe](../../../apps/osu-radio-qt/tests/AdapterProbe.qml),
[launch_smoke](../../../apps/osu-radio-qt/tests/launch_smoke.rs) и соответствующие
[HTTP-фикстуры](../../../apps/osu-radio-qt/tests/fixtures/server.py).
Проверить текущую отметку и открытие на ней без команды Play, запуск прошлого
без копии, remove/move двух одинаковых audio/item по разным ID, обе очистки,
ошибку операции, checking/unavailable, клавиатуру/Escape/backdrop/focus restoration.
Прогнать ID выше 2^53 через модель → QML → действие → HTTP и сравнить точное значение.

На 5000 прошлых плюс текущая/следующие измерить число созданных/живых делегатов
и HTTP медиазапросов: они зависят от viewport/ограниченного кэша, а не длины списка.
После прокрутки availability/media update сохраняет положение и готовые обложки,
дубликаты делят загрузку медиа, закрытие очищает спрос. Отдельно сохранить
регрессии library/playlist TrackListModel, Unicode и существующего artwork eviction.

`cargo test -p osu-radio-qt --locked -- --test-threads=1`;
`cargo build -p osu-radio-qt --locked`;
`apps/osu-radio-qt/scripts/lint-qml.sh` после сборки;
`cargo test -p osu-radio-client --features mock --lib --locked`.
Offscreen/input-пробы не подтверждают нативные drag/hit testing и физический звук;
проверку Linux/Windows оставить явными пунктами итоговой приёмки T10.

## Отчёт о выполнении

### Реализация и передача T09 (2026-10-16)

- [Qt VM/model](../../../apps/osu-radio-qt/src/qt_view_models.rs): отдельный
  `TrackListModel` очереди вместо `queueTracks: QVariantList`. Идентичность —
  `QueueEntryId`; сохранённые artwork URL принадлежат строке и cover source.
  Изменение данных идёт через `dataChanged`, структуры — begin/end insert,
  remove и move без reset модели. Artwork delivery использует существующий
  cover-index модели, сброс эпохи уведомляет QML об очищении URL.
- Роли 256–263 библиотеки/плейлистов сохранены. Дополнительные: 264 `entryId`
  (QString), 265 `isCurrent` (bool), 266 `isPast` (bool), 267 `availability`
  (`checking|available|unavailable`). `entryIdAt(index)` возвращает строковый ID.
- Queue Qt API: `tracks`, `startIndex`, `queueLoading`, `queueMessage`,
  `setQueueVisible(bool)`, `playEntry(id)`, `removeEntry(id)`,
  `moveEntry(id, beforeEntryId)`, `clearUpcoming()`, `clearAll()`,
  `setVisibleQueueMedia(ids)`. Все ID/anchor — десятичные строки; null означает
  конец. Rust проверяет положительный i64 и тип anchor до QueueAction.
  Проверяются `9007199254740993` и `9223372036854775807` без округления.
- [QueuePanel](../../../apps/osu-radio-qt/qml/components/QueuePanel.qml) и
  [PlayerPanel](../../../apps/osu-radio-qt/qml/PlayerPanel.qml): полный ListView,
  82px/14px, cacheBuffer=96px, reuseItems=false; текущая/история/следующие,
  сохранённые подписи и доступность, отдельные Play/remove/drag и обе очистки.
  После загрузки каждое открытие позиционирует один раз; навигация не меняет
  selection/Play, дальнейшие role updates сохраняют прокрутку и изображения.
- Медиаспрос до начального позиционирования не отправляется. Далее viewport,
  структурные/role updates и lifecycle делегатов заменяют снимок entry-ID;
  закрытие отправляет пустой. Дубли разделяют существующий клиентский кэш.
- Drop отправляет одну команду, локального изменения порядка нет. Проверены
  отказ и no-op, отмена Escape, индикатор вставки и прокрутка у края; исходный
  делегат удерживается через currentIndex. Tab/Shift+Tab, стрелки,
  Ctrl+Up/Down, Enter/Space, Delete, Escape/backdrop и возврат фокуса сохранены.
  Фокус на дочернем действии прокручивает его в видимую область без Play.
- [MockBridge](../../../apps/osu-radio-qt/src/bridge.rs),
  [Store](../../../apps/osu-radio-qt/qml/Store.qml) и
  [Gallery](../../../apps/osu-radio-qt/qml/Gallery.qml) используют ту же модель и

### Измерения

Один viewport 768px, маршрут: открытие у текущей → начало истории → возврат к
текущей. Финальный прогон дал одинаковые счётчики делегатов:

| Прошлых строк | Создано при открытии | Всего создано на маршруте | Живых в checkpoint | Entry-ID viewport demand | HTTP cover/duration за сценарий |
| --- | --- | --- | --- | --- | --- |
| 20 | 21 | 39 | 9 | 8 | 36 |
| 5000 | 21 | 39 | 9 | 8 | 33 |

Число созданных включает кратковременные делегаты при polish/прыжке и кэш;
это не число одновременно живых карточек. Проба ограничивает создание/живые
делегаты и HTTP, допускает один дополнительный viewport при polish.
Для дублированного audio=42 — ровно один HTTP duration и один cover за сценарий.
Закрытие даёт пустой спрос; reset модели — ноль. HTTP не обходит всю историю.
Счётчики печатает `managed_queue_virtualizes_history_and_preserves_exact_entry_commands`
с `--nocapture`. Отдельный серверный availability update после прокрутки
сохранил contentY, тот же делегат и artwork URL. Проверка выполняется при
постоянном viewport: показ/скрытие блока ошибки закономерно меняет его высоту
и проверяется отдельно от role updates.
