# T10. Сквозная проверка очереди и фиксация фактического результата

Состояние: автоматическая часть реализована и проверена на Linux/SQLite/PostgreSQL.
Нативная Linux/Windows и пользовательская приёмка не выполнены.
Источники: [спецификация](../../specs/queue-rework.md), R1–R11 и «Приёмка»;
[план](../queue-rework.md#5-проверка-результата), §5 и таблица покрытия §7.
Зависимости: T01–T09 — реализованные части и отчёты с фактическими проверками,
включая новую миграцию, обработчик, API, клиент, панель и все действия добавления.

## Результат

Взаимодействие частей проверено общим пользовательским сценарием на настоящем
сервере с одноразовой БД. Для каждого R1–R11 зафиксированы реализация, выполненные
проверки и оставшиеся ограничения. Автотесты, реальные взаимодействия и
пользовательская приёмка отмечаются раздельно.

## Проверка и приёмка

1. Запустить плейлист, дождаться доступности/подтверждённого запуска; открыть
   очередь. Видны прошлые, текущая и следующие, открытие не меняет selection/звук.
   Вернуться к прошлой записи без копии, Next/Previous следуют тому же списку.
2. Найти трек и добавить следующим; переставить текущую, затем удалить её на паузе.
   Проверить точные ID, порядок, token, сохранение позиции при move и паузы при
   удалении; checking следующий ждёт результата, unavailable пропускается.
3. Запустить другой плейлист: прошлое сохранено, будущее заменено, все unavailable
   пункты видимы. Проверить отдельно Play из поиска и append целого плейлиста.
   Дубли одного audio/item запускаются/перемещаются/удаляются независимо.
4. Удалить источник, удалить исходный плейлист и вернуть источник импортом:
   queue-ID/подпись/порядок сохранены, разрешение и проверка восстановлены.
   Запоздалые результаты после удаления/очистки не воскрешают записи.
5. Перезапустить сервер/клиент: список, граница и текущая сохраняются, автозапуска
   нет. Возобновить вручную. После конца добавить C → D и запустить C вручную.
   Полностью недоступный плейлист после возврата файлов сам не запускается.
6. Проверить обе очистки при playing/paused и сохранность библиотеки, исходных
   плейлистов, дат и громкости. Обновление дат — только от принятого Started.
7. На истории 4999/5000/5001 проверить обрезку только начала прошлой части;
   текущая/следующие не теряются. С 5000 прошлыми измерить делегаты/медиазапросы
   и сохранение прокрутки/обложек. Проверить ID выше 2^53 до серверной операции.

Сверить отдельные доказательства populated versioned migration без reset,
rollback/downgrade guards, независимых подключений/конкурентных изменений,
переполнений, потери уведомления/restart работника, stale download/seek/callback
и отсутствия ложного Started. Недостающие проверки выполнить, а не заменить сборкой.

Если новая сквозная проба имеет отдельное имя, записать точную команду в отчёт
и выполнить её явно. PostgreSQL repository/service contracts — отдельно на двух
свежих `radio_db_test_*` БД через `RADIO_DB_TEST_POSTGRES_URL` по
[процедуре](../../agent/development.md#repository-and-backend-checks).

Реальный звук, нативные drag/фокус/hit testing Linux и Windows требуют отдельной
пользовательской проверки приложения. Передать точные шаги из сценария, отметить
каждую платформу и фактический результат; недоступное оставить непроверенным.
Offscreen, mocked engine и успешная миграция не заменяют эти критерии.
Если ручная приёмка ещё не состоялась, не объявлять её завершённой и не удалять
временные документы, даже при зелёных автоматических проверках.

### Исправления проверок и границы свидетельств

Первый sandbox запуск клиентской пробы не смог открыть listener; вне sandbox
проверка прошла. В новой Qt-пробе исправлены тестовые предположения:
`currentAudioId` — назначение, даже без engine; отсутствие source проверяется
canSeek/position и финальными датами, напрямую engine — в fake-core probe.
После move проверка ждёт завершения layout и точного entryId делегата.
Эталон плейлиста теперь читается после установки override 29, чтобы сравнивать
одинаковые значения. Две лишние usize-конверсии из новой пробы убраны по Clippy.
Эти исправления не меняют поведение приложения.

Отдельный прежний managed probe получил 41/33 media requests на полном сценарии
при 20/5000 past и упал на разнице >6, хотя абсолютный лимит/дедупликация прошли.
Причина несопоставимости измерения: счётчик включал последующую автопрокрутку
у края, длина которой зависит от времени layout/HTTP. Теперь сравнительный
checkpoint находится до этого drag; общий лимит <60 остаётся на всём сценарии.
Это исправление измерения теста, не оптимизация production scheduler.
Известная граница T09 про возможную повторную cold-start cover delivery остаётся;
проба по-прежнему начинает очередь после начальной доставки library artwork.

Новая engine-probe управляет Core напрямую, не заменяет весь AppController fake
engine через публичный API. Qt real проверяет восстановленную паузу; Playing с
реальным устройством в ней не запускается. Промежуточное checking после reimport
может завершиться до следующего HTTP GET: оно детерминированно наблюдается в
существующих controlled worker/T06 NDJSON tests. Их playing/paused/stale guards,
потерянный wakeup/restart и запрет ложного Started повторно выполнены в обоих
серверных наборах. Реальный Realm producer, пользовательские данные и физический
звук остаются вне этих автоматических свидетельств.

Для каждой целевой платформы на отдельном тестовом профиле/БД:

1. Подготовить разные доступные A/B/C/D, две сложности A с общим audio и missing
   Ghost; плейлист A/Easy → A/Hard → B → Ghost и второй C → D.
   Запустить первый, дождаться реального звука/Started, открыть Queue.
   Проверить past/current/future, независимый selection и непрерывный звук;
   Play прошлой записи и Next/Previous не создают копии.
2. Во время звука найти C, добавить следующим; передвинуть звучащую запись
   через прошлое/будущее за drag handle. Звук/позиция не сбрасываются.
   Повторить клавиатурой Ctrl+Up/Down; Enter/Space, Delete, Escape, Tab/Shift+Tab,
