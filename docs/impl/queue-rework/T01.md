# T01. Записи очереди в таблице и перенос существующей БД

Состояние: выполнено; автоматические проверки SQLite/PostgreSQL пройдены.
Источники: [спецификация](../../specs/queue-rework.md), R8, R10, R11;
[план](../queue-rework.md#32-данные-и-миграция), §3.1–3.2, §5.
Зависимости: нет.

## Результат

Очередь хранит отдельные записи с постоянными ID, порядком, ключами источника,
nullable-ссылками, снимками подписей, доступностью и поколением проверки.
Существующая versioned-БД переносится без reset и потери позиций/повторов.
Singleton хранит текущий ID, границу прошлого, режим и checked-счётчики.

## Границы и контекст

- Начать с [модели](../../../crates/radio-db/src/model/queue.rs),
  [entity](../../../crates/radio-db/src/entities/queue.rs),
  [репозитория](../../../crates/radio-db/src/repositories/queue.rs) и
  [реестра миграций](../../../crates/radio-db/src/migrations/mod.rs).
  Сейчас сохранены параллельные JSON-массивы и индекс; последняя миграция — 11.
  Добавить новую версионную миграцию, регистрацию моделей/entities/репозиториев
  и новую таблицу в явный reset в порядке зависимостей.
- Следовать [database guide](../../agent/database.md): SQL принадлежит репозиториям,
  transaction-bound доступ и singleton writer lock сохраняются. Старые миграции
  не переписывать. Идентичность пути и `(kind, location)` не нормализовать заново;
  для плейлистов сохранять installation kind, hash kind и beatmap hash.
- Каждая старая позиция, включая повтор и утраченный источник, становится отдельной
  записью. Сохранить порядок, текущую позицию, режим, revision/token; отсутствующие
  подписи заменить явной заглушкой. Разрешённые источники получают `checking`,
  неразрешённые — `unavailable`. FK не должны каскадно удалять очередь при удалении
  плейлиста/библиотеки. ID после удаления не переиспользуется.
- Определить проверяемые инварианты границы без текущей записи и переполнения ID,
  revision, token, поколения и позиции. Чтение списка и метаданных должно быть
  возможно в одном read snapshot. Тип ID должен позволять точную передачу в Qt.
- Вместе с изменением модели адаптировать обязательные обращения в
  [QueueService](../../../crates/radio-services/src/queue.rs),
  [PlaylistService](../../../crates/radio-services/src/playlist.rs), серверных
  проекциях и тестовых конструкторах до собираемого состояния. Новая семантика
  операций относится к T02/T03; не вводить второе постоянное хранилище JSON
  или слой совместимости старых версий ради промежуточного этапа.
- Обновить [database guide](../../agent/database.md), сохраняя различие миграции
  versioned-БД и существующего отказа для legacy/unversioned-БД.

## Проверка и приёмка

Расширить [queue contracts](../../../crates/radio-db/src/tests/queue.rs) и
[migration lifecycle](../../../crates/radio-db/src/tests/migration_lifecycle.rs).
На временной populated-БД версии 11 проверить повторы audio-ID/playlist-item-ID,
пустую, paused/playing и exhausted очередь, отсутствующий источник/плейлист,
Unicode-подпись и переоткрытие. Сравнить все перенесённые позиции и сохранность
библиотеки, плейлистов, дат и громкости. Проверить rollback ошибочной миграции,
конкурентный startup независимых подключений, reset только таблиц приложения,
отсутствие повторного ID и отказ checked-счётчиков без частичного изменения.
Обратная миграция обязана отклонять непредставимое без потерь состояние;
проверить сохранность БД после отказа и поддерживаемый обратимый случай.

Команды: `cargo test -p radio-db -p radio-services --locked`,
`cargo test -p osu-radio-cli --locked`,
`cargo check -p osu-radio-server --locked`.
Повторить repository-контракты на отдельной временной PostgreSQL-БД
`radio_db_test_*` по [матрице](../../agent/development.md#repository-and-backend-checks),
включая lifecycle и rollback. Не использовать пользовательскую БД.
Сборка сервера здесь проверяет адаптацию вызывающего кода, а не новый HTTP-сценарий.

## Отчёт о выполнении

Реализация от 2026-10-16. Старые миграции 1–11 не изменялись.

### Изменённые участки и схема

- `crates/radio-db/src/migrations/m20261016_000012_queue_entries.rs`: фиксированные
  определения v11/v12, перенос каждой позиции и guarded downgrade; реестр миграций
  и reset дополнены новой таблицей. Схема меняется под прежней блокировкой и внешней
  транзакцией; old JSON/index удаляются после переноса.
- `model/queue.rs`, `entities/queue.rs`, новая `entities/queue_entry.rs`,
  `repositories/queue.rs`: `queue_entries` с positive BIGINT PK, unique BIGINT
  `position`, ключами аудио/плейлиста, nullable справочными ID, снимками подписей,
  сложности/обложки, availability и поколением. Singleton содержит текущий ID,
  границу, режим, revision/token и последний выданный ID. Справочные ссылки без FK:
  удаление библиотеки/плейлиста не меняет снимки и не удаляет записи очереди.
- `model/playlist.rs`, `repositories/playlist.rs`, экспорт моделей/сервисов:
  `PlaylistItem.hash_kind` доходит до сохранённого плейлистового ключа.
- `crates/radio-services/src/queue.rs`: существующие операции, включая путь
  `PlaylistService::play → QueueService::replace_in`, работают с entry-списком.
  Сохраняются прежние правила запуска/замены/переходов и токенов; очистка не сбрасывает
  счётчик выдачи. Подписи пунктов очереди сохраняются после удаления исходного item.
- `apps/osu-radio-server/src/routes/playback.rs`: существующая серверная проекция
  вычисляется из entry-модели. Новый HTTP-контракт относится к T06; отдельного
  постоянного JSON-хранилища и поддержки старых версий нет.
- `radio-db/src/tests/{queue,migration_lifecycle,playlists,listening_history,
  collections,model_projections}.rs`, общая тестовая очистка, service queue/playlist
  tests: исторические записи создаются SQL своей версии; последняя миграция — 12.
- [Database guide](../../agent/database.md) описывает новую схему и её ограничения;
  [backend guide](../../agent/backend.md#user-playlists) уточняет независимость подписей от item.

### Экспортируемые контракты для T02

`radio_db::model` и `radio_services` экспортируют `QueueEntry`, `QueueEntryId`,
`QueuePlaylistSource`, `QueueAvailability`, `QueueState` и `PlaybackMode`.

- `QueueEntryId::new(i64) -> Result<Self>`, `get() -> i64`, `Display`: ID строго
  положительный, десятичное строковое представление точное вплоть до `i64::MAX`.
  Qt/QML должен получать строку; передача ID в Qt реализуется последующими карточками.
- `QueueEntry`: `id`, `position: usize`, `audio_source: Option<SourceType>`,
  `playlist_source: Option<QueuePlaylistSource>` с installation/hash kind и hash,
  `audio_source_id`, `playlist_item_id`, `migration_audio_source_id`,
  `migration_playlist_item_id`, ordinary/Unicode title/artist, difficulty,
  nullable beatmap/set/cover IDs, `availability`, `check_generation: u64`.
- `QueueState`: `entries`, `current_entry_id`, `history_len: usize`,
  `last_entry_id: i64`, `mode`, `revision`/`playback_token: u64`.
  При current её позиция равна `history_len`; без current диапазон
  `[0, history_len)` — прошлое. Пустая граница 0, exhausted — длина.
- Методы состояния: `allocate_id`, `reindex`, `validate`, `current_index`,
  `current_entry`; `audio_source_ids()` / `playlist_item_ids()` — вычисляемые
  проекции для текущих обязательных вызывающих, а не второе хранилище.
- `QueueRepository::get()` читает singleton и записи одним LEFT JOIN statement:
  согласованность сохраняется даже у pool-вызова под PostgreSQL READ COMMITTED.
  `save(&QueueState)` допускает только transaction-bound репозиторий; вызывающий
  удерживает `user_data().lock()` до внешнего commit. До записи проверяются BIGINT,
  положительные/неповторные ID, плотный порядок, current, граница и режим;
  счётчики не уменьшаются, удалённые ID нельзя вернуть в список.
- Сохранение сейчас заменяет набор строк внутри одной транзакции. Точечные SQL-правки
  для будущих операций здесь не вводились. При ошибке вызывающий откатывает внешнюю
  транзакцию; репозиторий не делает самостоятельный commit.
- Старые Local/Copied-источники получают `Checking`, остальные `Unavailable`,
  поколение 0. Числовые идентификаторы без восстановленного ключа сохраняются
  только как `migration_*`; путь/hash не выдумываются. Подписи: item → library →
  явная заглушка `Unavailable track` для отсутствующего title.
- Downgrade разрешён только если полная замороженная реконструкция даёт ровно
  те же entry-поля/ID/порядок, границу и счётчик выдачи. Изменённые снимки,
  доступность/поколение, неприводимая граница и уже выданные лишние ID блокируют
  переход до первого изменения схемы.

### Ограничения

Автоматическая проверка использует синтетические источники и временные БД. Реальная
пользовательская БД, Windows, Qt GUI и физическое аудио не проверяются этой карточкой.
Файловая проверка/ожидание, восстановление привязок при импорте, новые операции,
полная wire/UI-проекция и лимит 5000 относятся к следующим карточкам. Проверенная
здесь availability — сохранённое начальное состояние; существующие команды пока
определяют playability через библиотеку, как до T01. Окончательная пользовательская
приёмка всего сценария не заявляется. Уже утраченный в v11 ключ автоматически
восстановить невозможно; downgrade намеренно отклоняет непредставимое состояние.
