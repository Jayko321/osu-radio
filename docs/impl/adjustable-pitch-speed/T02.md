# T02. Потоковое изменение темпа и pitch в локальном движке

Состояние: реализовано; автоматические проверки движка пройдены.
Прослушивание и нативная приёмка приложения остаются в T10/T12.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R2, R5, R6, R8;
[решение DSP](../adjustable-pitch-speed.md#обработка-звука).
Зависимости: нет. Независима от T01, T03, T04.

## Результат

Локальный Player меняет скорость с изменением либо сохранением высоты, в том
числе на лету; сохраняет исходную позицию и паузу, завершает обработанный хвост.

## Границы и контекст

- Владение: `crates/osu-radio-player/` и `Cargo.lock` для новой зависимости.
  Не менять клиент, медиаконтролы или CI/упаковку: это T07, T03 и T10.
- Начать с `src/lib.rs`: Player, Snapshot, prepare_at/replace,
  ReleasableSource и release_source; тестовый Headless в `src/tests.rs`
  уже потребляет mixer без аудиоустройства. Проверить всех вызывающих Player
  и конструкторы Snapshot перед расширением API.
- Добавить только сюда `signalsmith-stretch = 0.1.3`. Движок принимает единый
  набор speed + adjust_pitch, без DT/HT/NC и HTTP-идентичности. Для 1× оставить
  обычный путь; adjust_pitch использует скорость Rodio, сохранение высоты —
  потоковый Signalsmith внутри источника с ограниченными PCM-блоками.
- Не добавлять поток и обработку всего файла заранее. Учесть каналы,
  prefeed/latency, дробное число кадров, flush хвоста и смену параметров
  на границе блока. После EOF отдаётся ровно одно завершение.
- Snapshot содержит фактические параметры, позицию и длительность исходника;
  вычисление позиции учитывает историю скоростей, seek и задержку DSP.
  Сохранить ошибки загрузки, предыдущий источник при ошибке, освобождение
  декодера без callback и возможность подготовить параметры до play.
- Опубликовать в отчёте точные setter/type/поля Snapshot, единицы времени и
  ошибочные значения для T07/T08. Факты для frontend guide передать T11.
  Состав/версии новых Rust и встроенных C++ компонентов передать T10.

## Проверка и приёмка

Переиспользовать Headless, MP3 CBR/VBR, Vorbis и WAV из `tests/fixtures`.
Добавить небольшой генерируемый сигнал известной частоты: при HT/DT, включая
1,20× и границы 0,50×/2,00×, длительность меняется обратно скорости;
при adjust_pitch частота следует скорости, без него остаётся исходной.
В тесте указать обоснованные допуски с учётом latency, не требовать побитового
совпадения DSP. NC проверяется как тот же входной набор, без отдельного эффекта.

Транспортные проверки отличают реальные ошибки: смена скорости после уже
потреблённого участка не пересчитывает прошлое; paused update не возобновляет
аудио; seek сохраняет исходные координаты; короткий финальный блок не теряется,
EOF не ранний и не повторный. Невалидные/не finite параметры отклоняются без
повреждения текущего состояния. Сохранить проверки ошибок и release_source.

`cargo test -p osu-radio-player --locked` и
`cargo clippy -p osu-radio-player --all-targets --locked -- -D warnings`.
Нужны C++/libclang; доступность проверить до сборки, при настройке обратиться
к текущей документации. Нативные Linux/Windows сборки и слышимое качество
фиксируются отдельно в T10/T12; Headless их не доказывает.

  Добавлен 21 пакет; существующие версии пакетов не удалены и не обновлены.

### Контракт для T07/T08

```rust
pub struct PlaybackParameters {
    pub speed: f32,
    pub adjust_pitch: bool,
}
impl Player {
    pub fn set_parameters(
        &mut self,
        parameters: PlaybackParameters,
    ) -> Result<(), PlayerError>;
}
```

- Default: `{ speed: 1.0, adjust_pitch: false }`. `speed` — множитель, а не
  проценты; конечное значение в `0.5..=2.0`. Шаг и DT/HT/NC движок не проверяет:
  это правила верхнего слоя. NC 1,20× и DT 1,20× с pitch передают одну пару
  `{ speed: 1.2, adjust_pitch: true }`, отдельного NC-эффекта нет.
- `PlayerError::InvalidSpeed` отклоняет NaN, обе бесконечности и значения вне
  диапазона до изменения параметров, позиции, источника или состояния.
  Ошибка устройства остаётся `PlayerError::Output`.
- Setter допустим до `load` и после `load` до `play`. Пара сохраняется при
  load/seek/stop/replay, как громкость. **T07 обязан подавать параметры каждого
  нового назначения**, чтобы не переносить профиль предыдущего трека.
- На ходу последняя запрошенная пара применяется на следующей границе блока
  (512 выходных кадров, около 11,6 мс при 44,1 кГц, без учёта device buffer).
  Смена пары не переоткрывает файл и не перематывает его. На паузе новая пара
  подготавливается сразу с сохранением позиции и паузы; остаток обработанного
  блока перестраивается из сохранённого PCM. Незавершённый кадр каналов сохраняется.
- `Snapshot { state, position, duration, volume, parameters }`, где новое поле
  `parameters: PlaybackParameters` сообщает применённую пару, на паузе — уже
  подготовленную. Во время активного воспроизведения pending edit до границы
  блока ещё не выдаётся за применённую скорость.
- `position: Duration` и `duration: Option<Duration>` — **исходное аудио**,
  без деления на скорость. Seek тоже получает исходные координаты. Позиция
  интегрирует потреблённые выходные кадры с действовавшей на них скоростью;
  lookahead и prefeed не двигают её, смена скорости не пересчитывает прошлое.
  Громкость независима. Родio округляет изменённую частоту дискретизации до
  целых Гц; позиция pitch-пути учитывает именно это отношение частот.
- После вывода хвоста Snapshot стабильно возвращает `Ended`; отдельного
  callback/event завершения у Player нет. Однократную отправку клиентского
  события, как и раньше, обеспечивает worker (T07).
- Для UI T07 делит source position/duration на фактическую скорость и переводит
  UI seek обратно ровно один раз; native в T08 получает source coordinates +
  rate, Discord — время с учётом скорости. Эта интеграция в T02 не выполнялась.

Вызовы Player и конструкторы его Snapshot проверены поиском по `crates/` и
`apps/`: клиентский worker использует существующие методы, тестовые Snapshot
дополняются через Default. Механические правки клиента для нового поля не нужны.

### Автоматическая проверка

Linux x86_64, Rust 1.98.0, GCC C++ 16.2.1. Системный libclang в обычном поиске
отсутствует, найден ROCm LLVM 22. Первичная сборка с одним `LIBCLANG_PATH`
закончилась ошибкой bindgen `stddef.h file not found`; явный resource-dir
исправил её без установки пакетов и изменения системной конфигурации.
Обычный target одновременно использовался соседними работами, поэтому итоговые
проверки выполнялись в отдельном каталоге:

```bash
export CARGO_TARGET_DIR=/tmp/osu-radio-t02-target
export LIBCLANG_PATH=/opt/rocm/lib/llvm/lib
export BINDGEN_EXTRA_CLANG_ARGS=-resource-dir=/opt/rocm/lib/llvm/lib/clang/22
cargo test -p osu-radio-player --locked
cargo clippy -p osu-radio-player --all-targets --locked -- -D warnings
cargo fmt -p osu-radio-player --check
git diff --check -- Cargo.lock crates/osu-radio-player
```

Результат: **11 tests PASS**, doc-tests PASS (0), Clippy PASS с запретом
предупреждений, форматирование и whitespace PASS. Итоговые логи:
`/tmp/t02-isolated-test.log`, `/tmp/t02-clippy.log` (временные локальные файлы).
