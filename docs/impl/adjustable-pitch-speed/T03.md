# T03. Фактическая скорость в MPRIS и SMTC

Состояние: реализовано; доступные автоматические проверки Linux пройдены.
Windows native и пользовательская приёмка остаются открытыми до T12.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R5, R6;
[решение интеграций](../adjustable-pitch-speed.md#время-интерфейс-и-интеграции).
Зависимости: нет. Независима от T01, T02, T04.

## Результат

Нативные адаптеры принимают фактическую скорость и исходные координаты,
публикуют скорость в MPRIS/SMTC, сохраняя существующие seek и lifecycle.

## Границы и контекст

- Владение: `crates/osu-radio-media-controls/`. Единственное изменение клиента
  на этом этапе — механически дополнить конструктор media Snapshot в
  `crates/osu-radio-client/src/view_models/player.rs` нейтральной скоростью 1×.
  Получение настоящей скорости и готовность модов подключит T07/T08.
- В `src/lib.rs` расширить Snapshot скоростью с default 1×, не 0.
  Исходные duration/position и LaunchKey сохраняют значения/единицы.
  Скорость допустима в пределах 0,5–2; предусмотреть недопустимые значения
  на границе публикации по существующему error contract.
- Linux: `src/linux/player.rs`, `mod.rs`, `transform.rs` и conversion;
  публиковать Rate и изменения свойства, MinimumRate=0.5, MaximumRate=2.
  SMTC: `src/windows/mod.rs`, PlaybackRate и исходная timeline.
  Нового SetRate/управления модами со стороны ОС не добавлять.
- Сохранить порядок событий, launch-bound seek, artwork и acknowledged cleanup.
  Не вводить клиент/Qt/HTTP зависимости в native crate.
- Передать T08 имя/тип поля скорости и правила публикации; факты и ссылки
  для frontend/architecture guide передать T11. Не менять эти общие guides
  одновременно с другими стартовыми ветками.

## Проверка и приёмка

Расширить существующие transformation/protocol/native проверки:
default 1×, rate 0.75/1.2/1.5, изменение во время playing и paused,
сохранность исходной duration/position и launch-key команд. MPRIS должен
отправлять Rate change, даже когда track/token не менялись. Запрос изменения
скорости через ОС не создаёт клиентскую команду модов.

`cargo test -p osu-radio-media-controls --locked`, scoped Clippy;
Linux opt-in протокол:
`dbus-run-session -- cargo test -p osu-radio-media-controls --test linux --locked -- --ignored --test-threads=1`.
Это private bus, не desktop bus. Проверить сборку клиента после механической
адаптации Snapshot. Windows HWND-пробы выполнять только на Windows по
[процедуре](../../agent/development.md#system-media-controls-verification);
если среды нет, явно оставить их непроверенными до T12.
Нативная скорость от реального Player появится после T08.

## Отчёт о выполнении

### Реализация и передача T07/T08

2026-10-20, Linux x86_64, Rust/Cargo 1.98.0; исходный HEAD
`cf843383f32ec36e689b033e86bc897c8d5990dd`.

- [Snapshot](../../../crates/osu-radio-media-controls/src/lib.rs) расширен
  публичным полем `rate: f64`: фактическая скорость, default `1.0`, допустимы
  конечные значения `0.5..=2.0`. `duration` и `position` остаются исходными
  `Duration`, `LaunchKey` и `seek_serial` сохраняют прежний смысл.
- Валидация выполняется при нативной публикации, включая начальный снимок:
  Linux — `Published::new`, Windows — `Session::publish` (`E_INVALIDARG`).
  Неверная скорость завершает адаптер через существующий `Status::Failed(Error)`
  без retry, с прежним acknowledged cleanup. Контракт `publish -> bool`
  не менялся: `true` означает постановку последнего снимка, а не подтверждение
  нативной публикации; ошибку наблюдают через `status()`.
- [MPRIS Player](../../../crates/osu-radio-media-controls/src/linux/player.rs)
  отдаёт фактический Rate, MinimumRate `0.5`, MaximumRate `2.0`.
  [Diff](../../../crates/osu-radio-media-controls/src/linux/transform.rs)
  публикует `Property::Rate` при изменении скорости того же запуска,
  в том числе на паузе. Повторная запись текущего Rate из ОС — no-op,
  другое значение возвращает существующий NotSupported; клиентских команд
  модов не добавлено.
- [SMTC](../../../crates/osu-radio-media-controls/src/windows/mod.rs)
  вызывает `SetPlaybackRate(snapshot.rate)`; timeline остаётся в исходных
  координатах. Callback `PlaybackRateChangeRequested` не регистрируется.
- Единственная адаптация
  [клиента](../../../crates/osu-radio-client/src/view_models/player.rs) —
  `rate: 1.0` в `system_snapshot`. Передача фактической скорости из совпадающего
  worker и готовность модов принадлежат T07/T08; T03 их не реализует.
- Зависимости, lifecycle, порядок событий, artwork и conversion-код
  не менялись. Параллельные изменения T01/T02/T04 и исходные dirty files
  сохранены; коммитов нет.

Внешние API сверены через Context7: MPRIS specification и Windows UWP API
Documentation; также с установленными исходниками `mpris-server 0.10.0` /
`windows 0.62`. Первичные источники:
[MPRIS Rate](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html#Property:Rate),
[SMTC PlaybackRate](https://learn.microsoft.com/en-us/uwp/api/windows.media.systemmediatransportcontrols.playbackrate).

### Непроверенное и передача T11/T12

Windows target/desktop отсутствует: Windows-сборка и реальные HWND/Qt пробы
остаются непроверенными до T12. Проверка private D-Bus не является проверкой
панели рабочего стола, физических media keys или звука. Пользовательская
приёмка не выполнялась. Фактическая скорость живого Player будет подключена
в T08; вся функция adjustable pitch/speed этой карточкой не завершается.

T11 обновляет frontend/architecture guides по ссылкам выше: native Snapshot
теперь содержит исходные координаты + actual rate, MPRIS уведомляет об изменении
скорости того же запуска и объявляет диапазон `0.5..=2.0`, SMTC публикует
PlaybackRate; управление модами остаётся у клиента. Общие guides в T03
не редактировались согласно распределению владения. Существенных расхождений
с карточкой/спецификацией/планом нет.
