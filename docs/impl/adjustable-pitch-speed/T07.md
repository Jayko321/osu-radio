# T07. Моды до первого play, обновление на лету и шкала времени

Состояние: реализовано; client lib tests (225, с `mock` 242), player tests и Clippy PASS; нативная приёмка — T12.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R2–R6, R8;
[клиент](../adjustable-pitch-speed.md#клиент-и-сохранение) и
[время](../adjustable-pitch-speed.md#время-интерфейс-и-интеграции).
Зависимости: T02 — atomic engine parameters/исходный snapshot;
T03 — native Snapshot с rate и механический вызов;
T06 — состояние, effective profiles, загрузка и сохранение (включает T01/T05).

## Результат

Все пути Play/Resume/Next получают верные моды с первого звука. Изменение
профиля текущего запуска сохраняет исходную позицию, паузу и token.
Клиентская презентация/seek использует время с учётом скорости.

## Границы и контекст

- Владение: `client/src/playback.rs`, `view_models/player.rs`, необходимые
  изменения controller.rs/coordinator.rs/settings/Track и их tests/mock.
  Это последовательная передача владения от T03/T05/T06.
- Расширить существующий Command::Assign и Engine seam параметрами T02.
  Параметры и громкость применяются до load/play где необходимо;
  повторный Assign того же entry/token обновляет их без перезапуска.
  Сохранить generation/entry/token guards, download cancellation, temp-file
  cleanup, started/failed/finished callbacks и отсутствие ложной listening date.
- Один admission gate: загружены и громкость, и моды. Пока нет готовности,
  удерживать последнее assignment; ошибка любой загрузки блокирует запуск
  до Retry. Не создавать параллельный механизм допуска в VolumeWork и mods.
- Selected B изменяет B; текущий A пересчитывается по профилю своего запуска.
  Mode switch пересчитывает A. Смена binding queue entry не переносит профиль
  нового источника на старый запуск. Отдельного fetch модов перед Play нет.
- Движок/Playback сохраняют source position/duration и actual speed;
  PlayerPresentation отдаёт position/speed и duration/speed, UI seek переводится
  обратно ровно один раз. Выбранный B показывает duration по своему профилю,
  неизвестная duration остаётся неизвестной. Track metadata не переписывать.
- Системный seek остаётся в source coordinates: не проводить через новое
  преобразование UI seek. Передать T08 actual rate и доступный источник snapshot,
  T09 — presentation/seek signatures и ключ отмены drag (launch + speed).
  Факты для frontend guide передать T11.

### Реализация (2026-10-24)

Файлы (`crates/osu-radio-client/src`):
- `playback.rs` — `Command::Assign.parameters: PlaybackParameters` (re-export из player),
  `Engine::parameters`, `Core.parameters`; `From<AudioModsProfile> for PlaybackParameters`.
  Пара проверяется (конечная, 0,5–2) до любых изменений; применяется до `load/play` в
  `load_cached` рядом с громкостью, а при том же entry/token — на месте (позиция, пауза, token,
  feedback не меняются; неизменная пара движку не передаётся). Поздняя правка при скачивании
  побеждает: файл декодируется уже с последней парой.
- `view_models/settings.rs`, `mods.rs` — единственный gate: `playback_ready()` =
  громкость + `mods.loaded`; `release_playback_gate` (отложенный Assign + старт стрима)
  вызывается из обоих ответов загрузки. Параллельного механизма нет, `deferred_assignment`
  остаётся в `VolumeWork`. Ошибка загрузки модов держит gate закрытым до Retry (`ModsAction::Retry`).
  `selected_mods(track)` — эффективный профиль выбранного трека.
- `view_models/player.rs`, `controller/coordinator.rs`, `controller/system_media.rs` — gate
  вместо `volume.settings.is_some()` (Play, toggle, apply_assignment, can_play, system-ready);
  `assign_worker` берёт `assignment_parameters()` (профиль из сохранённого источника запуска,
  `assignment_mods`); `mods_action` пересылает тот же Assign живому worker (не создаёт новый)
  и обновляет презентацию.
- Время: `PlayerPresentation` — `position`/`duration` теперь в шкале UI (source ÷ скорость,
  целочисленно, 4:00 при 150% = 2:40 точно); новые поля `speed_percent` (фактическая скорость
  звучащего запуска из `Snapshot.parameters`, иначе профиль выбранного трека; Default 100,
  `Default` написан вручную) и `selected_duration` (длительность выбранного B по его профилю,
  неизвестная остаётся `None`; метаданные Track не меняются). `presentation()` получил 5-й
  аргумент `selected_mods`. `AppCommand::Seek` принимает UI-время; `seek_selected`
  умножает на фактическую скорость ровно один раз. Системный seek (`system_seek`) не менялся.

Контракты для следующих карточек:
- T08: фактическая скорость — `PlayerViewModel.playback.snapshot.parameters.speed` (f32, источник
  Snapshot воркера); `system_snapshot` по-прежнему ставит `rate: 1.0`; `playback.snapshot.position/duration`
  — исходные координаты, как и ждёт native. Единственная правка в system_media — `settings_loaded`
  теперь `playback_ready()` (иначе MPRIS мог бы принять Play, пока assignment отложен).
- T09: `PlayerPresentation { position, duration, selected_duration, speed_percent }`; Qt пока
  показывает метку выбранной длительности как `duration.or(selected_track.duration)` — для
  не звучащего B она без масштаба, надо перейти на `selected_duration`. Ключ отмены drag —
  (`current_entry_id`/token запуска, `speed_percent`). `AppCommand::Seek` — UI-время.
- T11 (frontend/architecture): единый gate громкость+моды; Assign несёт параметры движка;
  время UI = source/speed, seek переводится в `seek_selected`.

Новые тесты и что они доказывают:
- `playback::tests::parameters_precede_every_first_sample_and_update_the_same_launch_in_place`
  (fake Engine, `play_parameters` фиксирует пару в момент `play`): скачивание с поздней правкой,
  update того же launch без перезапуска (позиция 12 с, Playing, нет feedback, 1 load), правка на паузе
  и resume без перезагрузки, новый token с кэшированным файлом и автоследующий трек получают
  собственную пару, недопустимая скорость (NaN/0,49/2,01) не заменяет здоровый запуск.
- `one_gate_holds_the_last_assignment_until_volume_and_mods_are_loaded`: оба порядка загрузки,
  стартует только последнее assignment (revision 2); ошибка модов не пускает запуск, успешный
  повторный результат пускает.
- `mode_switch_resends_the_current_launchs_own_profile_without_restarting_it`: звучащий A (NC 1,20)
  при выбранном B (HT 0,75); переключение режима (individual ↔ global) даёт 1,2/pitch и 1,0 для A,
  тот же token у живого fake worker.
- `presentation_time_follows_actual_speed_and_the_selected_tracks_own_profile`: 4:00 при 1,5× → 2:40,
  позиция source 1:30 → 1:00; при смене скорости (1,0/1,2/0,75) source-позиция сохраняется;
  выбранный B с другой скоростью, неизвестная длительность остаётся неизвестной.
- `ui_seek_converts_once_while_system_seek_stays_in_source_time`: UI 1:00 при 1,5× → source 1:30;
  системный `SeekAbsolute` 1:00 → source 1:00.
- Исправлены два ожидания T06: `controller/mods_tests.rs` выставляет `stream_started`, потому что
  успешная загрузка модов теперь может открыть gate и стартовать стрим; редактирование без worker
  по-прежнему не создаёт его (`mods_action` пересылает Assign только существующему worker).
