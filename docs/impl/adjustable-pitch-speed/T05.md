# T05. HTTP модов и клиентский wire contract

Состояние: реализовано; автоматические проверки T05 пройдены. Пользовательская приёмка не выполнялась.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R1, R3–R6, R8;
[решение API](../adjustable-pitch-speed.md#профиль-хранение-и-http).
Зависимости: T01 — сервис, типы и согласованные проекции. T02/T03/T04 не нужны.

## Результат

Общий профиль и индивидуальные моды доступны через HTTP. Клиент получает
профили в библиотеке, плейлистах, полной очереди и назначениях REST/NDJSON;
его ApiClient выполняет чтение и сохранение с проверенными формами запросов.

## Границы и контекст

- Владение: `apps/osu-radio-server/`, клиентские `src/models.rs`, `src/api.rs`,
  `src/api/`, `src/view_models/track.rs` и преобразования треков/очереди/плейлистов,
  необходимые механические DTO-конструкторы/fixtures клиента, `docs/agent/backend.md`.
  Settings/worker/UI поведение здесь не реализовывать. Не менять native
  конструктор в player.rs, принадлежащий T03.
- Образцы: routes/audio_settings.rs, tracks.rs, playlists.rs, playback.rs,
  routes/mod.rs и docs.rs. Использовать только Services, сохранить оба router
  docs on/off и безопасный unexpected-error response.
- GET/PATCH `/api/user-data/audio-mods`; PUT/DELETE
  `/api/audio-sources/{id}/mods`. Общий режим/профиль передаётся отдельно
  от громкости. С T01 сверить форму partial update: пропущенное сохраняется,
  merged результат валидируется целиком, ошибка не меняет данные.
  Использовать существующую строгую обработку типов/null/unknown fields.
- Добавить nullable `mods` в wire DTO и required/nullable OpenAPI-проекции,
  включая верхний уровень assignment и вложенный track. DTO передаёт
  сохранённый индивидуальный профиль, не вычисленный общий результат.
- Протянуть профиль в клиентский Track и все преобразования library/playlist/
  queue/assignment; исходную duration не менять. Новые загрузочные endpoints
  добавить в затронутые HTTP fixtures. Не требовать отдельного fetch перед Play.
- Записать точные wire keys/settings schema и сигнатуры ApiClient для T06.
  Клиент/сервер обновляются вместе; миграцию старых клиентов не добавлять.

Контракт для T06 — типы находятся в `osu_radio_client::models`:

```rust
AudioModsMode::{None, Dt, Ht} // wire: none, dt, ht; NC = dt + true
AudioModsProfile { mode: AudioModsMode, speed_percent: u16, adjust_pitch: bool }
AudioModsSettings { individual_mods_enabled: bool, global_profile: AudioModsProfile }
AudioModsPatch {
    individual_mods_enabled: Option<bool>,
    global_mode: Option<AudioModsMode>,
    global_speed_percent: Option<u16>,
    global_adjust_pitch: Option<bool>,
}
// Async ApiClient methods:
audio_mods(&self) -> Result<AudioModsSettings, ApiError>
update_audio_mods(&self, changes: &AudioModsPatch) -> Result<AudioModsSettings, ApiError>
set_audio_mods(&self, id: i32, profile: Option<AudioModsProfile>) -> Result<(), ApiError>
```

GET/PATCH `/api/user-data/audio-mods` возвращает
`{"individual_mods_enabled":false,"global_profile":{"mode":"none","speed_percent":100,"adjust_pitch":false}}`
по умолчанию. PATCH принимает **плоские** необязательные поля перечисленного
`AudioModsPatch`; `None` пропускается при сериализации. Переход mode не
подставляет 150/75 или pitch: объединённый профиль должен быть валиден.
PUT `/api/audio-sources/{id}/mods` получает полный профиль, DELETE удаляет его;
успех 204, неизвестный ID 404. Ошибки mode/range/type/null/unknown fields и
несогласованного профиля — 400 с `{"error":...}`, без частичной записи.
Unexpected service errors остаются безопасными 500.

`LibraryTrack`, `PlaylistItem`, `QueueEntry`, `PlaybackAssignment` и `Track`
содержат `mods: Option<AudioModsProfile>`. Сервер передаёт обязательный nullable
ключ в каждой нужной проекции, включая верхний assignment и вложенный track
в REST/NDJSON; глобальный эффективный профиль сюда не подставляется.
`Track::from`, `PlaylistItem::track` и `QueueRow::from` сохраняют профиль;
путь assignment использует существующий `Track::from`. Длительность исходника
не меняется и отдельного fetch перед Play не добавлено. Legacy helper
`library_tracks(&[BeatmapSet])` не получает override из старого set DTO и
оставляет `mods=None`, как уже делает для даты/громкости; production library
использует `/api/tracks`.
