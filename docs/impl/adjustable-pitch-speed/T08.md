# T08. Подключение фактической скорости к медиаконтролам и Discord

Состояние: реализовано; client lib (mock off/on), media-controls и scoped Clippy PASS; реальная приёмка — T12.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R5, R6;
[решение интеграций](../adjustable-pitch-speed.md#время-интерфейс-и-интеграции).
Зависимости: T07 — actual rate/source coordinates и admission gate;
T03 — поддержка rate в native crate. Параллельна T09 и оставшейся T10.

## Результат

MPRIS/SMTC публикуют скорость звучащего запуска, а Discord показывает
скорректированное время и обновляется при смене скорости, в том числе на паузе.
Выбор/изменение B не подменяет внешнее представление играющего A.

## Границы и контекст

- Владение: `client/src/controller/system_media.rs` и tests,
  `client/src/discord.rs`, `src/discord/tests*`. При необходимости точечно
  передать изменения system_snapshot в player.rs от T07 до старта T09;
  после старта T09 не менять публичные client/Qt контракты.
- Использовать source position/duration и actual rate из совпадающего
  entry/token worker, не selected profile и не UI-scaled шкалу.
  Готовность native capabilities учитывает оба settings load.
  Сохранить launch-key и токены отложенных seek/overflow Next.
- Discord переводит position/duration в шкалу реального времени один раз;
  скорость входит в ключ обновления presence, чтобы без смены трека/seek
  обновлялись timestamps и paused label. Не менять IPC/lifecycle/reconnect.
- Записать факты и test links для frontend guide в отчёт T11.

## Проверка и приёмка

Расширить system_media tests: исходные координаты + rate 1.2/1.5/0.75,
A current/B selected, rate change при playing/paused, источник после rebinding,

и пересчитан. Сохранить отсутствие timestamps на паузе/при неизвестном конце.

`cargo test -p osu-radio-client --lib --locked` с mock off/on,
`cargo test -p osu-radio-media-controls --locked`, scoped Clippy.

Discord, desktop panel и физические клавиши отдельно в T12.

### Реализация (2026-10-24)

Файлы (`crates/osu-radio-client/src`), публичные контракты не менялись:
- `view_models/player.rs` — `system_snapshot`: `rate` = `playback.snapshot.parameters.speed`
  звучащего запуска, пока он `observed` (worker совпадает по entry/token/audio, нет loading/error);
  иначе нейтральные 1,0. Профиль выбранного B не участвует. `position`/`duration` остаются
  исходными координатами (T07); launch-key, `seek_serial`, токены отложенных seek/Next не тронуты.
  Native готовность уже включала оба settings load (`playback_ready()`, T07).
  Дополнительных изменений `system_media.rs` не потребовалось: `publish_system_media` вызывается
  каждый цикл, а `transform` (T03) публикует смену `Rate`.
- `discord.rs` — `Presence::from_playback` один раз переводит position/duration из исходной шкалы
  в реальное время (÷ скорость, скорость вне 0,5–2 трактуется как 1,0; переполнение → `Duration::MAX`);
  paused label использует пересчитанную позицию; в `Key` добавлен `speed_bits`, поэтому смена
  скорости без смены трека/seek/state переопубликовывает presence, в том числе на паузе.
  IPC/lifecycle/reconnect не менялись; на паузе и при неизвестном/нулевом конце timestamps нет.

Новые тесты:
- `controller::system_media::tests::rate_is_the_sounding_launchs_applied_speed_with_source_coordinates`:
  A звучит, B выбран; rate 1,2/1,5/0,75 на Playing и 1,5 на Paused публикуется в native backend,
  position 9 с и duration 240 с не масштабируются, launch прежний; при неподтверждённом worker — 1,0.
- `discord::tests::speed_scales_source_time_once_and_rate_only_change_republishes_even_paused`:
  240 с @1,5 → span 160 с; 90 с → 60 с; пауза: label «1:00», без timestamps; смена 1,5→0,75
  на паузе будит worker и даёт «2:00»/320 с; неизвестный конец — без timestamps.
- Существующий `seek_is_current_launch_bound…` + `ui_seek_converts_once_while_system_seek_stays_in_source_time`
  (T07) покрывают seek с тем же launch key и отсутствие двойного пересчёта; rebinding —
  `…new_launch_clears_old_position…`. Отдельный тест на них не дублировался.
