# T06. Клиентское редактирование и надёжное сохранение модов

Состояние: реализовано; клиентские tests и Clippy PASS в обоих состояниях feature `mock`; пользовательская приёмка не выполнялась.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R1, R3, R4, R6–R8;
[клиентское решение](../adjustable-pitch-speed.md#клиент-и-сохранение).
Зависимости: T05 — ApiClient, DTO и профили в Track. T02/T03/T04 не нужны.

## Результат

SettingsViewModel владеет общим и индивидуальным редактированием, immediate
local state, отдельной очередью сохранения, Retry и shutdown flush.
Мышь/клавиши могут использовать одни клиентские действия. Offline mock
поддерживает те же правила без сети и аудио.

## Границы и контекст

- Владение: `client/src/view_models/settings.rs`, новый соседний модуль модов
  и его tests, нужные экспорты, `src/controller.rs`, `controller/coordinator.rs`,
  `controller/workflow.rs` при необходимости, `src/mock.rs`/затронутый mock,
  клиентские fixtures. На этой стадии единственный владелец этих файлов — T06.
- Переиспользовать образец `view_models/volume.rs`, settings load/save handlers
  и volume tests. Состояние модов не добавлять в VolumeWork и не создавать
  шестую VM/новый event loop. Очередь модов самостоятельная, сериализованная,
  с coalescing одного адресата за 200 мс; deadline/save completion включены
  в существующий цикл и await shutdown до остановки backend.
- Общий профиль и индивидуальные настройки сохраняются при смене режима;
  отсутствующая индивидуальная настройка означает none, а не global.
  Правила громкости остаются независимыми. Выбранный B — адресат редактирования,
  текущий A — отдельный вход для вычисления effective параметров.
- D: DT → NC → none, E включает/снимает HT. Новая активация: DT=150/false,
  HT=75/false; DT↔NC сохраняет скорость. NC не отдельное хранимое состояние.
  Снятие возвращает 100/false. Проверять speed bounds и целый шаг.
- Ответы чтения/сохранения не затирают более новое local edit, включая DELETE.
  Защитить позднее событие от прежнего выбранного трека/режима; опубликовать
  для T09 адресат и способ завершения/отмены редактирования.
- Экспортировать settings state/actions для адаптера и effective профиль для
  текущего назначения/выбранного трека. Подготовить загрузку модов и её статус;
  единый playback gate и передачу движку завершает T07.
  Обновить fixtures, чтобы новый GET не висел/не отвечал чужим телом.
  Передать T07/T09 фактические сигнатуры, а T11 — изменения frontend/architecture.

## Проверка и приёмка

Основную матрицу правил R1/R3/R4/R6/R7/R8 проверить на этом уровне один раз:
общий DT → individual без overrides = 1×; NC A/HT B; A playing/B selected;
сохранённые наборы после mode roundtrip; shared audio; DT/D/D и E/E,
скорость 1.20 сохраняется при DT→NC. Действия для B не подменяют профиль A.
Проверить debounce, разные адресаты, out-of-order reads/ACK, Retry после
ошибки загрузки/записи, завершение очереди при shutdown и конечную ошибку
без бесконечного retry. Для времени использовать контролируемые часы
существующих tests, без нового тестового каркаса.

`cargo test -p osu-radio-client --lib --locked` и с `--features mock`,
scoped Clippy для обоих состояний feature. Эти проверки подтверждают состояние
и запросы; применение параметров до первого звука подтверждает T07.

## Отчёт о выполнении

### Реализация

Код был написан в предыдущем прерванном сеансе (20.10, без отчёта); в этом сеансе он
сверен с карточкой, спецификацией и планом, переписывать его не потребовалось.

Файлы (`crates/osu-radio-client/src`):
- `view_models/mods.rs` (новый) — `Editor` (правила D/E, границы, адресат/epoch),
  `ModsWork` (очередь, save task, load request/revision), методы `SettingsViewModel`;
  `view_models/mods/tests.rs` (новый); подключение в `view_models/mod.rs`, `settings.rs`.
- `controller.rs`, `controller/coordinator.rs` — `AppCommand::Mods`, `AppUpdate::AudioMods`,
  `Completed::AudioMods`, ветки deadline/save-completion в существующем `select!`,
  `load_mods` после подключения, `flush_mods_saves` при shutdown;
  `controller/mods_tests.rs` (новый, реальный HTTP-fixture).
- `mock.rs`, `mock/mods.rs` (новый) — `MockState::mods` с теми же `Editor`-правилами.
- `lib.rs` — экспорт `AudioModsState`, `ModsAction`, `ModsEdit`, `ModsEditTarget`.
- Правки fixtures других модулей — поле `mods: None` в `Track`/DTO.

Контракты для T07/T09 (фактические сигнатуры):
- `ModsAction::{SetIndividual(bool), Edit{target, edit}, Finish(target), Retry}`,
  `ModsEdit::{CycleDt, ToggleHt, SetSpeed(u16), SetAdjustPitch(bool), Clear}`.
  Команда: `AppCommand::Mods(ModsAction)`.
- `AudioModsState { settings, loaded, loading, saving, error, target: Option<ModsEditTarget>,
  selected_profile, selected_has_override }`, приходит как `AppUpdate::AudioMods`.
  `target` = `None`, пока моды не загружены или в индивидуальном режиме ничего не выбрано.
- `ModsEditTarget { audio_id: Option<i32>, epoch }` — адресат; поздний `Edit` с прежним
  адресатом/epoch отклоняется. `Finish(target)` делает записи due и аннулирует epoch
  (способ завершения редактирования для popup).
- Для T07: `SettingsViewModel::{effective_mods(audio_id, stored), assignment_mods(&assignment),
  mods_loaded()}`. Единый playback gate (громкость + моды) T06 не добавляет.
- Для T09: `apps/osu-radio-qt/src/app_bridge.rs` пока игнорирует `AppUpdate::AudioMods(_)`; Qt-проекция
  и QML-связка — T09.
- Для T11: в `docs/agent/frontend.md`/architecture нужно описать отдельную очередь модов

  `mods_load_retry_and_event_loop_save_completion_use_the_real_api`.
