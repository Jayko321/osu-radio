# T01. Сохранение модов и согласованные сервисные проекции

Состояние: реализовано, автоматические проверки T01 пройдены. Пользовательская приёмка не выполнялась.
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R1, R3–R6, R8;
[решение](../adjustable-pitch-speed.md#профиль-хранение-и-http).
Зависимости: нет. Независима от T02, T03, T04.

## Результат

Миграция сохраняет существующие данные; `Services::audio_mods()` читает и атомарно
сохраняет общий режим/профиль и индивидуальные профили по идентичности аудио.
Библиотека, плейлисты, полная очередь и текущее назначение возвращают сохранённый
nullable-профиль в согласованном snapshot чтения.

## Границы и контекст

- Владение: `crates/radio-db/`, `crates/radio-services/`,
  `docs/agent/database.md`; только необходимые механические исправления
  существующих серверных конструкторов после расширения сервисных моделей.
  HTTP-поведение и клиент принадлежат T05.
- Образцы: `src/repositories/audio_volume.rs`, `src/repositories/user_data.rs`,
  `src/model/user_data.rs`, `src/entities/user_data.rs` в radio-db;
  `src/audio_settings.rs`, `src/beatmap_set.rs`, `src/playlist.rs`,
  `src/queue.rs` в radio-services. Проверить реэкспорты и оба доступа
  Database/Transaction в `radio-db/src/lib.rs`.
- Сейчас последняя миграция — `m20261016_000014_queue_launch_source.rs`.
  Добавить следующую, зарегистрировать в `src/migrations/mod.rs` и включить
  `audio_mods` в explicit reset. Старые миграции не переписывать.
- Профиль: `mode: none|dt|ht`, integer `speed_percent`, bool `adjust_pitch`;
  none = 100/false, DT = 101–200, HT = 50–99. NC хранится как dt + true.
  Общие поля — в user_data; таблица audio_mods имеет ключ
  `(audio_kind, source_location)` без FK на библиотеку.
- Сохранить singleton writer lock, outer transaction и проверку merged PATCH
  до записи. Ограничения БД отклоняют недопустимые сочетания. Сервис не знает Qt.
- `QueueService::assignment` сейчас опирается на `QueueLaunchSource`:
  профиль текущего запуска читается по этому источнику даже после перепривязки
  queue entry. Записи модов не меняют queue revision/token. Нет профиля — нет
  индивидуальных модов; общий профиль сохраняется отдельно и не наследуется.
- Передать T05 точные типы/экспорты, сигнатуры сервиса, правила partial update
  и поля всех проекций. Обновить database guide со ссылками на проверки.

## Проверка и приёмка

Расширить существующие `radio-db/src/tests/audio_settings.rs`,
`radio-services/src/tests/audio_settings.rs` и queue source-rebinding contracts
либо соседние тесты модов на той же инфраструктуре. Проверить populated upgrade
v14 → новая версия, reopen/reset и сохранность громкости, библиотеки, очереди,
плейлистов, истории. Ошибочный профиль/частичное обновление не оставляет записи;
пропущенные поля сохраняются, режимы не стирают профили.
Проверить shared audio в сложностях/плейлистах, удаление/переимпорт с новым ID,
другую идентичность после смены kind/location и профиль старого запуска после
rebinding. Матрицу клиентских DT/D/E переходов здесь не дублировать.

Команды: `cargo test -p radio-db -p radio-services --locked`,
`cargo test -p osu-radio-cli --locked`, `cargo check -p osu-radio-server --locked`;
scoped Clippy для изменённых crates. Повторить repository/service contracts
раздельно на свежих PostgreSQL `radio_db_test_*` через
`RADIO_DB_TEST_POSTGRES_URL` по [матрице](../../agent/development.md#repository-and-backend-checks).
Пользовательскую БД не открывать. HTTP и физическое аудио эта карточка не подтверждает.

Передача T05 — точные публичные контракты:

```rust
// Все перечисленные типы реэкспортированы из radio_services.
AudioModsMode::{None, Dt, Ht} // as_str(): none/dt/ht, FromStr отклоняет другие строки
AudioModsProfile { mode: AudioModsMode, speed_percent: u16, adjust_pitch: bool }
AudioModsSettings { individual_mods_enabled: bool, global_profile: AudioModsProfile }
AudioModsPatch {
    individual_mods_enabled: Option<bool>,
    global_mode: Option<AudioModsMode>,
    global_speed_percent: Option<u16>,
    global_adjust_pitch: Option<bool>,
}
Services::audio_mods() -> AudioModsService<'_>
AudioModsService::get().await -> anyhow::Result<AudioModsSettings>
AudioModsService::update(AudioModsPatch).await -> anyhow::Result<AudioModsSettings>
AudioModsService::set_profile(id: i32, Option<AudioModsProfile>).await -> anyhow::Result<()>
AudioModsError::{InvalidProfile, UnknownAudio(i32)} // anyhow downcast
```

`AudioModsProfile::default()` = None/100/false, `is_valid()` проверяет целый
профиль. DTO и serde принадлежат T05: доменные типы здесь не сериализуются.
Пропущенные поля PATCH сохраняют прежние значения; сервис не подставляет
начальные 150/75 и не сбрасывает pitch при смене mode. Например, только
`global_mode=Ht` при сохранённой скорости 130 — ошибка без изменения даже
одновременно переданного `individual_mods_enabled`. Корректная смена должна
передать нужную скорость; переход к None также требует 100/false.
`Some(profile)` заменяет индивидуальный профиль целиком, `None` удаляет его.
Неизвестный audio ID ошибочен и для записи, и для удаления. Nullable `mods`
во всех проекциях — сохранённый индивидуальный профиль независимо от режима;
`None` не наследует общий. Явно сохранённый None/100/false отличается в проекции
от отсутствия записи. Настройки громкости и queue revision/token не меняются.
