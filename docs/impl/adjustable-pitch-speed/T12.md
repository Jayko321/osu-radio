Состояние: подготовлено к приёмке; **приёмка не выполнена** (прослушивание, физический
ввод и Windows недоступны агенту).
Источники: [спецификация](../../specs/adjustable-pitch-speed.md), R1–R8,
примеры 1–8 и реальная приёмка;
[общий сценарий](../adjustable-pitch-speed.md#проверка-результата).
Зависимости: T11 — объединённое проверенное приложение, handoff и evidence T10.
Linux и Windows части можно проходить параллельно в отдельных окружениях;
один владелец этой карточки собирает результаты.

## Результат

Общий пользовательский сценарий проверен в нативном приложении на обеих
целевых ОС с прослушиванием, реальным вводом и существующими интеграциями.
Фактическая приёмка и оставшиеся ограничения сохранены в спецификации.

## Границы и контекст

- Это приёмка, не новая реализация. Использовать точные сборки T11/T10,
  private profile/test DB и явно выбранные тестовые MP3 CBR/VBR, Ogg/Vorbis,
  WAV. Источники osu! не изменять; не импортировать все смонтированные корни.
- Проверять каждую ОС независимо. Для Linux нужен нативный Qt desktop,
  audio output и MPRIS client; для Windows — native Qt/SMTC и audio output.
  Discord/совместимый клиент должен быть реально доступен для его проверки.
  Доступность desktop/звука/ОС не выводить из успешного compile/offscreen.
- При обнаружении дефекта зафиксировать воспроизведение и затронутую карточку;
  после исправления повторить соответствующий сценарий. Не закрывать
  недостаток среды фиктивным PASS. Публикация, установка на основной профиль,
  release/AUR и изменение чужой БД в объём не входят.

## Проверка и приёмка

На Linux и Windows пройти один полный связный сценарий:

1. Без модов услышать обычное 1×; общий DT без pitch ускоряет с сохранением
   высоты. Включить individual: треки без профиля сразу 1×, volume независим.
2. Задать A NC 1.20, B HT 0.75; переключить global/individual и перезапустить.
   Настройки сохраняются. Сложности/плейлисты с тем же аудио делят профиль;
   remove/reimport того же тестового источника восстанавливает его.
3. Играть A, выбрать/изменить B: A не меняется, B не стартует. Явно Play B:
   нужные параметры слышны с начала. Повторить старт из library/playlist/queue.
4. Менять speed и pitch на лету в обе стороны; pause/resume, seek вперёд/назад,
   смена скорости на паузе и во время drag. Место/пауза сохраняются,
   4:00 при 1.5× отображается 2:40, старый drag не перематывает новый запуск.
   Дождаться EOF/next: нет обрезанного хвоста и лишнего переключения.
5. Мышь и физические F1→D→D→D / F1→E→E, фокус/закрытие, поиск Settings,
   смена редактируемого трека и состояния Retry работают одинаково.
6. Системная панель показывает текущий A/rate и корректно ведёт position/seek,
   даже когда выбран B. Discord timestamps и paused label обновляются
   после rate change. Закрытие приложения освобождает native resources.

Записать по каждой ОС версию/toolchain/бинарник, форматы, слышимый результат,
GUI/native integration результаты и непроверенные пункты. Поток PipeWire,
фиктивный движок, спектральный тест или открытый HWND не заменяют человека,
услышавшего звук и проверившего управление. Если прослушивание/ввод недоступны
агенту, оставить эти критерии пользователю явно открытыми.

Итог перенести в `docs/specs/adjustable-pitch-speed.md`, состояния таблицы
плана и этой карточки. Полной приёмкой считать только выполненные критерии
обеих ОС; план/карточки при подготовке результата автоматически не удалять.

## Порядок работы и передача

Сверить актуальные исходники и результаты зависимостей перед изменениями.
Следовать AGENTS.md и [распределению владения](../adjustable-pitch-speed.md#владение-файлами-и-синхронизация).
Соседние исполнители могут работать параллельно: сохранять их изменения,
не менять их файлы без передачи владения. Новые символы в задании — требуемые
контракты, а не утверждение об их наличии. Не запускать другие карточки.
Перед реализацией кратко указать изменяемое поведение, риски, существующее
покрытие и минимальные дополнительные проверки. Для советов по внешним API
использовать Context7 по процедуре проекта; для чтения местного кода он не нужен.

### Как пройти (Linux)

Запуск: private profile/test DB (не основной), `target/debug/osu-radio-qt` с сервером из той же
сборки; пройти шаги 1–6 карточки на каждом из четырёх файлов, не меньше одного раза на формат.
Windows: собрать то же дерево (C++ toolchain/libclang по T10), повторить сценарий с SMTC.
После прохождения внести результаты в спецификацию («Состояние и свидетельства») и в эту таблицу.
