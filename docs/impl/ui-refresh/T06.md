# T06. Тосты и диалог подтверждения

Состояние: выполнено; вид и положение тоста в окне не проверены.
Источники: [план](../ui-refresh.md), решение 7; [предпросмотр](preview.html), переключатели «Тост 1 с» и «Подтверждение удаления».
Зависимости: T01, T03, T04 (переходы `AppModal`).

## Результат

Добавление в очередь, удаление плейлиста и очистка очереди дают видимую
обратную связь. Удаление плейлиста и «Clear all» требуют подтверждения.

## Границы и контекст

Перед началом прочитать [AGENTS.md](../../../AGENTS.md),
[docs/agent/frontend.md](../../agent/frontend.md) и разделы «Общие правила» и
«Общие проверки» [плана](../ui-refresh.md).

Сейчас тостов и диалогов подтверждения нет. Цепочка удаления плейлиста:
пункт Delete в `PlaylistPane.qml` → сигнал `deleteRequested` →
`PlaylistsPanel.qml` → `playlists.deletePlaylist(id)` → VM без подтверждения.
«Clear all»: `QueuePanel.qml` → `clearAllRequested` → `PlayerPanel.qml`
→ `queue.clearAll()`.

Сделать только в QML (VM и адаптеры не менять):

   (`Main.qml` держит единственный экземпляр), текст, без кнопок и без Undo,
   показывается 1000 мс. Появление: сдвиг вверх на 16 px и `opacity` за
   `motionBase` через `Theme.ms()`. API: `show(text)`; новый вызов перезапускает таймер.
   Задать `Accessible.role: Accessible.AlertMessage` или `StatusBar` по
   документации Qt.
2. `components/ConfirmDialog.qml` на `AppModal` (малая панель шириной около 440),
   заголовок, пояснение, кнопки Cancel (фокус по умолчанию) и красная кнопка
   действия. Добавить `AppButton` вариант `danger` (фон `Theme.red`, тёмный текст).
   Dismiss по Escape и клику вне панели закрывает без действия.
3. Подключение:
   - Delete плейлиста: диалог «Delete “<имя>”?» с текстом «The playlist and its order
     will be deleted. Tracks stay in your library.», после подтверждения
     `deletePlaylist(id)`, тост «Playlist deleted» после успеха.
   - «Clear all» очереди: диалог «Clear the whole queue?»; текст сверить с

  затемнение панели очереди закрывало бы тост от «Clear upcoming». Сдвиг 16 px и

  (Songs и элементы плейлиста), «Playlist added to queue».
- Тосты ошибок не добавлены.

**Как определяется успех (ограничения):** адаптеры не менялись, поэтому
`OperationWatcher` ждёт, что `queueBusy` (или `playlistBusy`) станет true, затем false, и
ошибки нет. В `project_queue` (`qt_view_models.rs`) `queueBusy` и `queueMessage` выставляются
отдельными уведомлениями, busy первым, поэтому вердикт откладывается на один оборот цикла
(`Qt.callLater`), иначе ошибка приходила бы после тоста. Для `playlistBusy` порядок
уведомлений не проверял; вердикт там тоже отложен, а успех определяется по id (ниже). Для очереди ошибка читается из `queueMessage` (`operation_error`, иначе
`message`). Для плейлиста `playlistMessage` нельзя считать признаком ошибки: после
успешного удаления `load_playlist` ставит «Loading playlist…», поэтому успех удаления
определяется тем, что id исчез из `bridge.playlists.playlists`. Намерение
сбрасывается через 1,5 с, если busy так и не стал true (действие отклонено до
начала, например нет соединения), чтобы позднее несвязанная операция не получила чужой тост.
Если действие вызвано, пока очередь уже занята, busy не растёт и тоста не будет; UI это
блокирует (`canInsert` учитывает `queueBusy`).

**Расхождение/решение:** для Clear all показывается тост «Queue cleared» (в решении 7
тост «при очистках», в карточке текст дан только для Clear upcoming; текст взят из предпросмотра).
