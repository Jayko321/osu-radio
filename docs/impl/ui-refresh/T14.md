# T14. Шапка открытого плейлиста

Состояние: выполнено; вид шапки и запуск звука не проверены в окне.
Источники: [план](../ui-refresh.md), решение 15; [предпросмотр](preview.html), переключатель «Шапка открытого плейлиста».
Зависимости: T01.

## Результат

В открытом плейлисте есть обложка, число треков и действия Add to queue и Play.

## Границы и контекст

Перед началом прочитать [AGENTS.md](../../../AGENTS.md),
[docs/agent/frontend.md](../../agent/frontend.md) (раздел «User playlists») и разделы
«Общие правила» и «Общие проверки» [плана](../ui-refresh.md).

Файлы: `components/PlaylistPane.qml` (общий с галереей), `qml/PlaylistsPanel.qml`,
`Gallery.qml`. Сейчас в режиме деталей (`activeId >= 0`) только стрелка назад,
название и карандаш; «Add to queue» доступен лишь из меню карточки в списке.

Адаптеры уже содержат нужные команды: `playlists.addPlaylistToQueue(id)` и
`playlists.playPlaylist()` / `playPlaylistFrom(id)`. Данные: `trackCount`,
`activePlaylistId`, список `playlists` с `artworkUrl`, `queue.queueBusy`,
`playlists.playlistBusy`.

Сделать:

1. Под строкой «стрелка, название, карандаш» шапка: обложка 72×72 (по
   `activeId` из `playlists`, заглушка как в T09), справа текст «N tracks»
   (`trackCount`, единственное число «1 track») и кнопки «Add to queue» (иконка
   `add-to-queue`) и «Play» (акцентная, иконка `play`).
2. Условия доступности: Add to queue как в меню списка (`connected`, не `busy`,
   не `queueBusy`, `trackCount > 0`); Play при `connected`, не `busy`, `trackCount > 0`.
3. Новые сигналы `PlaylistPane` (`queueRequested(id)` уже есть, добавить
   `playRequested(id)`), чтобы компонент оставался независимым от адаптера;
   `PlaylistsPanel.qml` подключает `addPlaylistToQueue` и `playPlaylist`/`playPlaylistFrom`.
   В галерее подключить мок-обработчики без падений.
4. Общую длительность не показывать (нет числовых данных).
5. Сохранить `objectName` существующих элементов; новым дать
   `playlistDetailAddQueue`, `playlistDetailPlay`.

## Проверка и приёмка

- Пробы: кнопки видны только в деталях, отключены для пустого плейлиста и при
  `busy`; Add to queue вызывает `addPlaylistToQueue(activeId)`; Play вызывает
  запуск (мок), порядок и дубликаты не меняются.
- Для реального сервера: `real_backend_playlists_use_a_disposable_database`
  (`--ignored`, Python 3) проходит.
- Ошибочный случай: плейлист с недоступными записями: Play стартует по правилам
  существующего VM (недоступные пропускаются); проверить фактическое поведение и
  записать его в отчёт.
- `lint-qml.sh` проходит.
- Не проверено без пользователя: вид шапки и запуск звука.

## Отчёт о выполнении

Выполнено только в QML.

**Изменённые файлы:** `qml/components/PlaylistPane.qml`, `qml/PlaylistsPanel.qml`,
`qml/Gallery.qml`, `tests/AdapterProbe.qml`, `docs/agent/frontend.md`.

**Что сделано:** `PlaylistPane` получил сигнал `playRequested(id)` и шапку

обложка (`requestArtwork`): восстановленные детали могут открыться без показа списка.
