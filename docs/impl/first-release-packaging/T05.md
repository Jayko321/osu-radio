# T05. Бинарный архив для Arch с системными зависимостями

Состояние: реализовано 2026-10-29; Arch build/runtime проверены, Qt-проверка частичная (см. отчёт).
Источники: [спецификация](../../specs/first-release-packaging.md), R3, R7–R9;
[план](../first-release-packaging.md), этап 3 и разделы 2, 4, 7.
Зависимости: T01 — .NET 10 publish; T02 — installed startup;
T03 — относительный helper; T04 — Linux PNG и notices.

## Результат

В чистом актуальном Arch x86_64 собраны GUI, сервер и framework-dependent
helper .NET 10. Готов отдельный бинарный архив с системной раскладкой для
`osu-radio-bin`; установка требует объявленных runtime-пакетов, но не SDK.
Ubuntu, закреплённый Qt 6.8.3 и AppImage в текущий объём не входят.

## Границы и контекст

- Адаптировать существующие [средства Linux-сборки](../../../packaging/linux/README.md),
  переиспользуя staging, runtime-check и системную раскладку
  [Arch-рецепта](../../../packaging/arch/PKGBUILD). Не создавать второй общий
  упаковочный фреймворк; обновить README/guide вместе со сменой сборочного пути.
- Собирать в чистой Arch-среде с системным Qt и .NET 10, Rust из
  [toolchain](../../../rust-toolchain.toml), SQLite/default features. Записать
  точное состояние образа/пакетов, версии инструментов, source SHA и параметры.
  Cargo.lock и feature-набор ради обхода ошибки упаковки не менять.
- GUI и сервер брать из одного выбранного SHA. Candidate из грязного checkout
  явно помечать и перечислять включённые изменения. Финальную сборку из чистого
  SHA вместе с Windows повторяет T09; текущая карточка не разрешает commit/tag/push.
- Сохранить `usr/bin/osu-radio-qt`, прежнюю команду `osu-radio`, сервер рядом,
  `usr/lib/osu-radio/` с полным framework-dependent publish, desktop entry,
  hicolor PNG и лицензии. Helper ищется относительно executable по T03.
- Qt и .NET runtime предоставляются системными пакетами Arch. Установить
  фактические native/runtime зависимости GUI/server/Realm и передать их T07.
  Не заявлять запуск на Ubuntu или других дистрибутивах по результатам Arch.
- Сверить [notices](../../../packaging/arch/licenses/README.md) с фактическими
  Rust/helper/assets. Сохранить полные нужные тексты и hashes; системный Qt
  не описывать как упакованный. Windows-поставка проверяется отдельно в T08.
- Сохранить отчёт прежней Ubuntu-пробы ниже как историю. Его hashes, минимальная
  glibc и результаты не переносятся на новую сборку. Старые Qt 6.8.3-падения
  не считаются исправленными; проверить завершение на целевом Qt Arch.

## Проверка и приёмка

1. Собрать GUI/server и helper в чистой Arch-среде с отдельными кэшами/target.
   Базовая команда: `cargo build --release --locked -p osu-radio-qt -p osu-radio-server`.
   Сверить зависимости ELF/native Realm, состав архива и отсутствие зависимости
   runtime-поиска от build tree.
2. Установить раскладку в отдельную Arch runtime-среду с объявленными пакетами,
   без Rust/C++/.NET SDK, исходников и build tree. Из другого cwd запустить
   GUI/server и прочитать синтетический Realm через установленный helper;
   проверить неизменность входа. Отсутствующий runtime должен давать явную
   ошибку, без подхвата библиотек из сборочной среды.
3. Выполнить применимые Qt tests/probes, generated-import QML lint и scoped
   Clippy по [матрице](../../agent/development.md#verification-matrix) на системном
   Qt Arch. Не повторять неизменные проверки T01–T04. Изменённые ветви packaging
   проверить существующим self-check состава/ошибки входа; новый каркас не нужен.
4. Записать hashes/размер архива, бинарников и версии системных зависимостей.
   Передать T07 этот архив для проверки реального `-bin`; package install,
   конфликты и смена вариантов — T07, полный import/audio/lifecycle — T10.
   Offscreen smoke не заменяет нативную пользовательскую приёмку.

## Отчёт о выполнении актуальной карточки

Дата: 2026-10-29. Arch-кандидат собран; установленная раскладка проверена
в отдельном runtime-root. Qt-проба обложек воспроизводимо падает; остальные
выполненные проверки перечислены ниже.
Пользовательская приёмка этим отчётом не отмечается.

**Реализация.** `packaging/linux/build.sh` использует системные Qt и .NET 10
в подготовленном Arch root, Rust из toolchain, приватные кэши/target и прежние
SQLite/default features. Добавлен `enter-arch.sh`; `stage-archive.sh` сохраняет
системную раскладку, проверяет полноту FDD publish и соответствие helper inventory.
`runtime-check.sh` проверяет установленный комплект от обычного пользователя.
Обновлены обе Linux README, `docs/agent/development.md`, helper inventory/notices
и описание лицензий. Старые `pins.env`/`enter-ubuntu.sh` помечены/описаны как история.
Исходники продукта, Cargo.lock и features этой работой не изменялись.

**Источник.** Изолированный снимок грязного checkout на
`c9f2500bad0c645d4e5e2db5dcdd9f6b712ac551`, tracked diff SHA-256
`fbd332868c4e680aa9aa358b41d33e1be21cbfb864d395ec6eca92fcb31eec58`.
Состав, включая имеющиеся изменения поиска/БД, startup/helper и упаковки,

они не подменяют source commit/manifest уже собранных бинарников.
Это кандидат, не релиз; чистый общий SHA Windows/Arch повторяет T09.

**Среда.** Два новых Arch x86_64 rootfs созданы через `pacstrap -N` с проверкой

Rust/Cargo 1.98.0; Qt 6.12.0 (`qt6-base`/`qt6-declarative` `6.12.0-3`, svg/wayland
`6.12.0-1`); .NET SDK 10.0.113, runtime/apphost 10.0.13; gcc 16.2.1,

`target/arch-first-release-t05/` (локальные ignored-артефакты).
Первый bootstrap без `pacstrap -N` не смог смонтировать sysfs; штатный rootless
режим сработал. Первая загрузка crates.io завершилась timeout; 68 недостающих
