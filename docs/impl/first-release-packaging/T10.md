# T10. Итоговая приёмка установленных комплектов

Состояние: частичная независимая проверка 2026-10-29; итоговая приёмка заблокирована отсутствием окончательного комплекта T09.
Источники: [спецификация](../../specs/first-release-packaging.md), R1–R9;
[план](../first-release-packaging.md), разделы 2, 4, 6–7.
Зависимости: T09 — окончательный согласованный комплект, manifest, hashes,
проверенный tag/archive и инструкции. Отчёты T01–T05/T07/T08 переиспользуются
по их границам; Arch-кандидат T05 уже проверен с ограничением Qt-прогона,
описанным в её отчёте. T06 отложена.

## Результат

Общий пользовательский сценарий проверен на тех же готовых артефактах,
которые входят в комплект. По каждому R1–R9 в спецификации записаны место
реализации, фактическая проверка/результат и оставшиеся ограничения;
R2 отмечается исключённым, R4 — отложенным, без требования их выполнить. Реализация,
автоматизированная проверка и пользовательская приёмка отмечаются отдельно.

## Границы и контекст

- Подготовить чистые профили/VM: Windows 10 22H2 и LTSC 2021, Windows 11;
  актуальный Arch x86_64. Записать точные builds/пакеты и доступные Arch
  X11/Wayland desktop-сессии. Оба Arch-варианта проверяются в Arch, Setup —
  на всех согласованных Windows. Ubuntu и AppImage в матрицу не входят.
- Нужны тестовые stable и настоящая lazer-библиотека с доступными треками,
  native GUI и реальный аудиовыход. Изолировать БД/QSettings от рабочего профиля,
  сохранять исходные файлы osu! read-only. Discovery — только явно выбранные
  тестовые корни, без обхода всех дисков. Fixtures/fake engine/offscreen
  не подтверждают реальный Realm/физический звук.
- За основу регрессий брать отчёты предшественников, [verification matrix](../../agent/development.md#verification-matrix),
  [startup tests](../../../apps/osu-radio-server/tests/startup.rs),
  [embedded-server integration](../../../crates/osu-radio-client/tests/embedded_server.rs),
  [migration lifecycle fixtures](../../../crates/radio-db/src/tests/migration_lifecycle.rs)
  и [DB policy](../../agent/database.md). Миграции и параллельная доработка
  поиска могут измениться до финального SHA; сверить актуальные fixtures.
  Новую миграцию или arbitrary schema downgrade для упаковки не добавлять.
- Существенные дефекты исправлять в соответствующем владельце, затем пересобрать
  затронутые артефакты и повторить связанные критерии. Изменение исходного SHA
  требует обновлённого согласованного комплекта T09; нельзя смешивать результаты
  разных сборок в одной строке приёмки.

## Проверка и приёмка

1. Проверить hashes входов по T09. Установить/запустить каждый формат обычным
   пользователем без `.env`, app env overrides, исходников и build tree.
   Windows — без заранее установленных Qt/.NET/SDK; Arch `-bin` — без SDK, с объявленными
   runtime. Setup отдельно проверить per-user и all-users.
2. Для каждого установленного варианта отдельно пройти: запуск → добавить stable
   текущим UI → import → явный Play → слышимый звук; повторить для lazer.
   Проверить путь с пробелами/кириллицей, запуск из чужого cwd, отсутствие
   неожиданных консольных окон Windows, сохранность исходников и очистку временного
   аудио. Проверить реальное завершение принадлежащих приложению child processes:
   для Close учитывать действующий close-to-tray, затем выполнить полный выход.
3. Сохранить библиотеку, пользовательский плейлист и несколько существующих
   настроек. Проверить restart, update, reinstall, uninstall/reinstall;
   на Arch — ещё смену вариантов с совместимой схемой. Если новая версия
   runtime не имеет прежнего установщика для update, подготовить отдельный
   предыдущий candidate с тем же AppId/пакетной идентичностью, не объявлять
   простую повторную установку проверкой обновления. Архивные и пользовательские
   данные не удалять. На Linux подтвердить прежние XDG overrides; на Windows
   данные в LOCALAPPDATA, Qt keys/location сохранены.
4. На частной БД проверить существующие migration fixtures и запуск с
   несовместимой схемой: явный отказ без удаления/замены БД и без reset.
   Подтвердить, что package hooks/uninstall также не выполняют reset.
   Переиспользовать `cargo test -p radio-db --locked` для SQLite contracts;
   backend features и socket runners выбирать по guide. Уже прошедшие
   неизменные проверки предшественников не запускать заново без причины.
5. Windows: обе установки, menu/uninstall entries, update. Arch: команды,
   конфликты, иконки и доступные X11/Wayland-сессии. Во всех форматах проверить
   иконки R9, версии GUI/About/server/release и доступные notices/instructions.
6. Заполнить таблицу R1–R9 исходной спецификации фактическими свидетельствами
   по актуальной матрице Windows 10 22H2/LTSC 2021/11 и Arch; R2/R4 не
   отмечать выполненными. Сверить выбранный перенос `v0.1.0-alpha`. Отметить фактический статус
   переноса/публикации отдельно: приёмка не разрешает автоматически публиковать.
   Обновить затронутые agent guides, проверить локальные ссылки.
7. Если часть сред недоступна, перечислить точные непроверенные ячейки и оставить
   соответствующие требования/итоговую приёмку незавершёнными. Несовместимость
   согласованных ОС/Realm вернуть в `$impl-plan`, не исключать их из матрицы.

### Выполненные проверки

Среда новой проверки: хост Arch x86_64, kernel `7.2.11-arch1-1`,
`glibc 2.44+r50+g1848099f063e-1`, `qt6-base`/`qt6-declarative 6.12.0-3`,
`dotnet-runtime`/`dotnet-sdk 10.0.13.sdk113-1`. В окружении указаны
`XDG_SESSION_TYPE=wayland`, `WAYLAND_DISPLAY=wayland-1`, `DISPLAY=:0`.
Это рабочий хост с SDK, не чистая установленная desktop-проверка;
наличие DISPLAY не доказывает отдельную X11-сессию или физический звук.

- `cargo test -p radio-db --locked` — **11 passed**, 0 failed/ignored;
  doc-tests — 0. Это текущий dirty checkout, отдельно от упакованного сервера.
  Использованы существующие временные SQLite-фикстуры: историческая схема,
  сохранность данных при миграциях, v16→v17 с 257 строками и rollback при
  ошибке backfill, 20 циклов конкурентных migration/reset через независимые
  pools. Новые миграции, тесты или инфраструктура не добавлялись.
  Лог: `/tmp/osu-radio-t10-radio-db.log`.
- Одноразовая `python3` assert-проверка извлекла только server из указанного
  Arch-архива в частный временный путь с пробелами/кириллицей. SHA-256 executable
  сверён: `0002acc122a6c99d0ac942ce209e30df1bd806bc180109c5eef5f08ad598f3bf`.
  Созданы два SQLite-входа: legacy `beatmap_sets` без истории и история с
  неизвестной `m20990101_000001_future`; оба содержали контрольные данные и
  постороннюю таблицу. Для каждого выполнено два запуска из `/tmp` с очищенным
  окружением и явными тестовыми `SQLITE_DATABASE_URL`, `OSU_RADIO_SKIP_DOTENV=1`,
  `OSU_RADIO_SERVER_ADDRESS=127.0.0.1:0`. Все **4 проверки passed**: exit 1,

  Лог: `/tmp/osu-radio-t10-incompatible-db.log`; временные БД/executable удалены.
  Это проверка отказа candidate-сервера с явным URL, не default-path/UI приёмка.
