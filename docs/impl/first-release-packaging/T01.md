# T01. Helper и Realm-фикстуры на .NET 10

Состояние: реализовано; Linux проверен, нативная Windows-проверка не выполнена.
Источники: [спецификация](../../specs/first-release-packaging.md), R8 и runtime-часть R7;
[план](../first-release-packaging.md), разделы 2–4 и 7.
Зависимости: нет.

## Результат

Production helper и генератор настоящих синтетических Realm-файлов используют
.NET 10 и прежний Realm `20.1.0`. Framework-dependent и self-contained
публикации каталогом проверены нативно на Linux x64 и Windows x64; NDJSON,
ошибки и read-only доступ к входным файлам сохраняются.

  замена проверок этой карточки и не pin финальной версии runtime.

## Проверка и приёмка

1. С .NET 10 SDK выполнить из корня:

   ```sh
   python3 -B -m unittest discover -s crates/radio-scanner/tests -p 'test_*.py' -v
   dotnet build tools/osu-lazer-realm-parser/osu-lazer-realm-parser.csproj --configuration Release --nologo
   cargo test -p radio-scanner --locked -- real_ --test-threads=1
   ```

   Python fake-dotnet проверки POSIX-only; их пропуск на Windows не считать
   проверкой Windows build script. Rust real-helper тесты должны реально
   запустить production helper и генератор.
2. Нативно опубликовать оба режима для `linux-x64` и `win-x64` в отдельные
   временные каталоги. Выполнить real-helper набор с абсолютным build-time
   `OSU_LAZER_REALM_PARSER_PATH`, указывающим на соответствующий publish apphost;
   разделить Cargo outputs либо обеспечить пересборку env-зависимого build.rs.
   Для self-contained проверить прямой запуск без доступного системного .NET
   runtime; framework-dependent проверить с .NET 10 runtime. Генерация фикстур
   остаётся в среде SDK, а runtime-проба использует готовые файлы.
3. Ожидаются прежние beatmap/collection/schema записи, ошибки повреждённого
   Realm и некорректных аргументов в stderr, неизменные входные байты и отсутствие
   созданного аудио. Точные SDK/runtime/native Realm и ОС записать в отчёт.
4. Выполнить scoped Clippy scanner и форматирование по матрице проекта.
   Новые тесты нужны лишь для обнаруженного нового риска; существующую матрицу
   протокола не дублировать. Нативный Windows результат нельзя заменить
   cross-publish на Linux. Несовместимость блокирует R8 и требует `$impl-plan`.

## Отчёт о выполнении

Дата: 2026-10-27. Пользователь подтвердил отсутствие Windows VM/хоста;
доступная работа выполнена без подготовки VM. Пользовательская приёмка не отмечена.

Изменены оба `.csproj` (`net10.0`, Realm остаётся `20.1.0`), диагностика
`crates/radio-scanner/build.rs` и её существующий Python-тест, оба SDK setup
в `.github/workflows/linux-ci.yml` (`10.0.x`), helper README и guides
`docs/agent/scanner.md`/`development.md`. Синхронизированы фактическое состояние
R8 в спецификации и строка T01 в общем плане. Протокол, C# extraction-код,
поиск helper, build-time override и Arch-рецепты не менялись.

Среда: Arch Linux rolling x86_64, kernel `7.2.11-arch1-1`, glibc `2.44`;
.NET SDK `10.0.113`, MSBuild `18.0.36`, установленный runtime
`Microsoft.NETCore.App 10.0.13`. Self-contained каталоги включают runtime
`10.0.13`; framework-dependent требуют `10.0.0` с обычным patch roll-forward
(на Linux выполнялись с `10.0.13`). Это версии данной проверки, не pin релиза.
Realm NuGet `20.1.0`, native Core `20.1.2` по release notes пакета.
SHA-256 native Realm, одинаковый для обоих режимов соответствующего RID:

- Linux `librealm-wrappers.so`: `982e9febba48cf95bdbfd55dad4c1dc11d621e76087fd07f3cb84488eb7df9de`.
- Windows `realm-wrappers.dll`: `bd3afcac36f4875593c92930f676604d4d15294e4f596cb92df44bf322e4d1ab`.
