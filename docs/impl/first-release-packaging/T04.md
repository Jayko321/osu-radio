# T04. Пакетные иконки из существующего lazer-лого

Состояние: реализовано и проверено декодированием; отображение в оболочках не проверялось.
Источники: [спецификация](../../specs/first-release-packaging.md), R9;
[план](../first-release-packaging.md), этап 6 и раздел 7.
Зависимости: нет.

## Результат

Готовы ICO для Windows и PNG для Linux-пакетов из существующего изображения
lazer. Пути, размеры и происхождение определены для упаковщиков; нового дизайна
и новых условий лицензирования не появляется.

## Границы и контекст

- Источник — [lazer.png](../../../apps/osu-radio-qt/assets/logos/lazer.png).
  Оригинал сохранить, новые форматы разместить в подходящем общем каталоге
  `packaging/`, указав фактические пути в отчёте. Упаковочных файлов там пока нет,
  кроме существующего `packaging/arch/`.
- Использовать сведения [SOURCES.md](../../../apps/osu-radio-qt/assets/SOURCES.md)
  и [licenses README](../../../packaging/arch/licenses/README.md): разрешение
  maintainer на распространение не означает отдельную image-license или MIT
  для лого. Добавить сведения о производных форматах и воспроизводимый способ
  конвертации, не придумывать разрешение правообладателя.
- Формат ICO должен содержать пригодные для Windows shell размеры, Linux PNG —
  пригодные для Arch desktop entry размеры без выдуманного повышения качества.
  Точные представления выбрать по свойствам существующего исходника.
- Здесь подготовить сами assets и provenance. Встраивание в EXE/Setup выполняет
  T08; Arch desktop entry и hicolor — T05/T07. QML и UI не переделывать,
  зависимости приложения ради конвертации не добавлять.

## Проверка и приёмка

1. Проверить фактическое декодирование PNG и каждого ICO frame, размеры,
   прозрачность и визуальное соответствие исходному лого. Одного расширения
   файла недостаточно. Зафиксировать инструмент и команду конвертации.
2. Проверить неизменность исходного PNG и сохранность ссылок на provenance/notices.
   Для механической конвертации новый тестовый каркас не нужен; если добавлен
   нетривиальный скрипт, оставить минимальную проверку его результата.
3. Проверку отображения в меню/списке программ не засчитывать по файлам:
   это приёмка готовых комплектов T07/T08 и T10.

Уточнение 2026-10-29: AppImage отложен; прежний отчёт ниже сохраняется,
но отображение AppImage больше не входит в приёмку первого релиза.

## Отчёт о выполнении

Выполнено 2026-10-27.

- Новые файлы: `packaging/icons/osu-radio.ico` (кадры 16, 24, 32, 48, 64, 128 —
  32-bit BMP, 256 — PNG); `packaging/icons/hicolor/{16,24,32,48,64,128,256,512}x…/apps/osu-radio.png`
  (раскладка hicolor, ставится как есть); `packaging/icons/generate.py`;
  `packaging/icons/README.md` (происхождение и команда).
- Конвертация: Pillow 13.0.0 в временном venv, Lanczos с premultiplied alpha,
  `python packaging/icons/generate.py`. Исходник 1024×1024, поэтому максимум —
  512 px; повышения разрешения нет. Внешних зависимостей проекта не добавлено.
- Проверка: каждый PNG и каждый кадр ICO декодированы Pillow (ICO-ридер независим
  от моего писателя), размеры совпали, альфа 0..255, угол прозрачен, кадры ICO
  побайтно по пикселям равны прямому даунскейлу исходника (mean diff 0);
  `file` распознаёт ICO как «7 icons». Визуально сверен контактный лист: розовое
  «osu!» на прозрачном фоне, читается уже с 16 px. `lazer.png` не менялся
  (SHA-256 `c1859767…daae`, `git status` чист).
- Provenance: добавлено в `apps/osu-radio-qt/assets/SOURCES.md` и
  `packaging/arch/licenses/README.md`; новое разрешение не выдумывалось, статус
  производных тот же, что у `lazer.png`.
- Не проверено: показ в Windows shell/меню/списке программ, desktop entry и
  AppImage (T06–T08, T10); рендер ICO самой Windows (проверен только Pillow).
  Встраивание в EXE/Setup и `Icon=` в desktop entry не делались.
