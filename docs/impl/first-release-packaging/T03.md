# T03. Helper находится после установки и переноса комплекта

Состояние: реализовано на Linux; Windows-проверка и установленный комплект ожидают.
Источники: [спецификация](../../specs/first-release-packaging.md), R5, установленная часть R8;
[план](../first-release-packaging.md), «Запуск, пути и данные», разделы 4 и 7.
Зависимости: T01 — .NET 10 build/publish и сохранённые real-helper проверки.

## Результат

Scanner ищет helper в согласованном порядке: runtime
`OSU_LAZER_REALM_PARSER_PATH` → установленный путь относительно текущего backend/CLI
executable → прежний build-time helper. Пакетный путь относительный и разрешается
от executable, без зависимости от cwd или машины сборки. Ошибочный явный runtime
override даёт ошибку, не скрытую другим helper.

## Границы и контекст

- Точка выбора — `import_snapshot_from_lazer_realm` в
  [scanner.rs](../../../crates/radio-scanner/src/lazer/scanner.rs), сейчас runtime
  env либо `BUILT_HELPER_PATH`. Переиспользовать общий путь для set-only API;
  явные `*_with_helper` сохраняют переданный вызывающим кодом путь.
- Проверить dispatch `import_snapshot` и `import_snapshot_with_helper` в
  [lib.rs](../../../crates/radio-scanner/src/lib.rs) и exports
  [lazer/mod.rs](../../../crates/radio-scanner/src/lazer/mod.rs).
  Публичные интерфейсы, NDJSON и принадлежность source I/O не менять.
- [build.rs](../../../crates/radio-scanner/build.rs) должен поддерживать
  согласованный пакетный относительный путь и абсолютный dev fallback.
  Linux layout: `../lib/osu-radio/osu-lazer-realm-parser`; Windows:
  `helper/osu-lazer-realm-parser.exe`. Конкретный способ передачи пути при сборке
  — локальная деталь; записать фактический контракт для T05/T07/T08.
  Не подменять runtime override изменением глобального cwd.
- Windows запуск `Command` для helper не создаёт консоль, stdout/stderr остаются
  pipes. Сохранить terminate/kill-on-drop, обработку ошибок и read-only импорт.
- Расширить [build-script tests](../../../crates/radio-scanner/tests/test_build_helper.py)
  и нужные [lazer tests](../../../crates/radio-scanner/src/lazer/tests.rs).
  Обновить [scanner](../../agent/scanner.md), [development](../../agent/development.md)
  и [helper README](../../../tools/osu-lazer-realm-parser/README.md);
  следовать процедуре `osu-radio-scanner`.

## Проверка и приёмка

1. Проверить наблюдаемый выбор через изолированный process probe с отличимыми
   helper-ответами: override выше установленного; отсутствующий установленный
   использует dev fallback; неверный/пустой runtime override не переходит
   к рабочему установленному/dev helper; явный `*_with_helper` остаётся явным.
   Окружение задавать только дочернему процессу, не мутировать общее env тестов.
2. Во временной раскладке Windows/Linux переместить весь комплект в путь
   с пробелами/кириллицей и запустить из другого cwd. Сделать исходный build-time
   helper недоступным. Должен реально запуститься установленный helper и
   прочитать Realm-фикстуру; удаление установленного helper должно дать понятную
   ошибку, если dev fallback также недоступен.
3. Выполнить на подходящей ОС:

   ```sh
   python3 -B -m unittest discover -s crates/radio-scanner/tests -p 'test_*.py' -v
   cargo test -p radio-scanner --locked lazer::
   cargo test -p radio-scanner --locked -- real_ --test-threads=1
   cargo test -p osu-radio-cli --locked
   ```

   Учесть POSIX-only fake helper и build tests; для Windows нужен нативный
   portable probe/production helper, а не зачёт пропущенного Unix теста.
4. Scoped Clippy и форматирование по матрице проекта. Подтвердить на Windows
   отсутствие консоли helper с сохранением NDJSON/errors. Реальные библиотеки
   и установленный GUI проверяются в T10, не заявлять их проверенными здесь.

## Отчёт о выполнении

**Файлы:** `crates/radio-scanner/src/lazer/scanner.rs` (`select_helper`,
`INSTALLED_HELPER_PATH`, `CREATE_NO_WINDOW` на Windows), `lazer/tests.rs`; документация
`docs/agent/scanner.md`, `docs/agent/development.md`, `tools/osu-lazer-realm-parser/README.md`.

**Контракт пути (для T05/T07/T08):** `build.rs` не менялся и по-прежнему задаёт только
абсолютный dev fallback. Установленный путь — константа в коде, относительно каталога
`current_exe()`: Linux `../lib/osu-radio/osu-lazer-realm-parser`, Windows
`helper/osu-lazer-realm-parser.exe`. Достаточно разместить helper по этой раскладке; флагов
сборки нет. Пустой runtime override — явная ошибка; несуществующий — ошибка запуска.

**Проверки (Arch Linux x64, 2026-10-27):**
- `python3 -B -m unittest discover -s crates/radio-scanner/tests` — 5 passed.
- `cargo test -p radio-scanner --locked lazer::` — 24 passed, включая
  `helper_selection_order_…` (override → installed → built, отсутствующий/пустой override)
  и `relocated_executable_…`: копия test-бинарника в `Приложение osu radio/bin`, fake helper
  в `lib/osu-radio`, другой cwd, `env_clear`; installed используется, явный override выше,
  отсутствующий и пустой override дают ошибку при рабочем installed.
- `cargo test -p radio-scanner --locked -- real_ --test-threads=1` — 5 passed;
  `cargo test -p osu-radio-cli --locked` — зелёный; `cargo clippy -p radio-scanner --all-targets -- -D warnings` — чисто.
- Ручно: копия `osu-radio-cli` в каталог с кириллицей/пробелами, запуск из `/`, build-time helper
  с `chmod 000` → понятная ошибка запуска с путём build-time helper и `Permission denied`.
- `cargo check -p radio-scanner --target x86_64-pc-windows-msvc` — компилируется (включая `creation_flags`).

**Не проверено:** выполнение на Windows (раскладка `helper/…exe`, отсутствие консоли, NDJSON/ошибки);
pipe-захват с `CREATE_NO_WINDOW` только по типам. Process probe использует POSIX fake helper и
переносит test-бинарник, а не CLI/сервер; при отсутствии и installed, и build-time helper сообщение
называет только build-time путь. Реальные библиотеки и установленный GUI — T10.
