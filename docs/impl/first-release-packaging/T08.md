# T08. Windows Setup с полным runtime-комплектом

Состояние: Windows candidate собран в GitHub Actions и частично проверен в Wine; релизная лицензионная сверка и полная приёмка не выполнены.
Источники: [спецификация](../../specs/first-release-packaging.md), R1, Windows-части R5–R9;
[план](../first-release-packaging.md), этап 5, разделы 2, 4 и 7.
Зависимости: T01 — .NET 10/Realm native publish; T02 — Windows config/child startup;
T03 — relative helper/console behavior; T04 — ICO и provenance.

Уточнение 2026-10-29: Windows — основная пользовательская платформа. Карточка
не зависит от T05/T07 и может выполняться первой после T01–T04. Непроверенные
нативные Windows-критерии T01–T03 проверить в рамках подготовки комплекта;
Linux/cross-publish результаты не заменяют их. Объём Setup и Windows-матрица сохранены.

Последующее уточнение пользователя 2026-10-29: Wine достаточно для проверки
настоящего установщика в T08. Тест с пустыми файлами ему не соответствует.
Результат Wine и отсутствие нативной Windows-проверки указываются отдельно;
требования к составу и сценарию установки остаются в силе.

## Результат

Нативно собранный MSVC x64 Setup.exe доставляет GUI/server, динамический Qt,
self-contained helper .NET 10 и необходимые разрешённые MSVC runtime DLL.
Установка не скачивает runtime; текущий пользователь — default, доступна
установка для всех с повышением прав. Update/uninstall сохраняют данные.

## Границы и контекст

- Добавить Windows staging/build и Inno Setup script в `packaging/` (новые
  файлы). Закрепить фактические версии/источники инструментов, Qt, .NET и
  runtime до сборки; сохранить их для CI T09. Собирать выбранный SHA, версию
  `0.1.0-alpha`, Qt и сервер вместе с SQLite/default features.
- GUI и сервер рядом; полный `win-x64` self-contained helper —
  `helper/osu-lazer-realm-parser.exe` с зависимостями. Вызвать
  `windeployqt --qmldir` с [исходным QML](../../../apps/osu-radio-qt/qml/Main.qml)
  и проверить дополнительный native/runtime состав server/Realm отдельно.
  Не полагаться на PATH и Qt/.NET SDK хоста сборки.
- GUI subsystem и Windows EXE icon реализуются в существующих
  [main.rs](../../../apps/osu-radio-qt/src/main.rs)/[build.rs](../../../apps/osu-radio-qt/build.rs)
  и при необходимости [manifest](../../../apps/osu-radio-qt/Cargo.toml).
  Использовать существующий build context/платформенные средства без новой
  зависимости ради нескольких строк. Subprocess pipes/NDJSON/readiness
  сохраняют T02/T03; backend/helper не превращать в GUI-приложения ценой stdout.
- Inno Setup: постоянный AppId для последующих обновлений, default per-user,
  выбор all-users с elevation, меню «Пуск», uninstall entry и ICO в EXE/Setup,
  меню/списке программ. Разрешённые MSVC DLL локальны также для helper.
  Удалять только установленные файлы приложения; не LOCALAPPDATA/QSettings.
- Переиспользовать notices/provenance; сформировать соответствующий Windows
  inventory, полные Qt/.NET/native/MSVC license materials и Qt sources/patches
  со сведениями о замене динамических библиотек. Обновить инструкции установки,
  update/uninstall и затронутые [frontend](../../agent/frontend.md)/
  [development](../../agent/development.md) guides. Не менять схему/ключи настроек.
- Если Windows compilation выявляет необходимость архитектурных изменений,
  вернуть вопрос в `$impl-plan`; не отключать функцию приложения для сборки.

## Проверка и приёмка

1. Нативная MSVC x64 build/staging, проверка imports/DLL/plugin состава,
   Qt tests/probes и scoped Clippy по применимой матрице проекта. Для нового
   staging/script оставить минимальную проверку отсутствующих обязательных
   файлов; не добавлять отдельный большой test framework.
2. В чистом Windows-профиле без Qt/.NET/SDK и runtime в PATH выполнить per-user
   установку без admin, затем отдельно all-users с elevation. Сеть отключить
   на этапе install/start: никакого runtime download. Проверить GUI/server/helper
   после удаления build tree, из произвольного cwd и пути с пробелами/кириллицей.
3. Запуск через меню не открывает лишнюю консоль; server readiness и helper
   errors продолжают обрабатываться. Проверить EXE/Setup/menu/uninstall иконки.
4. Создать библиотеку/плейлист/настройки в отдельном профиле, установить обновлённый
   candidate с тем же AppId, повторно установить и удалить через Windows.
   После reinstall данные сохранены, application files заменены/удалены штатно.
   Не объявлять update проверенным только по совпадению AppId.
5. В этой карточке нужен хотя бы один настоящий installed прогон через Wine;
   T10 проверяет Windows 10 22H2, LTSC 2021 и Windows 11, настоящий stable/lazer
   и звук. Пропуски фиксировать, требования не сужать при несовместимости .NET 10.

## Отчёт о выполнении

Частичная работа 2026-10-29, Linux x86_64. HEAD
`c9f2500bad0c645d4e5e2db5dcdd9f6b712ac551`; дерево содержит незакоммиченные
изменения, поэтому это не выбранный релизный SHA и не исходник релизного Setup.

- [Inno script](../../../packaging/windows/osu-radio.iss) — заготовка с постоянным
  AppId `osu-radio-desktop`, default per-user, выбором all-users, меню и setup icon.
  Он проверяет наличие нескольких ключевых файлов, но не проверяет полноту DLL,
  лицензий и provenance; **не использовать для выпуска** до завершения staging.
- [main.rs](../../../apps/osu-radio-qt/src/main.rs),
  [build.rs](../../../apps/osu-radio-qt/build.rs) и
  [windows.rc](../../../apps/osu-radio-qt/src/windows.rc): GUI subsystem и ресурс ICO
  для Windows GUI; сборка ожидает `rc.exe` из Windows SDK. Сервер/helper не менялись.
- Inno Setup 6.7.3 под Wine с отдельным временным профилем: скрипт компилирует
  установщик из фиктивных пустых файлов; пустой каталог и тот же набор без
  `platforms/qwindows.dll` отклоняются. Фиктивный Setup не является артефактом
  приложения и не проверял установку. `llvm-rc` собрал ресурс ICO, `llvm-readobj`
  показал группу с семью иконками; связывание через MSVC не проверено.
- `cargo check --locked -p osu-radio-qt`, `cargo clippy --locked -p osu-radio-qt
  --all-targets -- -D warnings` и `cargo fmt --all -- --check` прошли на Linux.
  Они не проверяют Windows-ветку.
- Context7 вернул месячную квоту; синтаксис сверялся с официальными страницами
  [Inno Setup](https://jrsoftware.org/ishelp/topic_setup_privilegesrequiredoverridesallowed.htm),
  [Qt 6.8](https://doc.qt.io/qt-6.8/windows-deployment.html) и
  [Microsoft](https://learn.microsoft.com/cpp/windows/redistributing-visual-cpp-files).
  Для Context7 доступны `npx ctx7@latest login` или `CONTEXT7_API_KEY`.

Дополнение: [build.py](../../../packaging/windows/build.py) готовит candidate
в Windows MSVC-среде: публикует helper, собирает приложения, запускает
`windeployqt`, копирует DLL и переданные license materials, проверяет ключевые
файлы и запускает Inno. До сборки проверяет заданные версии инструментов и hash
ISCC, записывает tool/source summary и payload hashes; выбор и подтверждение
источников pins, проверка imports и аудит лицензий ещё нужны. Есть
[инструкция](../../../packaging/windows/README.md). `python3 -B -m unittest
discover -s packaging/windows -p 'test_*.py' -v` прошёл проверки отказа при
отсутствующем или пустом файле и несовпадении версии Qt. Скрипт не запускался в MSVC/Qt и не является
подтверждением сборки Setup.

Реальный self-contained helper T01 для win-x64 запущен под Wine 11.20 на копии
`full.realm`: exit 0, одна запись набора и две коллекции в NDJSON; SHA-256 копии
до и после `346a8c8456a7488d93fef624fae6d7c44e5795f87f297a027b723eb9c13ab080`.
Запуск без аргументов вернул exit 2 и usage на stderr. Это отдельная проверка
helper, а не установленного приложения.

Не выполнено: MSVC build/staging, pins и source inventory, состав и
лицензии Qt/.NET/Realm/MSVC, Qt sources/patches, фактический Setup/hash и проверка
imports. Не проверены T01–T03 на Windows, GUI subsystem/иконки, локальный runtime,
обе установки, запуск, update/reinstall/uninstall и сохранность данных. Windows
host/VM не обязателен для проверки T08 по уточнению пользователя, но нативная
Windows-совместимость остаётся непроверенной. Wine-прогон настоящего установленного
приложения ещё нужен; прежний cross-publish его не заменяет. T09 зависит от T08.

### GitHub candidate и Wine, 2026-10-29

С разрешения пользователя опубликована отдельная ветка
[`ci/t08-windows-candidate`](https://github.com/Jayko321/osu-radio/tree/ci/t08-windows-candidate),
без изменения `main` и release tag. Финальная для этой проверки сборка:
[Actions 40896160598](https://github.com/Jayko321/osu-radio/actions/runs/40896160598),
commit `1d912e71bc33d7c754c375f0805f60e6bdeb841c`, Windows Server 2022 x64,
MSVC `14.44.35207`, Windows SDK `10.0.26100.0`, Rust `1.98.0`, Qt `6.8.3`,
.NET SDK `10.0.113`, Inno Setup `6.7.3`. Первые два запуска выявили и помогли
исправить выбор SDK и регистр переменных MSVC в Python. `BUILD-INFO.txt`
зафиксировал один untracked файл `aqtinstall.log`; это candidate, не чистый
финальный release SHA. Ветка включает ранее локальный commit `c9f2500` и
отобранные изменения T01–T04/T08; незакоммиченные поиск/БД не включены.

Скачанный artifact `windows-installer-candidate-not-for-release` SHA-256
`dab09df986b8b97d9b962c15e20f6c5210a6f2ea47c5373a1a73e937233517f4` совпал с
GitHub digest. Setup SHA-256
`4b9a4cdd4224269a0681b78346063a42445186eb09f47d99ae1358f59f867fc5` сохранён в
`target/first-release-t08/downloaded/output/` (локальный ignored каталог).

В отдельном Wine 11.20 prefix per-user silent Setup установился в путь с
пробелами; все 1612 файлов совпали с `payload.sha256`. Из `/tmp` установленный
helper прочитал тестовую Realm с 2 beatmaps и 2 collections. Установленный Qt
запустил свой server, создал SQLite в профиле и вернул пустую библиотеку по HTTP.
Тестовый плейлист, созданный через HTTP, сохранился после повторной установки,
uninstall и новой установки: SQLite integrity `ok`, переустановленное приложение
вернуло плейлист через HTTP. Uninstall удалил исполняемый файл GUI. Процессы
тестового prefix завершались принудительно, поэтому обычное закрытие не проверено.
Wine выводит `Windows SMTC: 0x80004002`; системные медиакнопки не подтверждены.

Это диагностический, не распространяемый комплект: Windows-specific licenses,
исходники/patches Qt и разрешённость MSVC DLL ещё не сверены; в составе оставлен
предупреждающий файл. Не проверены all-users/elevation, реальный стабильный или
lazer import из UI, воспроизведение, реальное обновление другой версии, иконки в
shell, native Windows и полный T10. `README` и прежние сообщения об отсутствии
настоящего Setup относятся к состоянию до этого запуска.
