# T02. Пользовательские данные и запуск сервера на Windows

Состояние: реализовано, проверено на Linux; нативная Windows-проверка не выполнена.
Источники: [спецификация](../../specs/first-release-packaging.md), R5–R6 и часть R1;
[план](../first-release-packaging.md), «Запуск, пути и данные», разделы 4 и 7.
Зависимости: нет.

## Результат

Без явного URL Windows SQLite создаётся в
`%LOCALAPPDATA%\osu-radio\osu-radio.db`. Клиент на Windows и Linux запускает
свой сервер с `OSU_RADIO_SKIP_DOTENV=1`; на Windows дочерний сервер не открывает
лишнее консольное окно. Ошибки конфигурации явные, пользовательские данные
не оказываются в cwd или каталоге установки.

## Границы и контекст

- Точка конфигурации — `ServerConfig::from_env` и `default_sqlite_path` в
  [config.rs](../../../apps/osu-radio-server/src/config.rs). Сейчас fallback
  ограничен Linux+SQLite. Требовать абсолютный пригодный LOCALAPPDATA;
  отсутствие, пустое/относительное значение и невозможность создать каталог
  завершают запуск ошибкой. Явный `SQLITE_DATABASE_URL` приоритетен и не требует
  создания default directory. Сохранить PostgreSQL и прежние Linux XDG/HOME.
- Точка subprocess — `EmbeddedServer::start_cancellable` в
  [client server.rs](../../../crates/osu-radio-client/src/server.rs).
  Сохранить разрешение binary, readiness stdout, drain stderr/stdout, timeout,
  cancellation, kill/reap и remote-сессию. Подавление Windows console не должно
  отключать pipes. GUI subsystem принадлежит T08, запуск helper — T03.
- Самостоятельный сервер продолжает искать `.env` и соблюдать текущую семантику
  skip-switch; публичные API и lifecycle не менять.
- Переиспользовать subprocess harness в [config tests](../../../apps/osu-radio-server/src/config/tests.rs),
  [startup tests](../../../apps/osu-radio-server/tests/startup.rs) и client server
  tests. Пересмотреть cfg существующего `selected_database_url_is_still_required`:
  после изменения Windows+SQLite больше не относится к требующим URL режимам.
- Миграции, QSettings `osu-radio/osu-radio-qt`, ключи настроек и reset policy
  сохраняются. Схему БД эта карточка не меняет. Обновить затронутые
  [backend](../../agent/backend.md), [frontend](../../agent/frontend.md) и
  [development](../../agent/development.md) guides.

## Проверка и приёмка

1. Расширить существующие изолированные probes: Windows путь с пробелами и
   кириллицей; отсутствующий/пустой/относительный LOCALAPPDATA; файл вместо
   каталога; явный URL при непригодном LOCALAPPDATA. Проверить точный путь,
   сохранение записи после restart и отсутствие БД в cwd. Дочернее окружение
   изолировать, рабочую БД пользователя не открывать.
2. Проверить клиентский запуск из каталога с ошибочным `.env`: дочерний сервер
   его игнорирует на обеих ОС, но standalone-тесты загрузки/ошибок `.env` проходят.
   Переиспользовать shutdown/cancel/remote регрессии; не дублировать всю их матрицу.
3. В socket-capable runner на Linux и нативной Windows выполнить:

   ```sh
   cargo test -p osu-radio-server --locked
   cargo test -p osu-radio-server --no-default-features --features sqlite --locked
   cargo test -p osu-radio-client --lib --locked
   cargo test -p osu-radio-client --features mock --lib --locked
   ```

   PostgreSQL-конфигурацию без подключения проверить отдельно:
   `cargo test -p osu-radio-server --no-default-features --features postgres --locked config::tests::`.
   Не объединять backend features и Cargo-компиляции одного target directory.
4. Scoped Clippy затронутых crates, docs on/off и client mock on/off, затем
   форматирование по матрице проекта. В нативной Windows desktop-сессии проверить
   отсутствие консоли при создании child и доступность диагностики при ошибке.
   Установленный GUI и весь data lifecycle дополнительно принимаются T08/T10.

## Отчёт о выполнении

Платформа: Linux (Arch, x86_64). Нативная Windows не использовалась.

Файлы:
- [config.rs](../../../apps/osu-radio-server/src/config.rs): `default_sqlite_path` на Linux и
  Windows; `user_data_home` — XDG/HOME (без изменений) либо абсолютный `LOCALAPPDATA`.
- [client server.rs](../../../crates/osu-radio-client/src/server.rs):
  `OSU_RADIO_SKIP_DOTENV=1` для дочернего сервера на всех ОС с Linux/Windows
  (без cfg), `CREATE_NO_WINDOW` на Windows; pipes и остальной lifecycle не менялись.
- Тесты: [config/tests.rs](../../../apps/osu-radio-server/src/config/tests.rs) (Windows-проба,
  cfg `selected_database_url_is_still_required`), [startup.rs](../../../apps/osu-radio-server/tests/startup.rs)
  (Windows-restart, общий тест ошибки каталога), [embedded_server.rs](../../../crates/osu-radio-client/tests/embedded_server.rs)
  (`.env`-случаи теперь и на Windows, LOCALAPPDATA).
- Документы: backend, frontend, development guides.

Выполнено на Linux (все успешно, кроме отмеченного):
- `cargo test -p osu-radio-server --locked` — 79 + 6 passed;
  `--no-default-features --features sqlite` — 71 + 6 passed;
  `--features postgres config::tests::` — 9 passed.
- `cargo test -p osu-radio-client --lib --locked` — 238 passed (со сборочным обходом libclang
  из памяти пользователя); `--features mock` — 256 passed.
  Эти наборы нестабильны независимо от изменения: примерно 1 из 3 запусков падает случайный тест
  (ETXTBSY у script-фикстур `lifecycle_tests`, тайминг `search_debounces…`); та же картина
  на базовом коммите со stash изменений.
- `cargo test -p osu-radio-client --test embedded_server --locked -- --ignored` — passed
  (реальный сервер, cwd без БД, XDG-путь, ignored valid/malformed/unreadable `.env`).
- Clippy (`-p osu-radio-server -p osu-radio-client --all-targets`, mock on, server sqlite-only)
  и `cargo fmt --check` — без замечаний.

Не проверено:
- Все `cfg(windows)`: код и тесты (LOCALAPPDATA с пробелами/кириллицей, пустой/относительный/
  отсутствующий, файл вместо каталога, явный URL, restart, `CREATE_NO_WINDOW`) не компилировались
  и не запускались; кросс-`cargo check` под `x86_64-pc-windows-msvc` не удался (нет `lib.exe` для C-зависимостей).
- Отсутствие консольного окна и доступность диагностики при ошибке на реальном Windows desktop.
- Тесты на нативной Windows, docs on/off для Windows; PostgreSQL-подключение не проверялось.

Расхождений со спецификацией и планом нет.
