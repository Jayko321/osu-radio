# T07. Два согласованных Arch-варианта

Состояние: реализовано и проверено на candidate; финальные релизные входы и нативная приёмка ожидают T09/T10.
Источники: [спецификация](../../specs/first-release-packaging.md), R3 (R2 исключён), Arch-части R6–R9;
[план](../first-release-packaging.md), версия/источник, этап 4 и раздел 7.
Зависимости: обновлённая T05 — архив, собранный в Arch с системным Qt,
installed layout, Linux PNG и notices; прежняя Ubuntu-проба входом не считается;
T01/T03 — .NET 10 и helper-контракт доступны через T05.

## Результат

Подготовлены рецепты `osu-radio-git` и `osu-radio-bin` с инструкциями
и воспроизводимой генерацией `.SRCINFO`. Их build/install функции проверены
в чистом Arch. Оба варианта предоставляют одно приложение, конфликтуют,
используют прежние команды и данные; `-bin` не требует SDK.

## Границы и контекст

- Обновить [PKGBUILD](../../../packaging/arch/PKGBUILD),
  [.SRCINFO](../../../packaging/arch/.SRCINFO),
  [README](../../../packaging/arch/README.md) и
  [desktop entry](../../../packaging/arch/osu-radio.desktop);
  добавить отдельные каталоги/рецепты для `-git` и `-bin` в `packaging/`.
  Фактические пути записать для T09. Согласовать назначение существующего
  `PKGBUILD.local`, если он остаётся:
  dev-рецепт не должен рекламировать старую runtime-модель как текущую.
- Обычный `osu-radio` не поставляется (R2 исключён); существующий PKGBUILD служит
  основой `-git`. `-bin`: релизный тег `v0.1.0-alpha`, `pkgver=0.1.0alpha`,
  `pkgrel` по `vercmp` с прежним локальным `0.1.0alpha-1`, новый архив/checksum
  только после переноса тега. `-git`: полная main history,
  `0.1.0alpha.r<число-коммитов>.g<hash>`, не shallow clone и не релизный архив.
- `-git` использует системные Qt и .NET 10 SDK/runtime, Rust из
  `rust-toolchain.toml`, необходимые C++/clang prerequisites и relative helper
  T03. `-bin` устанавливает отдельный framework-dependent архив T05, объявляя
  только фактические runtime dependencies, согласованные с системными пакетами
  сборочной Arch-среды T05; self-contained publish вместо этого архива не использовать.
- Сохранить `/usr/bin/osu-radio`, `osu-radio-qt`, `osu-radio-server`,
  `/usr/lib/osu-radio`, QSettings/XDG; добавить иконку/полные licenses.
  osu!/Wine остаются необязательными. Пакетные hooks не делают reset и не
  удаляют пользовательские данные. Обновить затронутые agent guides.
- До внешнего шага из раздела 7 плана проверить immutable candidate в отдельном
  staging/local-source рецепте. Явно отделить его от финального release recipe:
  старый опубликованный архив не содержит новый код. Параметры генерации
  финальных source/checksum и `.SRCINFO` передать T09; не вносить checksum
  бинарного релиза в его исходный commit и не переносить тег этой карточкой.

## Проверка и приёмка

1. В чистом Arch с `base-devel`, без личных кэшей, обычным пользователем
   собрать каждый вариант и проверить установку через `makepkg -si`.
   Предварительный `-git`, если main ещё не содержит изменения, проверять
   на полном candidate Git remote отдельным тестовым рецептом; это не приёмка
   финального main. Реальные main/tag/asset входы повторно проверяет T09.
2. Для каждого рецепта выполнить `makepkg --printsrcinfo`, сравнить с его
   `.SRCINFO`; проверить checksums дополнительных файлов и архивов. `SKIP`
   допустим для VCS source, не для release archive/desktop/icon/notices.
   Изменённый архив должен провалить проверку checksum.
3. Проверить package contents, `provides`/`conflicts`, desktop entry, иконку,
   Linux helper path и запуск без build tree. Для `-bin` runtime-среда
   не содержит Rust/C++/.NET SDK; нативный Realm должен запускаться.
4. Через `vercmp` проверить, что `-bin` обновляет прежний локальный `0.1.0alpha-1`, и рост
   версии `-git` между последовательными commit. Проверить запрет совместной
   установки вариантов, запуск `-bin` с объявленными системными зависимостями
   Arch и замену одного варианта другим на совместимой схеме, сохраняя
   тестовую библиотеку/плейлист/настройки. Произвольный schema downgrade не добавлять.
5. Записать, какие source/checksum пока candidate. Финальные `.SRCINFO`, archive
   и `-git` main — T09; слышимый звук и полная сохранность lifecycle — T10.

## Отчёт о выполнении

Дата: 2026-10-29. Пользовательская приёмка не отмечалась.

**Файлы.** Релизные рецепты и `.SRCINFO` находятся в
`packaging/arch/osu-radio-git/` и `packaging/arch/osu-radio-bin/`.
Корневые `packaging/arch/PKGBUILD` и `.SRCINFO` повторяют `-git` для прежних
ссылок. Обновлены desktop entry с иконкой, `packaging/arch/README.md`,
`docs/agent/development.md` и `docs/agent/test-coverage.md`. Устаревший
`PKGBUILD.local` на .NET 8 удалён. Лицензионные файлы T05 сохранены.

**Источники.** Проверен отдельный полный Git-клон из снимка T05 с добавленным
временным commit тестовой фикстуры `935cd20750c22831327b98f0d4a0ea507e8cee79`
(54 commit, `0.1.0alpha.r54.g935cd20-1`). Основной репозиторий не коммитился.
Реальный `main` пока не содержит этих изменений, это не его финальная приёмка.
Для `-bin` использован архив T05 SHA-256
`fa8eb7de12150787b640605c102422d78280499cf519373f4f3faacc4eb33bda`;
локальный тестовый рецепт хранится отдельно в ignored `target/arch-first-release-t07/`.
Полученный для runtime-проверки пакет имеет SHA-256
`a29f1ba8d20512ed872429fc4bbbec32fc364385c5a4ebdc2f54baa9c3667fbf`;
`-git` пакет, использованный для замены, —
`7277a783a622d67f9a2682669ea50ad1f914451849ed1b83af20ebb8b3c601d7`.
Это candidate-снимки, не финальные release assets. Релизный `-bin` содержит
намеренно неверный нулевой checksum: T09 должен подставить SHA-256 фактического
архива после отдельно разрешённого переноса тега и заново сгенерировать `.SRCINFO`.
В release commit checksum ещё не существующего бинарника не вносился.

**Сборка и установка.** В отдельной копии Arch build-root T05 с новой учётной
записью и пустыми приватными Rust/Cargo/NuGet-кэшами `-git` собран с полным
Git history; затем оба candidate-рецепта прошли `makepkg -si` обычным
пользователем. Portal-зависимости установлены из подписанных Arch-пакетов;
для их проверки скопирован keyring T05. Из-за namespace в тестовом root
отключён `CheckSpace` pacman, диск проверен на хосте; исходный root и пакеты
хоста не изменялись. Это копия уже подготовленной T05 среды, а не повторный
bootstrap с нуля. Вторая сборка `-git` использовала кэши первой. Логи:
`git-build.log`, `git-si.log`, `bin-si.log` в `target/arch-first-release-t07/`.

`-bin` зависит от glibc >= 2.39, Qt base/declarative >= 6.12, системных
libgcc/libstdc++, ALSA, Qt SVG/Wayland, .NET 10 runtime и desktop portal с
реализацией. Границы glibc/Qt соответствуют проверенному кандидату T05;
при финальной сборке T09 должен заново сверить их с фактическими бинарниками.
Rust/C++/.NET SDK в runtime-root отсутствуют. Через pacman установлен `-bin`,
затем сервер прочитал реальный synthetic Realm (`beatmap_count=2`) через
`../lib/osu-radio`; проверены отказ без .NET runtime, ELF-зависимости и
запуск offscreen GUI с дочерним сервером. GUI и сервер запускались без
исходников и build tree. Логи `runtime-final.log` и `runtime-install.log`.

**Метаданные и данные.** У обоих рецептов `makepkg --printsrcinfo` совпал с
сохранённой `.SRCINFO`; Bash syntax и `desktop-file-validate` прошли.
SHA-256 корректного candidate проверен, намеренно изменённый архив отклонён.
`vercmp` подтвердил `0.1.0alpha-2 > 0.1.0alpha-1` и рост `r54 > r53`.
Состав пакетов включает команды, helper, desktop entry, PNG и notices;
`provides`/`conflicts` проверены фактическим отказом pacman от одновременной
установки. При `-bin → -git → -bin` сохранены импортированная Realm-библиотека,
созданный плейлист и байты файла настроек; после каждой замены работали сервер,
helper и offscreen GUI. Повторная установка `-bin` сохранила те же данные.
Логи `switch.log`, `persistence-final.log`, `integrity-final.log`,
`corrupt-final.log`. Входная Realm-фикстура не изменена.

**Ограничения.** `makepkg` предупредил о строках пути `$srcdir` в двух
Rust-бинарниках и DLL helper у `-git`; автономный запуск проверен, однако эти
строки могут раскрывать путь сборки. Прежняя Qt-проба T05 с повторным запросом
обложки остаётся открытой. Настоящий `main`, перенесённый тег, финальный архив,
его checksum и финальные `.SRCINFO` проверяет T09. Нативные desktop/X11/Wayland,
фактическое отображение иконки в меню, слышимый звук, полные lifecycle и
пользовательская приёмка остаются T10. Context7 вернул `Monthly quota exceeded`;
доступ к нему восстанавливается через `npx ctx7@latest login` или
`CONTEXT7_API_KEY`. Поведение `makepkg` сверено с установленным инструментом и
[официальным руководством Arch](https://man.archlinux.org/man/makepkg.8.en).
