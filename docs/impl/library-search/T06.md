# T06. Фильтры BPM, stars и полной длительности

Состояние: реализовано и проверено; пользовательская приёмка не проводилась.
Источники: [спецификация](../../specs/library-search.md), R5–R6, R11–R12;
[план](../library-search.md), разделы 2–3 и 5.
Зависимости: T04 — duration в импортированном снимке; T05 — общий parser,
критерии и отбор audio ID. Хранение stars/BPM предоставлено T01.

## Результат

Запросы `bpm`, `star/stars/sr` и `length` фильтруют аудио по известным
импортированным значениям. Все ограничения одного поля проверяются на одном
значении; аудиомоды и скорость воспроизведения на поиск не влияют.

## Границы и контекст

Следовать [API-процедуре](../../../.agents/skills/osu-radio-api/SKILL.md).
Сверить фактические parser/repo-типы из отчёта T05, схему T01 и duration-путь T04.
Точки входа остаются
[BeatmapSetService](../../../crates/radio-services/src/beatmap_set.rs) и
[BeatmapSetRepository](../../../crates/radio-db/src/repositories/beatmap_set.rs).

- Расширить существующий parser и SQL-критерии, не вводить параллельный
  механизм или новые endpoints. Операторы `=`, `!=`, `<`, `<=`, `>`,
  `>=`; алиасы `:` → `=`, `!:` → `!=`, `<:` → `<=`,
  `>:` → `>=`.
- Объединять сравнения одного поля, включая алиасы и `!=`, в условие на одно
  известное значение. Разные поля могут совпасть в разных связанных сложностях.
  Числовое `!=` не имеет семантики текстового исключения всего аудио:
  оно выбирает известные значения вне запрещённого диапазона/значения.
- BPM `=180` включает [179,5; 180,5], `!=180` — дополнение среди известных
  значений. Остальные сравнения идут с исходным числом без сдвига границ.
- Stars перед сравнением усекаются вниз до сотых; неизвестный/нерассчитанный
  рейтинг не становится нулём. Используются сохранённые no-mod stars исходного
  режима, без перерасчёта. Реальное извлечение источников — T02/T03.
- `length` принимает секунды, `m:ss`, `h:mm:ss`, `ms/s/m/h`;
  привести к единице сохранённой полной длительности `audio_sources.duration_ms`.
  Не использовать длину карты, live duration endpoint или скорость playback.
  Поиск не открывает файлы; Refresh отвечает за актуальность значения.
- Неизвестное значение не удовлетворяет ни одному числовому сравнению,
  включая `!=`. Невалидное или непредставимое значение запроса остаётся
  буквальным текстом по правилу T05; ошибки разбора не снимают фильтр.
- Сохранить snapshot, grouping, загрузку полных сложностей, порядок и форму
  ответов. Обновить описание `q` в обоих route-файлах и backend/database guides.

## Проверка и приёмка

Расширить [search contracts](../../../crates/radio-services/src/tests/search.rs)
одной общей матрицей для SQLite/PostgreSQL; unit-проверки нужны для parsing
форматов и границ, которые не покрыты сервисным уровнем.

| Данные/запрос | Ожидаемый результат |
| --- | --- |
| Общее аудио с BPM 100 и 300; `bpm>=180 bpm<=200` | Не найдено: нельзя собрать диапазон из разных значений |
| BPM 179,5 / 180,5 / за этими границами; `bpm=180`, `bpm!=180` | Включённые границы и их точное дополнение среди известных |
| BPM 180,2; `bpm>180` | Найдено без lazer-сдвига границы |
| Stars 5,999; `stars=5.99`, `stars>=6` | Первое проходит, второе нет после усечения |
| `stars>=5 sr<6` | Оба алиаса ограничивают одно значение, не разные сложности |
| NULL и известные значения; числовое `!=` | NULL не проходит; известное подходящее значение может включить аудио |
| Эквивалентные length в секундах, `m:ss`, `h:mm:ss` и единицах | Одинаковая выборка без потери значимой точности |
| Файл 4 секунды, карта 2 секунды; `length>3s` | Найдено по полной длительности |
| Изменение аудиомодов/скорости при том же снимке | Та же выборка BPM/stars/length |

Также проверить сочетание числового и текстового условия, разные поля на разных
сложностях, противоречивые ограничения и буквальный fallback ошибочного ввода.
Для duration использовать результат подготовки T04 и его Refresh-to-NULL,
не повторять codec-матрицу здесь.

```sh
cargo test -p radio-services --lib --locked
```

Выполнить PostgreSQL service contracts отдельно по
[development guide](../../agent/development.md#repository-and-backend-checks)
в свежей `radio_db_test_*`. Парсер без реального SQL не подтверждает backend-паритет.
Сквозную связь stable/lazer → сохранение → поиск и Songs проверяет T08.

## Отчёт о выполнении

### Реализация

- [Парсер поиска](../../../crates/radio-services/src/search.rs) добавляет
  `bpm`, `star`/`stars`/`sr` и `length` с операторами и алиасами карточки;
  невалидный или непредставимый ввод остаётся буквальным текстом. Десятичные
  значения длительности преобразуются в целые миллисекунды с признаком остатка,
  поэтому сравнение сохраняет точность и для долей миллисекунды.
- [Репозиторий](../../../crates/radio-db/src/repositories/beatmap_set.rs)
  предоставляет `NumericField`, `Comparison`, `NumericValue`, `NumericCriterion`
  и `matching_numeric`: все ограничения одного поля применяются к одной
  известной записи. Сервис пересекает ID разных полей с текстовыми совпадениями
  и online ID в существующем снимке. `!=` выбирает подходящее известное значение,
  а не исключает аудио по другой записи. Для BPM применяется допуск только к
  равенству и его дополнению; stars усекаются до сотых с учётом двоичной границы.
  Length читает сохранённую длительность audio source без файлового I/O.
- Обновлены `beatmap_set.rs` сервиса, сервисные тесты `tests/search.rs` и
  `tests.rs`, существующие CLI фикстура и [тест](../../../apps/osu-radio-cli/tests/commands.rs),
  описания `q` в обоих server routes, guides [backend](../../agent/backend.md)
  и [database](../../agent/database.md). T07 расширяет тот же парсер и отбор.

### Проверки

- `cargo test -p radio-services --lib --locked` — 23 прошли, 2 измерительных
  теста штатно `ignored`. Общая матрица проверяет интервалы на одном значении,
  границы и дополнение BPM, stars 5.999 и значения на/рядом с границей сотой,
  алиасы, NULL, разные поля на разных сложностях, сочетание с текстом и online ID,
  форматы и дробные миллисекунды, буквальный fallback и независимость от активных
  индивидуальных audio mods. Существующие проверки T05 снимка, порядка и группировки
  также прошли. Тест T04 использует четырёхсекундный WAV и проверяет поиск до и
  после Refresh до NULL.
- `cargo test -p radio-services --lib --no-default-features --features postgres
  --locked postgres_service_contracts -- --ignored` — тот же сервисный контракт
  прошёл на новой `radio_db_test_t06_final`. Временный кластер остановлен и удалён.
- `cargo test -p osu-radio-cli --test commands --locked` — 14 прошли. Stable
  фикстура с длительностью карты 2 секунды и WAV 4 секунды импортируется через
  CLI; `length>3s` находит трек, `length<3s` не находит, исходный файл сохранён.
- Scoped Clippy с `-D warnings` для `radio-db`, `radio-services`, CLI и server
  прошёл на SQLite/default docs и PostgreSQL без docs; отдельно server на SQLite
  без docs — прошёл. `cargo fmt --check`, `git diff --check` — прошли.
  При сборках использован `OSU_LAZER_REALM_PARSER_PATH=/bin/false`; реальный
  Realm helper этими проверками не запускался.

### Границы

T07 и T08, пользовательская приёмка, HTTP encoding и реальное взаимодействие
Songs не проверялись. CLI проверка использует синтетический stable source и
частную базу; реальные установки и пользовательские базы не затрагивались.
