# T04. Полная длительность аудио в импортированном снимке

Состояние: реализовано и проверено; пользовательская приёмка не проводилась.
Источники: [спецификация](../../specs/library-search.md), R6, R11–R12;
[план](../library-search.md), раздел 2 «Длительность» и раздел 5.
Зависимости: T01 — nullable duration_ms и запись/чтение в audio_sources.

## Результат

Серверный импорт/Refresh и CLI сохраняют полную длительность уникального аудио
вместе со снимком. HTTP duration и playback используют общий probe и продолжают
проверять файл при обращении. Поиск сможет читать сохранённое значение без I/O.

## Границы и контекст

Следовать [API-процедуре](../../../.agents/skills/osu-radio-api/SKILL.md).
Сверить запись duration и обновление существующего audio ID после T01.

- Перенести `probe_duration`/`probe_source_duration` из
  [server media.rs](../../../apps/osu-radio-server/src/routes/media.rs)
  в `radio-services` и предоставить необходимый экспорт через
  [lib.rs](../../../crates/radio-services/src/lib.rs).
  Сохранить определение формата по содержимому, запрет специальных файлов до
  открытия и повторную проверку открытого файла, отсутствие чтения tags,
  обработку нулевой длительности и ошибок. `Online` остаётся без локального probe.
- Перенести использование Lofty из server manifest в
  [services manifest](../../../crates/radio-services/Cargo.toml);
  Tokio, сейчас dev-dependency services, нужен и в runtime.
  Обновить Cargo.lock при необходимости. Эти зависимости согласованы планом.
  Новые crates, фоновые worker и дополнительные настройки не нужны.
- Перед записывающей транзакцией последовательно выполнять `spawn_blocking`
  для каждого уникального аудио один раз. Пути брать из существующего
  `ImportedBeatmapSet::resolved_audio_path`, сохранив идентичность источника.
  Подготовленные значения передавать в уже существующую транзакцию снимка.
- Охватить все пути в
  [folder_selection.rs](../../../crates/radio-services/src/folder_selection.rs):
  `import_folder`, `register_imported_snapshot`, `register_snapshot`,
  `reimport_folder`/`reimport_snapshot`; и в
  [osu_installation.rs](../../../crates/radio-services/src/osu_installation.rs):
  `replace_imported_snapshot`/`replace_snapshot` и внутренние варианты.
  Не запускать probe повторно во вложенных вызовах или под writer lock.
  Сохранить повторную проверку identity и удаление папки во время подготовки.
- [CLI store](../../../apps/osu-radio-cli/src/commands/store.rs) вызывает
  `replace_imported_snapshot`; он должен получать ту же подготовку без
  дублирования логики в приложении. Preview/count остаются чтением scanner.
- В [media.rs](../../../apps/osu-radio-server/src/routes/media.rs) и
  [playback.rs](../../../apps/osu-radio-server/src/routes/playback.rs)
  заменить вызовы общей функцией, сохранив HTTP payload/status/error boundary.
  Ожидаемая ошибка файла даёт неизвестную длительность и не отменяет импорт;
  неожиданный сбой задачи/БД не маскировать как успешную запись.
- Refresh записывает текущее значение, в том числе NULL вместо прежней
  длительности. Сохранить atomicity с библиотекой и timestamp, в том числе
  для audio row, используемой другими наборами. Файлы не копировать/не изменять.
  Обновить database/backend guides; scanner продолжает только читать источник.

## Проверка и приёмка

Переиспользовать MP3/Ogg/WAV и FIFO-проверки из media.rs. При переносе сохранить
валидные пути к fixtures и платформенные ограничения; не создавать второй
набор одинаковых probe-тестов в server.

1. Extensionless MP3/Ogg/WAV дают полную длительность; повреждённый, отсутствующий
   файл, каталог и FIFO дают неизвестное значение без блокирующего открытия.
2. Импорт нескольких сложностей с одним аудио сохраняет один подготовленный
   результат. Полная длительность отличается от cached length карты;
   аудиомоды её не меняют.
3. Refresh после изменения файла обновляет duration, после удаления/повреждения
   сбрасывает её в NULL. Ошибка записи сохраняет старый снимок вместе с duration.
   Пока идёт подготовка, удаление папки не должно приводить к её воссозданию;
   concurrent label/enabled edits сохраняются. Расширить существующие
   [folder-selection проверки](../../../crates/radio-services/src/tests/folder_selection.rs)
   и snapshot contracts только для новых рисков этого этапа.
4. [CLI subprocess fixture](../../../apps/osu-radio-cli/tests/commands.rs)
   подтверждает сохранение длительности через `store` с явным marker и частной БД.
   Сохранить source bytes и прежнюю семантику `--clear`.
5. Запуски на разрешённом socket-capable runner:

   ```sh
   cargo test -p radio-services -p osu-radio-cli -p osu-radio-server --locked
   cargo test -p osu-radio-server --no-default-features --features sqlite --locked
   ```

Изменённую запись снимка проверить также PostgreSQL service contracts по
[development guide](../../agent/development.md#repository-and-backend-checks).
Политика уникальности/последовательного probe подтверждается узкой проверкой
пути подготовки; не нужен benchmark. Сервисная запись не подтверждает
поисковый `length` до T06, а HTTP/playback тесты не подтверждают физический звук.

## Отчёт о выполнении

Общий probe в `crates/radio-services/src/duration.rs` используется HTTP duration,
playback и подготовкой снимка; Lofty и runtime Tokio перенесены в services.
`osu_installation.rs` подготавливает длительности последовательно по уникальному
resolved path до транзакции; `folder_selection.rs` и публичные replace-методы
передают результат в транзакцию. Запись использует существующий audio ID и
обновляет в том числе NULL. CLI store использует тот же сервис. Изменены
`Cargo.lock`, manifests, `audio_source.rs`, `lib.rs`, server media/playback,
service/CLI tests и database/backend guides. В `lazer/types.rs` уточнён Clippy
allow для точного sentinel -1, обнаруженного при проверке зависимого кода T03.

- `cargo test -p radio-services -p osu-radio-cli -p osu-radio-server --locked`
  на socket-capable runner: CLI 15 unit + 13 subprocess, server 77 unit + 6
  startup, services 20 unit — прошли; по два benchmark/helper теста server и
  services игнорированы штатно. После правки структуры HashMap повторно прошёл
  `sqlite_service_contracts`.
- `cargo test -p osu-radio-server --no-default-features --features sqlite --locked`:
  69 unit + 6 startup прошли, два штатно игнорированы.
- PostgreSQL: полный service-набор на новой временной `radio_db_test_t04` —
  4 passed; после правки HashMap повторён `postgres_service_contracts` — passed
  на новом временном кластере. Кластеры остановлены и удалены.
- `cargo clippy -p radio-services -p osu-radio-cli -p osu-radio-server --all-targets
  --locked -- -D warnings` и `git diff --check` — успешно.
- `duration` tests покрывают extensionless WAV/MP3/Ogg, ошибки и FIFO;
  `duration_snapshot` на SQLite/PostgreSQL проверяет общий audio ID, изменение,
  NULL, rollback и timestamp. `reimport_waiting_for_probe_preserves_edits_and_deletion`
  отдельно прошёл на SQLite с занятым blocking worker. CLI subprocess проверяет
  сохранение длительности и неизменность исходных файлов. Код подготовки и размер
  результата проверяют уникальность путей; порядок задаётся последовательным await.

Поисковый `length` относится к T06; физическое воспроизведение и пользовательская
приёмка не проверялись. Native Windows и реальные установки не проверялись.
Расхождений с карточкой не обнаружено.
