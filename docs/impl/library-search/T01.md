# T01. Новые поисковые данные и безопасное обновление схемы

Состояние: реализовано и проверено; пользовательская приёмка не проводилась.
Источники: [спецификация](../../specs/library-search.md), R2–R3, R6–R8,
R11–R12; [план](../library-search.md), разделы 2 и 5.
Зависимости: нет.

## Результат

Следующая миграция после v18 добавляет согласованные поля. Обновление заполненной
базы сохраняет библиотеку и пользовательские данные; сервисная замена снимка
записывает новые импортные значения атомарно. Старые неизвестные значения
не становятся нулями или локальными датами.

## Границы и контекст

Работать по [API-процедуре](../../../.agents/skills/osu-radio-api/SKILL.md),
[database guide](../../agent/database.md) и импортным ограничениям
[scanner guide](../../agent/scanner.md).

- Расширить [ImportedBeatmap/ImportedBeatmapSet](../../../crates/radio-core/src/import_types.rs):
  nullable stars и нормализованный статус сложности; nullable ranked/submitted
  набора в Unix milliseconds UTC. Согласовать их с entities, plain models,
  преобразованиями и репозиториями `beatmap`/`beatmap_set` в
  [radio-db](../../../crates/radio-db/src/lib.rs). Точные имена новых полей
  выбрать при реализации и записать в отчёт для следующих карточек.
- В `audio_sources` добавить nullable `duration_ms` и чтение/запись этого
  значения в [AudioSourceRepository](../../../crates/radio-db/src/repositories/audio_source.rs).
  Здесь проверить хранение; файловый probe и включение в импорт принадлежат T04.
  Сохранить идентичность `(kind, location)`, включая уже существующий audio ID.
- Добавить производные нормализованные mapper/source в metadata. Имя mapper —
  `author.username`; исходный author хранится JSON-объектом.
  В [metadata repository](../../../crates/radio-db/src/repositories/beatmap_metadata.rs)
  переиспользовать Rust `to_lowercase()` и существующую проверку неизменности
  строки. Новые поисковые поля не входят в `metadata_hash`; исходный JSON,
  регистр, null/empty и идентификаторы не менять.
- Зарегистрировать новую миграцию в
  [migrations/mod.rs](../../../crates/radio-db/src/migrations/mod.rs).
  Backfill только mapper/source, ограниченными keyset-страницами по образцу
  [v17](../../../crates/radio-db/src/migrations/m20261027_000017_search_text.rs).
  Stars/status/dates/duration старых строк остаются неизвестными до Refresh.
  Исторические миграции не редактировать; startup не сканирует источники.
- Протянуть новые значения через
  [OsuInstallationService](../../../crates/radio-services/src/osu_installation.rs),
  `BeatmapSetService::add` и `BeatmapService::add`, сохранив writer lock,
  transaction-bound repositories, cleanup и единственный внешний commit.
  Не менять теги, коллекции, плейлисты, историю, настройки или форму HTTP-ответов.
- Обновить сломанные конструкторы и fixtures вместе с типами. Сейчас такие
  литералы есть в stable/lazer mapping, DB/service tests, server
  [test_support](../../../apps/osu-radio-server/src/test_support.rs) и CLI
  [import.rs](../../../apps/osu-radio-cli/src/commands/import.rs).
  До T02/T03 новые source-поля остаются `None`; извлечение данных не реализовывать
  частично в этой карточке. Экспорты — через существующие model/service модули.
- Обновить факты схемы в database guide, отличая уже работающую запись от ещё
  не выполненных importer/search карточек.

## Проверка и приёмка

Основной риск — потеря старых данных или несовместимость исторических fixtures
с новой моделью. Расширить существующие
[migration_lifecycle](../../../crates/radio-db/src/tests/migration_lifecycle.rs)
и [service contracts](../../../crates/radio-services/src/tests.rs).

1. Заполненная v18 обновляется без reset: сохраняются IDs, metadata hashes,
   исходные метаданные, библиотека, плейлисты/элементы, история и настройки.
   Backfill проходит более одной страницы, включая Unicode и null/empty author/source.
   Новые недоступные данные остаются NULL. Повторный `migrate` не меняет результат.
2. Новая версия корректно понижается до v18 без потери прежних данных.
   Ошибка backfill откатывает схему и данные. Переиспользовать существующий
   способ инъекции отказа; не создавать отдельную инфраструктуру.
   Исторические fixtures должны вставлять строки по исторической схеме:
   текущие repo/models с новыми колонками нельзя применять к v4/v16/v18.
3. Снимок с новыми значениями читается обратно; следующий снимок может заменить
   их на неизвестные. Ошибка/отмена сохраняет прежние значения, shared rows,
   коллекции и timestamp вместе. Значение duration обновляется и откатывается
   у уже существующей audio identity.
4. SQLite:

   ```sh
   cargo test -p radio-core -p radio-db -p radio-services --locked
   cargo check -p radio-scanner -p osu-radio-cli -p osu-radio-server --all-targets --locked
   ```

5. Те же repository/service contracts выполнить с PostgreSQL отдельно, по
   [командам и правилам одноразовой БД](../../agent/development.md#repository-and-backend-checks).
   Нужны новые `radio_db_test_*` базы для соответствующих запусков; обычная
   application DB не подходит. Проверка компиляции не заменяет runtime-миграцию.

В отчёте указать реально выполненные проверки и фактическую версию миграции.
Formatting/scoped Clippy — по общей матрице плана, с переиспользованием результатов.
Сценарий Songs и реальный source import этой карточкой не подтверждаются.

## Отчёт о выполнении

### Контракт и изменённые файлы

- [Миграция v19](../../../crates/radio-db/src/migrations/m20261106_000019_library_search.rs)
  зарегистрирована после v18. `ImportedBeatmap`/`Beatmap` получили nullable
  `stars: Option<f64>` и `status: Option<BeatmapStatus>`; статусы `ranked`,
  `approved`, `qualified`, `loved`, `pending`, `wip`, `graveyard`,
  `locallymodified` хранятся в lowercase, неизвестный статус — SQL NULL.
  `ImportedBeatmapSet`/`BeatmapSet` получили `ranked_at_ms` и
  `submitted_at_ms: Option<i64>` — UTC Unix milliseconds. `AudioSource` получил
  `duration_ms: Option<i64>`; `AudioSourceRepository::set_duration` обновляет
  значение существующего ID через привязанный к транзакции репозиторий.
  Поля `search_mapper` и `search_source` — производные и не входят в hash.
- Типы и запись: `crates/radio-core/src/import_types.rs`,
  `crates/radio-db/src/entities/{audio_source,beatmap,beatmap_metadata,beatmap_set}.rs`,
  `crates/radio-db/src/model/{audio_source,beatmap,beatmap_set,mod}.rs`,
  `crates/radio-db/src/repositories/{audio_source,beatmap,beatmap_metadata,beatmap_set}.rs`,
  `crates/radio-db/src/migrations/mod.rs`. Сервисы передают существующие
  импортные структуры в эти репозитории без смены границы транзакции.
- Исторические и текущие фикстуры: `crates/radio-db/src/tests.rs` и
  `tests/{audio_mods,audio_settings,collections,listening_history,migration_lifecycle,model_projections,playlists,queue,tag_migration}.rs`;
  `crates/radio-services/src/tests.rs`, `tests/collections.rs`,
  `beatmap_set/tracks.rs`; `crates/radio-scanner/src/lazer/types.rs`,
  `stable/{mod,reader}.rs`; `apps/osu-radio-cli/src/commands/import.rs`,
  `apps/osu-radio-server/src/test_support.rs` и `routes/beatmap_sets.rs`.
  Извлечение новых source-полей не добавлено: оба scanner mapping дают `None`.
- Обновлены [database guide](../../agent/database.md), эта карточка и
  [таблица плана](../library-search.md#7-карточки-и-зависимости).
  Предшествующие пользовательские изменения guides сохранены.

### Выполненные проверки

- SQLite: `cargo test -p radio-core -p radio-db -p radio-services --locked` —
  8, 11 и 18 тестов прошли соответственно; 2 измерительных теста services
  остались `ignored`. После уточнения rollback-сценария повторно прошёл
  `sqlite_service_contracts`; после замечаний Clippy повторно прошёл весь
  `radio-db` (11 тестов).
- PostgreSQL: команды repository и service contracts из карточки прошли в
  отдельных новых `radio_db_test_repositories` и `radio_db_test_services`;
  6 тестов `radio-db` и 2 теста `radio-services` прошли, синтетический
  benchmark исключён. Уточнённый сервисный контракт и после Clippy весь
  repository contract повторно прошли на новых одноразовых базах. Оба
  временных кластера остановлены и удалены.
- `cargo check -p radio-scanner -p osu-radio-cli -p osu-radio-server --all-targets --locked`
  прошёл. Отдельный server-тест `wire_projection_preserves_all_fields_and_source_kinds_without_internal_installation_id`
  прошёл и сохранил прежнюю форму ответа.
- `cargo fmt --check`, `git diff --check` и scoped Clippy с `-D warnings`
  прошли: core/scanner/DB/services/CLI/server для SQLite, DB/services/CLI/server
  для PostgreSQL и server без docs для SQLite / с docs для PostgreSQL.
  Для Rust-сборок задан `OSU_LAZER_REALM_PARSER_PATH=/bin/false`: проверялись
  модели, тестовые фикстуры и подставные helper-процессы, не реальный Realm helper.

Миграционный тест использует заполненную историческую v18, 257 строк с Unicode
и null/empty значениями; проверяет исходные ID/hash/JSON, библиотеку, плейлист,
историю и настройки после ошибки на второй странице, повторного `migrate` и
downgrade. Контракты сервисов проверяют замену значений на известные и NULL,
а также сохранение старых данных, коллекции и timestamp при ошибке и отмене;
репозиторий отдельно проверяет обновление и rollback длительности того же audio ID.
При первом запуске обнаружены устаревшее ожидание числа миграций и замечания
Clippy; они исправлены, затронутые проверки повторены успешно.
