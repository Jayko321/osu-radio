# T08. Общий сценарий Songs и приёмка взаимодействия частей

Состояние: реализовано и проверено в объёме карточки; пользовательская приёмка открыта.
Источники: [спецификация](../../specs/library-search.md), R1–R12 и «Приёмка»;
[план](../library-search.md), разделы 3, 5 и 7.
Зависимости: T02/T03 — оба source importer; T07 — полный поисковый механизм
с результатами T01/T04/T05/T06 и их проверками.

## Результат

Расширенный запрос проходит через настоящий клиент и оба HTTP endpoint без
искажения. В Songs с реальным backend ввод поля с кавычками показывает
нужные аудиотреки, очистка восстанавливает библиотеку с прежней сортировкой.
В спецификации сохранены фактические свидетельства R1–R12 и ограничения.

Следовать [API-процедуре](../../../.agents/skills/osu-radio-api/SKILL.md);

  пользовательские установки, unscoped discovery и application DB не нужны.

## Проверка и приёмка

1. Сохранить импортированный stable и lazer снимки в частной БД и запросить
   их через сервис/HTTP: no-mod stars и нормализованный статус доходят до
   поиска; lazer-даты доступны, stable-даты остаются неизвестными. Импорт и
   Refresh полной длительности дают соответствующий `length`, включая
   сброс после недоступного файла. Переиспользовать уже проверенные source
   fixtures и не повторять всю mapping/codec-матрицу.
2. Расширить существующие HTTP/client fixtures запросом с полем и кавычками
   и передачей символов `=`, `!`, `<`, `>`, `:`, `+`, `&`, Unicode.
   Оба endpoint получают неизменённый декодированный `q`, отбирают те же
   audio ID и сохраняют все связанные сложности. Формы JSON не изменились;
   docs включены/выключены дают одинаковое поведение.
3. В отдельной временной библиотеке для Songs подготовить:
   подходящий трек `artist=xi`, title с `freedom`, несколько сложностей
   одного аудио; контрольный трек, где xi встречается только в тегах;
   ещё один трек для проверки порядка. При SQL-seeding заполнить производные
   search-поля по фактической схеме T01/T05, не оставлять их DEFAULT ''.
4. Запустить настоящий server и Qt в изолированном окружении, выбрать
   недефолтную сортировку, ввести `artist="xi" freedom`.
   Дождаться результата: только подходящее аудио со всеми сложностями,
   порядок соответствует выбранной сортировке. Очистить строку — возвращается
   вся библиотека в прежнем порядке. Выбор оставшегося трека сохраняется
   по прежним правилам; ввод/очистка не запускают воспроизведение.
5. Существующие controller/adapter проверки подтверждают debounce/cancellation
   и stale-response защиту; новый настоящий backend-сценарий подтверждает
   связь UI → client → HTTP → service → DB. Не подменять его fixture-server.

Минимальные команды для затронутых границ:

```sh
cargo test -p osu-radio-server --locked
cargo test -p osu-radio-server --no-default-features --features sqlite --locked
cargo test -p osu-radio-client --lib --locked api::contract_tests
cargo test -p osu-radio-client --lib --locked search_debounces_cancels_and_ignores_late_success_and_error
cargo build -p osu-radio-server -p osu-radio-qt --locked
cargo test -p osu-radio-qt --test launch_smoke --locked songs_search_debounces_retries_and_clears_through_the_live_adapter -- --test-threads=1
cargo test -p osu-radio-qt --test launch_smoke --locked track_sort_menu_reorders_without_refetching_media_or_changing_selection -- --test-threads=1
```

Новый real-backend case ещё не существует: выбрать имя при реализации и
выполнить его отдельно с фактическим точным фильтром, включая `--ignored`,
если он остаётся opt-in как остальные real-backend probes. Записать команду,
использованный platform plugin и результат. После правки QML выполнить
[lint-qml.sh](../../../apps/osu-radio-qt/scripts/lint-qml.sh) по
[development guide](../../agent/development.md#qt-frontend).
Нужны Qt/QtTest, .NET для Realm, Python для текущих probes и разрешённые сокеты.
Неизменный sandbox-запрет не устранять повторением того же запуска.

Проверить наличие результатов core/scanner/helper, миграции/снимков и
service contracts SQLite/PostgreSQL, CLI из T01–T07. Недостающие или ставшие
неактуальными проверки выполнить по
[матрице](../../agent/development.md#verification-matrix), с отдельными backend
invocations и одноразовой `radio_db_test_*`. Завершить `cargo fmt --check`,
`git diff --check` и scoped Clippy для затронутых crates, включая backend
features и server с docs/без docs. Успешные актуальные результаты переиспользовать.

## Документация и критерий завершения

Обновить [спецификацию](../../specs/library-search.md): по R1–R12 записать
реализованное поведение, команды/результаты и оставшиеся ограничения.
Согласовать затронутые backend/database/scanner/frontend guides и описание
`q` с итоговым кодом; сохранить сторонние правки. Статусы T01–T08 и таблицу
плана обновить по фактическому результату, не объявляя пользовательскую
приёмку автоматически состоявшейся.

Отдельно указать: старой библиотеке нужен Refresh для новых source-полей,
stable объединяет часть статусов, поиск использует duration последнего снимка,
импорт дополнительно читает аудио. Числового performance-критерия нет.
Offscreen не подтверждает native Windows или физическое воспроизведение;
непроверенные критерии так и обозначить. Отсутствующий обязательный backend
или real-helper результат нельзя заменить успешной сборкой.

Документы не удалять: это допустимо только после всех задач, итоговой приёмки
и переноса существенных свидетельств в спецификацию.

## Отчёт о выполнении

### Результат

- [Клиентский контракт](../../../crates/osu-radio-client/src/api/contract_tests.rs)
  проверяет точное кодирование расширенного запроса для обоих endpoint.
  [HTTP-контракт](../../../apps/osu-radio-server/src/routes/tracks.rs) передаёт
  тот же запрос через настоящий client/router и сверяет аудио и все сложности.
- [CLI-фикстуры](../../../apps/osu-radio-cli/tests/commands.rs) и
  [stable writer](../../../apps/osu-radio-cli/tests/support/mod.rs) проверяют
  сохранение no-mod stars/status и неизвестных stable-дат; настоящий Refresh
  сбрасывает длительность отсутствующего аудио. Генератор создаёт отдельную
  Realm, production helper читает её для store, а поиск находит lazer
  stars/status/ranked/submitted/played. Realm marker проверяется на неизменность;
  временный аудиофайл stable намеренно удаляется для проверки Refresh.
- [Qt probe](../../../apps/osu-radio-qt/tests/AdapterProbe.qml) и
  [launch_smoke](../../../apps/osu-radio-qt/tests/launch_smoke.rs) проверяют
  Songs с настоящим server и private SQLite: `artist="xi" freedom` выбирает
  нужный audio ID со сложностями Easy/Hard, не выбирает трек с xi только в
  тегах, сохраняет сортировку по исполнителю и выбор при очистке и не запускает
  playback. SQL-фикстура заполняет производные поля поиска.
- Обновлены [спецификация](../../specs/library-search.md#состояние-проверки),
  [frontend](../../agent/frontend.md), [backend](../../agent/backend.md),
  [database](../../agent/database.md), [scanner](../../agent/scanner.md) и план.

### Ограничения и обнаруженное расхождение

Qt использовал offscreen, а источники были синтетическими. Нативные Windows,
визуальная и пользовательская приёмка, реальные библиотеки и физическое аудио
не проверялись. Старым источникам нужен Refresh для новых полей; stable
объединяет часть статусов, duration относится к последнему снимку, импорт
дополнительно читает аудиофайлы. Числовой performance-критерий не задан.

При первоначальном тесте CLI `store --marker osu/osu!.db` сохранил относительный
путь, после чего `reimport_folder` вернул `RelativePath("osu/osu!.db")`.
Тест T08 использует явный абсолютный marker, и Refresh для него прошёл.
Это соседнее существующее расхождение регистрации CLI и Refresh, не исправленное
данной карточкой: [выбор marker](../../../apps/osu-radio-cli/src/commands/helpers.rs),
[проверка Refresh](../../../crates/radio-services/src/folder_selection.rs).
