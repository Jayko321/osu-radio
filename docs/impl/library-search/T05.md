# T05. Текстовые условия, фразы и online set ID в общем поиске

Состояние: реализовано и проверено на сервисных контрактах; пользовательская приёмка не проводилась.
Источники: [спецификация](../../specs/library-search.md), R1–R5, R10–R12;
[план](../library-search.md), разделы 3 и 5.
Зависимости: T01 — нормализованные mapper/source, совместимая схема и запись.

## Результат

Оба существующих endpoint ищут по обычному тексту, указанным полям, фразам
и отрицаниям через один механизм. Результат — аудиотрек со всеми связанными
сложностями; одиночное свободное число также ищет online set ID.

## Границы и контекст

Следовать [API-процедуре](../../../.agents/skills/osu-radio-api/SKILL.md).
Основные входы — `BeatmapSetService::matching_audio_ids`,
`search_with_audio_sources` и `search_tracks` в
[beatmap_set.rs](../../../crates/radio-services/src/beatmap_set.rs);
SQL — [BeatmapSetRepository](../../../crates/radio-db/src/repositories/beatmap_set.rs).

- Добавить модуль разбора в `radio-services`; типизированные критерии
  репозитория разместить в `radio-db`, SQL оставить в репозиториях.
  Новые имена модулей/типов выбрать локально и передать в отчёте T06/T07.
  Эта карточка распознаёт текстовые поля; числовые/date/status/played условия
  подключаются в T06/T07. До этого их исходный текст не должен пропадать.
- Обычный поиск расширить mapper и source; сохранить artist/title с Unicode,
  diff и существующие теги. Между словами/условиями — И, между доступными
  полями одного свободного слова — ИЛИ. Нормализация — Rust `to_lowercase()`,
  без транслитерации, снятия диакритики или новой семантики UserTags.
- Поля: `artist`, `title`, `creator/author/mapper`, `diff`, `source`,
  `tag`. `=`/`:` — включение, `!=`/`!:` — исключение.
  Без кавычек — подстрока; кавычки — отдельное слово/фраза; суффикс `!`
  после закрывающей кавычки — полное совпадение поля.
  Свободная фраза также совпадает внутри одного поля или отдельного тега.
- Для фраз SQL отбирает подстроковые кандидаты; узкий Rust matcher проверяет
  границы только нужных полей потоково. Использовать согласованный regex
  и правила .NET `\b` из раздела 3 плана, включая начало/конец поля.
  Обычный Rust `\b` не подставлять как эквивалент. Текст пользователя
  остаётся буквальным: SQL parameters, без исполнения как regex.
- Положительные совпадения пересекаются по global audio ID; отрицательное
  текстовое условие исключает аудио, если совпала любая связанная запись.
  Повторные условия сохраняются, а не заменяют друг друга.
- Неизвестные поля, неподдерживаемые операторы, пустое/невалидное значение
  и незакрытые кавычки остаются исходным обычным текстом. Не терять фрагмент
  при неудаче распознавания и не превращать ошибку в отсутствие фильтра.
- Если после выделения условий весь свободный запрос — одно положительное
  целое число, объединить его текстовые совпадения с online set ID,
  затем применить остальные условия. Не искать local DB ID или difficulty ID.
- Сохранить один read snapshot, загрузку полных связей порциями по 500 ID,
  порядок, multiplicity, enrichment и пустые наборы legacy blank-query пути.
  Не возвращать в production тестовый full-library matcher
  `matching_audio` из service-файла.
- Форму HTTP-ответов, Qt/client передачу `q`, сортировку и playback не менять.
  Обновить описание текущего текстового синтаксиса `q` в
  [tracks](../../../apps/osu-radio-server/src/routes/tracks.rs) и
  [beatmap_sets](../../../apps/osu-radio-server/src/routes/beatmap_sets.rs),
  backend/database guides. Не объявлять T06/T07 уже выполненными.

## Проверка и приёмка

Расширить [сервисную матрицу](../../../crates/radio-services/src/tests/search.rs);
parser/matcher проверять локально только на риски разбора и Unicode-границ,
не дублировать там всю выборку БД.

- `easy hard` на разных сложностях одного аудио возвращает один полный трек;
  unrelated audio в том же наборе не добавляется. Повторные условия сохраняют И.
- `artist=xi`, `artist="xi"`, `artist="xi"!` различают подстроку, границу
  слова и полное поле. Совпадение только в tag не проходит artist; mapper/source
  работают и как отдельные поля, и в свободном запросе.
- `artist!=xi` исключает аудио целиком, даже если другая связанная запись
  имеет пустого или другого исполнителя. Для отрицательной фразы учитывать
  итог matcher, а не только SQL-кандидата.
- Фразы не склеиваются между полями, сложностями или отдельными тегами.
  Проверить Unicode-написание, начало/конец, пунктуацию и категорию символов,
  на которой правила .NET и стандартного Rust boundary расходятся.
- Буквальные `a+b%_&?#` и regex-символы не становятся шаблонами.
  Для ошибочного/незавершённого условия fixture с его буквальным текстом
  находится; отсутствие такого текста не превращает результат во всю библиотеку.
- Число находит и online set ID, и текст; условие рядом с числом ограничивает
  объединённый результат. Ноль, отрицательное число и несколько свободных слов
  не включают ветку online ID.
- Сохранить имеющиеся проверки пустого запроса, всех сложностей, порядка
  между тремя порциями и замены снимка другим соединением во время поиска.

```sh
cargo test -p radio-services --lib --locked
```

Эта команда включает `sqlite_service_contracts`; фильтр только `search`
не запускает вложенную матрицу. Те же контракты выполнить на отдельной
PostgreSQL `radio_db_test_*` по
[development guide](../../agent/development.md#repository-and-backend-checks).
Оба server docs-варианта проверяются по общей матрице, а HTTP encoding и
реальный Songs-сценарий — в T08. Не считать их проверенными этим сервисным тестом.

## Отчёт о выполнении

### Реализация и контракты для T06/T07

- [search.rs](../../../crates/radio-services/src/search.rs): `parse` возвращает
  последовательность `Condition`, `TextCriterion`, признак отрицания/фразы и
  позицию единственного свободного online ID. Неизвестные или неполные условия
  сохраняются буквальным свободным текстом. `phrase_matches` проверяет границы
  .NET по нормализованному полю; пользовательский текст не становится regex.
  T06/T07 расширяют этот общий разбор, сохраняя исходный fallback и повторения.
- [beatmap_set.rs в radio-db](../../../crates/radio-db/src/repositories/beatmap_set.rs):
  `TextField`, `TextCriterion`, `matching_text` и `matching_online_set_id` —
  репозиторный контракт. SQL возвращает ID для подстрок/полного совпадения и
  потоковые поля кандидатов для фраз; SQL остаётся в репозитории. Сервис
  пересекает или исключает глобальные audio ID и добавляет online ID к одному
  свободному числу до применения остальных условий. Общие снимок, порции,
  порядок, enrichment и legacy blank-query путь сохранены.
- Изменены сервис `beatmap_set.rs`, `lib.rs`, зависимости `Cargo.toml` и
  `Cargo.lock`, сервисная [матрица](../../../crates/radio-services/src/tests/search.rs),
  описания `q` в `routes/tracks.rs` и `routes/beatmap_sets.rs`, guides
  [backend](../../agent/backend.md), [database](../../agent/database.md) и
  [index](../../agent/index.md). Добавлена зависимость `regex`, согласованная
  общим планом, для Unicode-класса границ.

### Проверки

- `cargo test -p radio-services --lib --locked`: 22 прошли, 2 измерительных
  теста `ignored`. Сервисная матрица проверяет оба представления, общие аудио
  и сложности, поля, фразы, отрицания, буквальный fallback, online ID, пустой
  запрос, порядок между тремя порциями и снимок при конкурентной замене.
  Локальный тест парсера/matcher проверяет также Unicode-категории .NET.

  postgres --locked postgres_service_contracts -- --ignored` — контракт прошёл
  на новой отдельной `radio_db_test_t05_lint`; временный кластер остановлен и
  удалён. Это те же сервисные сценарии, а не проверка рабочей базы приложения.
- Scoped Clippy с `-D warnings`: `radio-db`, `radio-services`, `osu-radio-server`
  с SQLite/default docs и с PostgreSQL без docs; отдельно server с SQLite без
  docs — прошли. `cargo fmt --check` и `git diff --check` — прошли.

реальный импорт или работу приложения с пользовательской библиотекой.
