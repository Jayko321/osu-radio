`packaging/arch/licenses/` и только необходимые связанные тексты атрибуции.
Эти пути пока отсутствуют и являются результатом задачи. T04 создаёт остальные
файлы `packaging/arch/` и устанавливает подготовленные материалы.
Не изменять manifests, Cargo.lock, исходники приложения, тестовые runners
и общие руководства параллельного потока.

Проверить фактических правообладателей по проектным данным; не придумывать
имена/годы. MIT уже заявлена в [workspace manifest](../../../Cargo.toml).

Состав ассетов сверить с [Qt build.rs](../../../apps/osu-radio-qt/build.rs).
Состав Rust сверять по [Cargo.lock](../../../Cargo.lock) и features реально
поставляемых Qt/SQLite server binaries, не подменяя его произвольным списком crates.
Состав NuGet/native сверять по
[csproj](../../../tools/osu-lazer-realm-parser/osu-lazer-realm-parser.csproj)
и framework-dependent `linux-x64` publish, предусмотренному планом.
Нужные restore/publish-артефакты получать в изолированном рабочем каталоге;
это не production-бинарники. Системные пакеты и bundled-компоненты различать
по фактической поставке. Использовать необходимые тексты/уведомления,
не добавлять новую постоянную систему лицензирования или зависимость ради отчёта.

T02 меняет только версии двух приложений, поэтому независимая инвентаризация
возможна; T04/T05 повторно сверяют материалы с окончательным составом.
Если обнаружена несовместимость выбранной поставки с лицензией, зафиксировать
конкретное препятствие для `$impl-plan`, не менять состав/способ поставки молча.

## Проверка и приёмка

1. Убедиться, что корневая MIT полная и соответствует установленным проектным
   сведениям; обязательные notices не заменены одним SPDX-идентификатором.
2. Сопоставить фактический Cargo/NuGet/native/asset состав с материалами;
   для каждого обязательного текста указать источник и покрываемый компонент
   в самом комплекте уведомлений. Не считать перечень названий доказательством
   наличия необходимых полных текстов.
3. Существующий repository check защищает полные тексты четырёх asset licenses:

   ```sh
   python3 -B -m unittest discover -s tests -v
   ```

   На момент декомпозиции общий набор уже выявляет несогласованность
   `.gitignore`/политики `docs/impl/`, инвентаря и внешних skill links
   (свидетельства в разделе 7 плана). Лицензионный check оценивать отдельно
   от этих ошибок, не объявлять общий набор успешным и не откатывать
   пользовательскую политику хранения документов ради его прохождения.

4. Сверить пути будущей установки с T04: корневой MIT и все обязательные notices
   должны попадать в `/usr/share/licenses/osu-radio/`. До появления готового
   пакета это проверка материалов; содержимое установленного пакета проверяет T05.

Команды конкретных SDK/API при получении сведений сверять по процедуре Context7.
Неразрешённые вопросы правообладателя/обязательного уведомления записывать явно;
не объявлять лицензионную часть релиза готовой при отсутствующих материалах.
