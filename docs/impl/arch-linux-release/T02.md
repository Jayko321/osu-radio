# T02. Версия 0.1.0-alpha и About в существующих Settings

Состояние: выполнено; автоматические проверки T02 прошли. Приёмка установленного
About и открытия ссылки в KDE остаётся T06.
Источники: [спецификация, R8/R10](../../specs/arch-linux-release.md),
[план, раздел «Версия и лицензии»](../arch-linux-release.md).
Зависимости: T01 — завершены изменения общих `launch_smoke.rs` и руководств;
повторно сверить обновлённую изоляцию тестовых процессов.

## Результат

Qt-приложение и сервер имеют Cargo-версию `0.1.0-alpha`.
В существующих Settings есть небольшой About: та же версия, MIT и ссылка
`https://github.com/Jayko321/osu-radio`. Раздел участвует в поиске настроек.

  [server Cargo.toml](../../../apps/osu-radio-server/Cargo.toml),
  [Cargo.lock](../../../Cargo.lock): обновить согласованные версии двух приложений
  и соответствующие записи lockfile, не обновляя попутно зависимости/все crates.
- [main.rs](../../../apps/osu-radio-qt/src/main.rs), `run`: установить Qt application
  version из `CARGO_PKG_VERSION` до загрузки QML. Использовать существующую
  CXX-Qt/Qt-интеграцию, при необходимости её
  [runtime bridge](../../../apps/osu-radio-qt/src/runtime.rs) и
  [runtime.h](../../../apps/osu-radio-qt/src/runtime.h).
  QML читает `Qt.application.version`; новый VM/state/протокол не нужен.
- [SettingsPanel.qml](../../../apps/osu-radio-qt/qml/SettingsPanel.qml):
  добавить About в нынешние layout, `matches` и `hasMatches`, сохранив
  поиск по разделам/названиям, отсутствие отступов скрытых секций и empty state.
  Переиспользовать существующие стили и доступность; отдельное окно не требуется.
- [AdapterProbe.qml](../../../apps/osu-radio-qt/tests/AdapterProbe.qml) и

  дополнить существующую проверку Settings либо добавить небольшой согласованный
  probe case. Проверить потребителей поисковых ожиданий и fixtures, чтобы новая
  видимая секция не ломала расчёт пустого состояния/размеров.
- Обновить [frontend](../../agent/frontend.md), релевантные строки
  [development](../../agent/development.md) и
  [test-coverage](../../agent/test-coverage.md) по фактическим изменениям.

Сохранить QSettings organization/application `osu-radio/osu-radio-qt` и все ключи.
Установка метаданных Qt не должна переместить настройки. Gallery остаётся offline,
не запускает сервер и не начинает сохранять пользовательские preferences.
Текст MIT и полные уведомления готовит T03; здесь показывается обозначение лицензии.

## Проверка и приёмка

1. Проверить оба manifests и соответствующие Cargo.lock entries: `0.1.0-alpha`;
   команды с `--locked` не требуют изменения lockfile.
2. Qt probe проверяет непустую `Qt.application.version` и точное значение версии
   в About, обозначение MIT и точную ссылку проекта. Версия UI должна поступать
   из метаданных приложения, а не из второго вручную записанного номера в QML.
3. Поиск по About и текущим названиям его полей показывает ожидаемые строки;
   регистр/окружающие пробелы обрабатываются существующим способом. Несовпадение
   показывает прежний empty state без пустого места, очистка возвращает секции.
   Songs/selection и запросы backend не меняются от поиска Settings.
4. Собрать Qt и выполнить:

   ```sh
   cargo build -p osu-radio-qt --locked
   cargo test -p osu-radio-qt --locked -- --test-threads=1
   bash apps/osu-radio-qt/scripts/lint-qml.sh
   cargo test -p osu-radio-client --lib --locked
   cargo test -p osu-radio-client --features mock --lib --locked
   cargo clippy -p osu-radio-client --features mock -p osu-radio-qt --all-targets --locked -- -D warnings
   cargo fmt -p osu-radio-client -p osu-radio-qt -p osu-radio-server --check
   ```

   QML lint требует debug-сборку с generated imports; учитывать её
   `CARGO_TARGET_DIR`. Для вопросов установки Qt version через CXX-Qt проверить
   текущие API по Context7 процедуре проекта перед реализацией.

Offscreen probe подтверждает свойства/поиск; фактический About в установленном
пакете и открытие ссылки с рабочего стола проверяются в T06.

## Отчёт о выполнении

Выполнено 2026-10-17 в основном чате, без субагентов и коммитов.

### Изменения и соответствие приёмке

- `apps/osu-radio-qt/Cargo.toml`, `apps/osu-radio-server/Cargo.toml` и две
  соответствующие записи `Cargo.lock` теперь содержат `0.1.0-alpha`. Сравнение
  разобранного lockfile с HEAD подтверждает, что зависимости и остальные версии
  не менялись. `cargo metadata --no-deps --locked --format-version 1` успешно
  подтверждает версии обоих приложений.
- `apps/osu-radio-qt/src/main.rs`, `run`: существующий
  `QGuiApplication::set_application_version` получает `CARGO_PKG_VERSION` до
  загрузки QML. `SettingsPanel.qml` читает `Qt.application.version`, второго
  номера версии в production QML нет. Новые bridge/VM/state не потребовались.
- В `SettingsPanel.qml` добавлен About: Version, License — MIT и Project с
  точной ссылкой `https://github.com/Jayko321/osu-radio`. Ссылка использует
  существующий `AppButton` с вариантом `link`, доступным именем и стандартным
  `Qt.openUrlExternally`. Поиск использует текущий `matches`/`hasMatches`:
  About показывает все три строки, имя поля — соответствующую строку.
  Значения и URL не являются именами настроек и в поиск не включаются.
- `AdapterProbe.qml`: существующий `settings-search` проверяет точную версию,
  MIT, URL/доступное имя ссылки и реакцию UI на временную замену Qt metadata
  с последующим восстановлением. Проверены названия секции/полей, смешанный
  регистр, пробелы, отсутствие отступов скрытых секций/строк, прежний empty state
  и очистка. Сохранены проверки Songs/selection, скролла и условного volume.
  `launch_smoke.rs` сохраняет T01-изоляцию БД/XDG и дополнительно запрещает
  POST/DELETE в этом сценарии; существующая проверка запросов Songs проходит.
- Обновлены `docs/agent/frontend.md`, `development.md`, `test-coverage.md`
  и состояние T02 в общем плане.

QSettings остаётся `NativeFormat`/`UserScope`, `osu-radio/osu-radio-qt`, без
fallbacks, с прежними ключами `display/use_unicode_titles`,
`display/use_unicode_artists`, `integrations/discord_rich_presence`.
Код чтения/записи не изменён; изолированные проверки сохранения и ошибок
прошли. Offline gallery не запускает backend и не сохраняет preferences;
соответствующие smoke tests прошли.
