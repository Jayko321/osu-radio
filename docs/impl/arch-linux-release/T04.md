# T04. Комплект Arch-упаковки с установленными путями компонентов

Состояние: выполнено; рецепт проверен на локальном снимке в изолированном
окружении 2026-10-17. Финальный checksum, опубликованный тег и clean chroot — T05;
пользовательская приёмка не заявлена.
Источники: [спецификация, R1/R2/R5/R6/R8/R9](../../specs/arch-linux-release.md),
[план, раздел «Упаковка» и порядок синхронизации](../arch-linux-release.md).
Зависимости: T01 — рабочий Linux startup и изолированные fixtures;
T02 — версии/About; T03 — полный комплект лицензий.

## Результат

`packaging/arch/` содержит PKGBUILD, `.SRCINFO`, `osu-radio.desktop`, короткую
инструкцию и лицензионные материалы. Рецепт собирает три компонента и размещает
их в согласованных системных путях без зависимости от машины разработчика.

## Границы и контекст

Область изменения: новые файлы упаковки, кроме подготовленных T03 лицензий;
необходимые ссылки/команды в [development](../../agent/development.md),
[backend](../../agent/backend.md) и [frontend](../../agent/frontend.md).
Существующих packaging scripts нет; не расширять задачу до CI/AUR/других платформ.

Контракт рецепта из плана:

- `pkgname=osu-radio`, `pkgver=0.1.0alpha`, `pkgrel=1`, `arch=('x86_64')`;
  source — GitHub archive тега `v0.1.0-alpha` проекта Jayko321/osu-radio.
  Финальный SHA-256 получает T05 после появления тега. Предварительный рецепт
  не выдаётся за готовый релиз; `SKIP` не допускается в финальном комплекте.
- Build: `rustup`, `dotnet-sdk-8.0`, `lld`, `pkgconf` поверх `base-devel`.
  Runtime: `glibc`, `libgcc`, `libstdc++`, `alsa-lib`, `qt6-base>=6.8`,
  `qt6-declarative>=6.8`, `qt6-svg`, `qt6-wayland`, `dotnet-runtime-8.0`,
  `xdg-desktop-portal`, `xdg-desktop-portal-impl`.
  Для KDE инструкция называет `xdg-desktop-portal-kde`.
  `optdepends`: `osu` и `osu-lazer-bin` с пояснениями stable/lazer.
  Перед записью перепроверить актуальные официальные Arch metadata и AUR RPC;
  при существенном противоречии согласованному решению вернуть вопрос в план.
- Rust — закреплённый [rust-toolchain.toml](../../../rust-toolchain.toml)
  через rustup, `--locked`, явный LLD. Cargo/rustup/.NET build homes и кэши
  находятся внутри рабочего каталога упаковки; личные toolchain/config/cache
  и уже собранные артефакты не требуются. Не переопределять системный HOME.
- Настоящий helper публикуется из
  [csproj](../../../tools/osu-lazer-realm-parser/osu-lazer-realm-parser.csproj)
  для `linux-x64` с `--self-contained false`.
  В `/usr/lib/osu-radio/` устанавливается весь нужный publish-каталог:
  apphost, DLL, runtimeconfig, deps, управляемые и нативные Realm-зависимости.
  Системный .NET runtime обязателен; встроенный runtime не добавлять.
- В production Rust build задать
  `OSU_LAZER_REALM_PARSER_PATH=/usr/lib/osu-radio/osu-lazer-realm-parser`.
  [scanner build.rs](../../../crates/radio-scanner/build.rs) уже встраивает этот
  путь и пропускает повторный dotnet build; runtime override сохраняется.
  Production Cargo target отделить от тестовых сборок с build-tree helper.
  Существующий механизм поиска helper не переписывать.
- Установить Qt в `/usr/bin/osu-radio-qt`, ссылку `/usr/bin/osu-radio` на него,
  server в `/usr/bin/osu-radio-server`, desktop в
  `/usr/share/applications/osu-radio.desktop`, лицензии T03 в
  `/usr/share/licenses/osu-radio/`. Server собирается с SQLite;
  PostgreSQL и SQLite features вместе не включать. QML/assets уже embedded.
- Desktop: `Name=osu! radio`, `Exec=/usr/bin/osu-radio`, `Terminal=false`,
  `Categories=AudioVideo;Audio;Player;`; без `Icon` и `Path`.
- Инструкция: исходные условия, зависимости и конфликт Arch `rustup`/`rust`,
  первый сетевой restore/toolchain download, `makepkg -si`, обновление,
  пользовательские XDG-пути и сохранение данных. Не вводить install hooks,
  изменяющие пользовательскую БД/настройки, и не требовать osu!/Wine для пакета.

## Проверка и приёмка

1. Сверить все installed destinations и executable permissions в staging tree;
   отсутствуют build/source paths как способ поиска server/helper, Qt assets
   и библиотек. Не путать диагностические пути в бинарнике с runtime-зависимостью.
2. Проверить рецепт и desktop, сгенерировать/сопоставить `.SRCINFO`:

   ```sh
   bash -n packaging/arch/PKGBUILD
   desktop-file-validate packaging/arch/osu-radio.desktop
   makepkg --dir packaging/arch --printsrcinfo
   ```

   Эти режимы присутствуют в локальном makepkg/валидаторе; саму сборку выполнять
   только в подготовленном отдельном окружении. Новые SDK/CLI-параметры и Arch
   приёмы сверять по Context7 и первичной документации согласно guide.
3. При отсутствии опубликованного тега проверить сборочные/package steps
   на временной копии рецепта с локальным архивом подготовленных исходников
   и настоящим checksum. Зафиксировать точный снимок; не менять source финального
   рецепта на ветку, не создавать/публиковать тег и не отмечать R8 выполненным.
4. Подтвердить production/helper build isolation: test target не поставляется;
   пакет включает полный publish и лицензии; рецепт не требует локального
   `.env`, каталогов разработчика или fake-helper. Инструкция не обещает
   успешную финальную сборку до заполнения checksum в T05.
5. Проверить Markdown links существующим repository check и обновлённые
   команды по реальным файлам. Результаты T04 — проверка рецепта/материалов;
   clean chroot, package dependency analysis и установленный сценарий — T05/T06.

### Точный локальный снимок и сборка

Рабочие артефакты и журналы находятся в `target/arch-t04/` (ignored).
Архив содержит **375** файлов, перечисленных с SHA-256 в `snapshot.json`;
исходники продукта соответствуют рабочему дереву после T01–T03.

- `osu-radio-0.1.0-alpha.tar.gz`:
  `5a62465c0ed6c2f8621a0484e8fef3a82d51465a40c69a405fc8ac0124e25169`.
- Cargo.lock:
  `7e81151b2d684cedd01a22a9430205f7a06a3fa5a475809b4addb0a4495fe870`.
- Финальный PKGBUILD:
  `8baf32a2f4cdda3d1491c2e9750d024860693b07c20ed553fef76c17c490e498`.
- Временный проверенный PKGBUILD:
  `4e83057fd0bafc06e861c0f75dd8b557f54f3d4f52010a965b4844833429aee4`.
  Assert подтвердил, что он отличается от итогового только локальным source
  и настоящим checksum архива. Исходники приложения в архиве не подменялись.

Сборка выполнялась через Bubblewrap: root filesystem read-only, личный `/home`
скрыт, рабочий каталог доступен как `/tmp`. Использован отдельно распакованный
официальный SDK **8.0.426** из проверки T03, смонтированный read-only как `/opt`;
это сборочный инструмент, не готовый helper/publish. Cargo/rustup/NuGet кэши
изначально пусты; Rust **1.98.0** и зависимости скачаны заново.

Первый `makepkg --nodeps --nocheck --noconfirm` установил Rust, но остановился
на mutex .NET `NuGet-Migrations` в ограниченном namespace. После подготовки
приватных `.dotnet/shm` directories и пустого временного home (личные файлы
по-прежнему скрыты) повторный `makepkg --noextract --nodeps --nocheck --noconfirm`
завершился с **exit 0**, без изменения build-команд рецепта.
`--nodeps` использован только для этой временной проверки: SDK 8 предоставлен
из отдельного каталога, а не зарегистрирован как системный Arch SDK package.
Это не clean chroot и не проверка пакетного разрешения зависимостей T05.
`--nocheck` не заменяет проектную suite; рецепт не определяет `check()`.

Получен `target/arch-t04/osu-radio-0.1.0alpha-1-x86_64.pkg.tar.zst` (~15 MiB),
SHA-256 `1a6427818b3d91d2d2e20d3b31a1fa62d2b6923b3a4f64ebdf03d000c39e02a2`.
Это пакет **локального снимка**, не опубликованного релиза.
