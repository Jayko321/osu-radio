# T01. Linux-запуск без настройки БД и без зависимости от `.env`

Состояние: выполнено; автоматические проверки Linux пройдены.
Пользовательская приёмка установленного релиза остаётся T05/T06.
Источники: [спецификация, R3/R9 и сохранённые границы](../../specs/arch-linux-release.md),
[план, разделы 2 и 4](../arch-linux-release.md).
Зависимости: нет.

## Результат

На Linux сервер с SQLite без явного `SQLITE_DATABASE_URL` создаёт и открывает
`$XDG_DATA_HOME/osu-radio/osu-radio.db`; отсутствующий, пустой или относительный
XDG переключает путь на `$HOME/.local/share/osu-radio/osu-radio.db`.
Родительский каталог создаётся автоматически. Явный URL сохраняет приоритет.
Дочерний сервер, запущенный клиентом на Linux, получает
`OSU_RADIO_SKIP_DOTENV=1` и пропускает чтение `.env`.

## Границы и контекст

Область изменения:

- [config.rs](../../../apps/osu-radio-server/src/config.rs):
  `ServerConfig::from_env`, выбор пути, создание только стандартного каталога,
  существующее распространение ошибок. Никакого fallback в PostgreSQL;
  новый Windows-путь не вводится. Не менять семантику явных SQLite URL,
  включая `:memory:` и ошибку отсутствующего родителя явно заданного файла.
- [server.rs](../../../crates/osu-radio-client/src/server.rs):
  `EmbeddedServer::start_cancellable`, Linux env дочернего процесса;
  актуализировать устаревший совет обязательной `.env` в `ServerError::Exited`
  и проверяющий его unit test. Поиск binary, readiness, shutdown и владение
  процессом сохраняются; remote-сессия по-прежнему не запускает сервер.
- [config tests](../../../apps/osu-radio-server/src/config/tests.rs) и
  [startup tests](../../../apps/osu-radio-server/tests/startup.rs):
  использовать существующий subprocess-подход; прежние ожидания обязательного
  URL на Linux/SQLite заменить проверкой стандартного пути. Standalone сохраняет
  загрузку `.env`, приоритет process env и ошибки разбора/чтения; пропуск
  включается именно значением `1` согласованного переключателя.
- [embedded_server.rs](../../../crates/osu-radio-client/tests/embedded_server.rs),
  [Qt launch_smoke.rs](../../../apps/osu-radio-qt/tests/launch_smoke.rs),
  [queue_backend.py](../../../apps/osu-radio-qt/tests/fixtures/queue_backend.py),
  его [client consumer](../../../crates/osu-radio-client/src/playback/tests/real_backend.rs).
  Обычный Qt test runner удаляет URL из env, queue wrapper тоже их удаляет,
  а реальные БД/путь fake-helper пока задаются через `.env`. Обновить все эти
  запуски согласованно: каждый дочерний процесс явно получает приватные пути
  и настройки. Сохранить одну и ту же fixture-БД при prepare/Qt/client/verify,
  restart и test-only SQL; не читать пользовательские данные.
- Обновить затронутые описания запуска/команды в
  [backend](../../agent/backend.md), [development](../../agent/development.md)
  и [frontend](../../agent/frontend.md); в [database](../../agent/database.md)
  уточнить только отличие server fallback от CLI, если затронуто описание URL.

Выбор пути остаётся в серверной конфигурации. Существующие
`radio-db` file creation, `AppState::connect`, миграции и запрет неявного reset
переиспользуются. Схема БД, HTTP/NDJSON, VM, QSettings и хранение аудио не меняются.
До редактирования повторно найти вызывающие места и env/`.env` fixtures.

## Проверка и приёмка

1. Изолированные subprocess cases с приватными HOME/XDG и cwd: стандартный путь,
   абсолютный XDG, пустой/относительный XDG, явный URL, пробелы в пути;
   при невозможности определить fallback или создать каталог — ошибка через
   существующий путь обработки и отсутствие readiness. Для ошибки записи
   использовать детерминированный конфликт «файл вместо каталога», пригодный
   и при запуске тестов с расширенными правами.
2. Реальный сервер создаёт БД, сохраняет fixture-данные, закрывается и читает
   их повторно. В cwd база не появляется; рабочая БД разработчика не открывается.
   Явный URL не создаёт побочный XDG-каталог. PostgreSQL без URL остаётся ошибкой;
   Windows не получает новый Linux fallback.
3. Embedded launch игнорирует валидную, повреждённую и нечитаемую `.env` в cwd
   и родительском каталоге; standalone без переключателя сохраняет прежние
   dotenv-тесты, а process env имеет приоритет. Remote test использует
   отсутствующий local binary, не запускает/не останавливает remote server.
4. Выполнить применимые команды из матрицы проекта:

   ```sh
   cargo test -p osu-radio-server --locked
   cargo test -p osu-radio-server --no-default-features --features sqlite --locked
   cargo test -p osu-radio-server --no-default-features --features postgres --locked config::tests::
   cargo test -p osu-radio-client --lib --locked
   cargo test -p osu-radio-client --features mock --lib --locked
   cargo build -p osu-radio-server -p osu-radio-qt --locked
   env -u SQLITE_DATABASE_URL -u POSTGRES_DATABASE_URL cargo test -p osu-radio-client --test embedded_server --locked -- --ignored
   cargo test -p osu-radio-qt --locked --test launch_smoke real_backend_ -- --ignored --test-threads=1
   cargo test -p osu-radio-client --lib --locked real_server_queue_and_fake_engine_preserve_launches_across_edits_and_reimport -- --ignored
   python3 -B -m unittest discover -s apps/osu-radio-qt/tests -p 'test_*.py' -v
   ```

   Qt real-backend и client queue probes ожидают debug-сервер в существующих
   местах из исходников; при отдельном target-каталоге согласовать пути fixtures.
   Проверки с build-tree helper отделять от будущей production-сборки.
5. Выполнить formatting и scoped Clippy для изменённых server/client/Qt,
   server docs on/off и PostgreSQL отдельно по
   [матрице](../../agent/development.md#verification-matrix).
   Обновить [инвентарь проверок](../../agent/test-coverage.md) новыми фактическими
   свидетельствами и ограничениями.

Это проверки приватных процессов/БД; fake Realm и fake audio engine в queue
fixtures не подтверждают настоящий импорт lazer, KDE или физический звук.
Эти критерии остаются T05/T06. Новые SDK/API-вопросы исследовать по Context7
процедуре проекта; архитектурные расхождения возвращать в `$impl-plan`.

## Отчёт о выполнении

Выполнено 2026-10-17 в основном чате, без субагентов и коммитов.

### Изменения и сверка приёмки

- [config.rs](../../../apps/osu-radio-server/src/config.rs): Linux/SQLite при
  отсутствующем URL выбирает абсолютный XDG-путь либо HOME fallback и создаёт
  только стандартный родительский каталог. Явные URL сохраняют приоритет;
  PostgreSQL и платформы вне Linux не получают fallback. Ошибки определения
  пути/создания каталога идут через существующий `anyhow`/startup exit.
- [config tests](../../../apps/osu-radio-server/src/config/tests.rs): subprocess
  cases проверяют отсутствующий/пустой/относительный XDG, абсолютный XDG в том
  числе без HOME, пути с пробелами, отсутствующий/пустой/относительный HOME,
  детерминированный конфликт файла и каталога, приоритет URL без побочного
  XDG-каталога. Только process switch `1` отключает dotenv; `0`, `true`, `01`
  и пустое значение сохраняют загрузку. Прежние standalone precedence,
  parse/read-error tests сохранены.
- [startup tests](../../../apps/osu-radio-server/tests/startup.rs): реальный сервер
  создаёт private SQLite при четырёх вариантах XDG, сохраняет зарегистрированную
  fixture-папку и читает её после повторного запуска. Проверяются отсутствие БД
  в cwd, сохранность исходного marker и отсутствие readiness при ошибке каталога.
  Явный путь с отсутствующим родителем по-прежнему завершается ошибкой без
  создания родителя или побочного XDG-каталога; in-memory startup сохранён.
- [client server.rs](../../../crates/osu-radio-client/src/server.rs): Linux child
  получает `OSU_RADIO_SKIP_DOTENV=1`; из `ServerError::Exited` удалён устаревший
  совет обязательной `.env`, ожидания unit test обновлены.
- [embedded test](../../../crates/osu-radio-client/tests/embedded_server.rs):
  отдельный subprocess очищает наследуемую конфигурацию, получает приватные
  HOME/XDG и проверяет запуск без URL, сохранение данных и шесть `.env` cases
  (валидный, malformed, invalid UTF-8 в cwd/parent). Внешнее значение skip=`0`
  переопределяется supervisor. Remote-сессия с отсутствующим local binary
  работает; её shutdown/drop оставляют исходный сервер доступным.
- [Qt smoke runner](../../../apps/osu-radio-qt/tests/launch_smoke.rs) передаёт
  приватный абсолютный SQLite URL и XDG; прежние `.env` fixtures удалены.
  [queue_backend.py](../../../apps/osu-radio-qt/tests/fixtures/queue_backend.py)
  использует один набор абсолютных путей для prepare/verify и генерируемого
  wrapper, включая fake Realm helper и skip-dotenv. Test-only SQL, оба Qt запуска,
  reimport и restart работают с той же `library.sqlite`.
  [Client consumer](../../../crates/osu-radio-client/src/playback/tests/real_backend.rs)
  дополнительно проверяет наличие этой БД, отсутствие `.env` и побочного XDG.
- При повторном поиске callers найден устаревший комментарий
  [controller benchmark](../../../crates/osu-radio-client/src/controller/benchmarks.rs):
  он и соответствующая команда руководства теперь требуют явно передать URL
  disposable backup вместо расчёта на dotenv дочернего Linux-сервера.
- Обновлены [backend](../../agent/backend.md), [development](../../agent/development.md),
  [frontend](../../agent/frontend.md), отличие server/CLI в
  [database](../../agent/database.md) и [инвентарь проверок](../../agent/test-coverage.md).
  Общая схема/миграции, HTTP, VM и владение процессом не изменялись.

### Окружение, ограничения и передача

- Первые server/Python запуски внутри песочницы получили запрет loopback sockets
  (`Operation not permitted`). Успешные process/socket проверки выполнены вне
  неё; private paths/БД и явные discovery markers сохранены.
- Первая попытка Clippy вызвала автоматическую сборку helper и обнаружила
  `MSB4242`: у локального .NET SDK 10.0.113 отсутствуют workload manifests
  `10.0.112.1`. Системный SDK не исправлялся. Последующие Rust build/test/lint
  использовали предусмотренный build script override:

  ```sh
  export OSU_LAZER_REALM_PARSER_PATH=/home/jayko/Code/Rust/osu-radio/target/debug/build/radio-scanner-4f9dff0c1b4c1c6b/out/dotnet-helper/osu-lazer-realm-parser
  ```

  Это build-tree helper для проверок T01, не установленный production helper
  и не доказательство чистой сборки. В queue probes Realm producer и audio
  engine заменены fixtures. Их прохождение не подтверждает реальный lazer/звук.
- Windows runtime, чистый Arch chroot, установленный пакет без build tree,
  KDE/реальные stable/lazer, физический звук и обновление/переустановка не
  проверялись: остаются T05/T06. Отсутствие Windows fallback подтверждено
  условием компиляции в исходнике, не native Windows запуском.
- Общая repository documentation suite не заявляется пройденной: её ранее
  найденная несогласованность с пользовательским versioned `docs/impl/`
  описана в разделе 7 общего плана и не исправлялась в T01. Line coverage
  повторно не измерялся.
- Предшествующие изменения `.gitignore`, `.serena/project.yml`, спецификации
  и документов сохранены. Появившиеся параллельно `LICENSE`, `packaging/`
  и изменения `apps/osu-radio-qt/assets/SOURCES.md` не редактировались в T01.
- Зависимость T02 закрыта: изменения общих Qt smoke tests и руководств завершены.
  T02 и следующие карточки не выполнялись; пользовательская приёмка релиза
  не отмечалась. Расхождений с утверждённым runtime-решением T01 не обнаружено.
