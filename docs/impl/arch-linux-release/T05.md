# T05. Сборка опубликованного тега в чистом Arch и автономность пакета

Состояние: выполнено; опубликованный источник, clean Arch chroot, состав,
зависимости и установленный Qt/server/настоящий helper проверены.
Ограничение native Realm по FULL RELRO разобрано ниже; пользовательская
приёмка KDE/библиотек/звука остаётся T06.
Источники: [спецификация, R1/R2/R5/R6/R8](../../specs/arch-linux-release.md),
[план, разделы 2, 4 и 6](../arch-linux-release.md).
Зависимости: T04 — готов рецепт и материалы; внешний вход — опубликованный
по отдельному поручению тег `v0.1.0-alpha`, содержащий необходимые результаты
T01–T03 и исходники, используемые рецептом T04.

## Результат

В финальном PKGBUILD/.SRCINFO записан реальный SHA-256 архива тега.
Пакет собирается в чистом Arch chroot без личных кэшей/настроек и работает
в отдельном окружении установки после удаления исходников и build tree.
Есть доказательства состава, зависимостей, версий и работоспособности
настоящего установленного помощника lazer.

## Границы и контекст

Область изменения: финальные source checksum и `.SRCINFO` в `packaging/arch/`,
обнаруженные локальные дефекты рецепта, фактические результаты в этой карточке,
релевантные [development](../../agent/development.md) и
[test-coverage](../../agent/test-coverage.md).
Публикация/перемещение тега, push, GitHub Release и AUR не входят в задачу.
Если исходный тег не содержит необходимых исправлений, запросить отдельное
решение выпуска; не патчить молча tag archive до другого состояния.

Сначала проверить готовность внешнего входа. Без него можно подготовить
chroot/инструменты и провести предварительную локальную сборку, но финальные
R1/R8 и статус карточки остаются непроверенными. Рецепт с вычисленным checksum
может поставляться отдельно от неизменяемого исходного тега, см. раздел 6 плана.
Не требовать checksum того же архива внутри его собственного содержимого.

Среда: чистый Arch x86_64 chroot; отдельное окружение установки;
сетевой доступ для исходников/dependencies; private data/config/cache paths.
`devtools`, `namcap`, `mkarchroot`, `makechrootpkg` не обнаружены при декомпозиции;
подготовка проверочного окружения входит сюда. Конкретные команды брать из
текущей документации Arch/Context7, не объявлять отсутствующий инструмент
доступным. Не устанавливать экспериментальный пакет поверх рабочего профиля.

## Проверка и приёмка

1. Скачать точный archive опубликованного тега проекта, записать commit/tag,
   source URL и SHA-256. Зафиксировать checksum в PKGBUILD, пересоздать `.SRCINFO`
   через `makepkg --dir packaging/arch --printsrcinfo` и сопоставить поля.
   `makepkg --dir packaging/arch --verifysource` проходит; испорченный архив
   отклоняется проверкой целостности в отдельной временной копии.
2. Собрать без личных Cargo/rustup/NuGet caches, `.env` и предварительных
   артефактов, по инструкции T04, внутри чистого Arch chroot. Runtime/build
   dependencies должны разрешиться через объявленные metadata;
   пакеты osu!/Wine не установлены. Зафиксировать toolchain и версии пакетов.
3. Проанализировать готовый пакет доступными средствами Arch, включая `namcap`,
   список файлов и зависимости ELF/native Realm. Проверить Qt plugins/QML,
   системный .NET runtime, desktop, symlink и все лицензии T03.
   Разобрать существенные замечания; один успешный exit build не закрывает их.
   В metadata osu!/lazer только `optdepends`, с актуальными пояснениями.
4. Установить пакет в отдельную среду с runtime dependencies. Сделать исходники,
   helper publish/build tree и Rust target недоступными; удалить build-time
   overrides. Из произвольного cwd стартовать установленный server с private
   XDG и loopback ephemeral address: readiness, создание БД и штатное завершение.
   Запустить установленный Qt на совместимом display/offscreen для проверки
   загрузки системных plugins; реальное меню/звук остаются T06.
5. Настоящий `/usr/lib/osu-radio/osu-lazer-realm-parser` должен загрузить
   framework и Realm native library без SDK и без build tree. Вызов help или
   ошибка отсутствующего аргумента этого не доказывает: нужен разбор приватной
   валидной Realm fixture установленным helper. Использовать существующий
   [fixture generator](../../../tools/osu-lazer-realm-parser/fixture-generator/fixture-generator.csproj)
   и [описание real-helper checks](../../../tools/osu-lazer-realm-parser/README.md).
   Fixture подготовить до удаления исходников и перенести отдельно; stdout —
   ожидаемый NDJSON, диагностика — stderr, source-файлы не изменились.
6. Убедиться, что сборка идёт из зафиксированного тега: подготовленное отдельно
   dirty checkout/текущая ветка не влияют на результат. Проверить версии двух
   приложений и пакетную версию `0.1.0alpha-1`, сохранить путь/хэш пакета для T06.
7. Если исправляется рецепт, повторить затронутые проверки и clean build до
   передачи конечного артефакта. Если обнаружено изменение поведения/состава
   вне плана, вернуть конкретное расхождение в `$impl-plan`.

Офлайн-галерея и минимальная Realm fixture не заменяют пользовательский импорт
stable/lazer и физический звук. Для передачи T06 нужны именно проверенный
пакет и доказательства R1/R2/R5/R6/R8, а не только локально собранные бинарники.

### Итог и оставшиеся границы

Критерии 1–7 T05 выполнены в описанном объёме; namcap warning partial RELRO
остаётся известным ограничением поставляемой native Realm. Ссылки/UTF-8/fences
изменённых документов, Bash/desktop/SRCINFO и whitespace checks прошли.
Исходный тег не перемещался и не патчился; финальный checksum-рецепт поставляется
отдельно от source tag по разделу 6 плана. GitHub Release/AUR не публиковались.

**T06 получает указанный пакет и SHA-256.** Реальные KDE menu/picker,
пользовательские stable/lazer библиотеки, физический звук, About/URL в KDE,
update/reinstall и сохранность пользовательского профиля остаются T06.
Полная Rust suite/Clippy не повторялись: продуктовые исходники совпали с T04;
выполнены scoped package/runtime checks. Проверки на синтетической Realm
и offscreen display не являются пользовательской приёмкой релиза.
