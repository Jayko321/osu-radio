# T06. Итоговая приёмка релиза в реальной KDE-сессии

Состояние: частично проверено 2026-10-17; native KDE/lazer/playback/XDG,
restart/upgrade/reinstall проверены в описанном ниже объёме. Меню KDE,
stable, завершённый native picker и подтверждение слышимого звука остаются открытыми.
Пользовательская приёмка не получена.
Источники: [спецификация, сценарий и приёмка R1–R10](../../specs/arch-linux-release.md),
[план, раздел 4 и таблица покрытия](../arch-linux-release.md).
Зависимости: T05 — проверенный пакет из опубликованного тега, его хэш,
результаты clean build/installed helper и окончательная инструкция.

## Результат

Проверен весь пользовательский путь «собрал → установил → открыл из меню →
добавил osu! → слушаешь». Установленное приложение сохраняет данные/настройки
при закрытии, повторном запуске, обновлении и переустановке; исходники osu!
не меняются. Фактические результаты и оставшиеся ограничения перенесены
в спецификацию без подмены реальной приёмки тестами с заменами.

## Границы и контекст

Это карточка интеграционной проверки, не новый этап проектирования.
Область изменения: отчёт здесь, фактическое состояние
[спецификации](../../specs/arch-linux-release.md), необходимые уточнения
[backend](../../agent/backend.md), [frontend](../../agent/frontend.md),
[development](../../agent/development.md),
[database](../../agent/database.md) и [test-coverage](../../agent/test-coverage.md)
только по затронутым контрактам и реально полученным свидетельствам.
Не переписывать архитектуру, не добавлять onboarding, иконку, MPRIS,
single-instance или новый diagnostic UI.

Нужны реальная KDE-сессия, рабочий аудиовыход и private user profile,
тестовые копии stable/lazer с воспроизводимыми треками и известными исходными
файлами/хэшами. Установки выбирать по явным путям через существующий UI;
не запускать неограниченное discovery по дискам. Исходники и build tree
из T05 недоступны, runtime overrides удалены. Рабочая БД и настройки
разработчика не используются. Дополнительно требуется приватный профиль
с переопределёнными абсолютными XDG data/config/cache paths.

## Проверка и приёмка

1. Сверить пакет/хэш с T05 и следовать инструкции установки. В обычном чистом
   профиле без `.env` и переменных настройки osu! radio найти `osu! radio`
   в аудиокатегории меню KDE. Запуск не открывает терминал. Повторить запуск
   через `/usr/bin/osu-radio` из произвольного cwd без исходников.
   Автоматически запускается принадлежащий клиенту server, появляется
   `$HOME/.local/share/osu-radio/osu-radio.db` при отсутствующем XDG_DATA_HOME.
2. Через существующий UI отдельно добавить stable и lazer, применить импорт,
   дождаться библиотеки, явно выбрать Play и услышать воспроизведение через
   физический выход. В обоих случаях подтвердить чтение установленными
   компонентами. Повторить с вручную размещённой установкой osu!,
   не зарегистрированной pacman/AUR. Проверить контрольные хэши/состав
   исходных файлов до и после импорта/воспроизведения; запись в osu! не допускается.
3. Проверить folder picker с настоящим KDE portal, видимость и поиск About,
   версию `0.1.0-alpha`, MIT и ссылку проекта. Проверить открытие ссылки
   стандартным браузером и доступность элементов с клавиатуры.
4. Изменить существующие preferences и запомнить библиотеку/зарегистрированные
   папки. Закрыть приложение обычным способом: дочерний server завершился,
   временные аудиофайлы, созданные этим запуском, очищены. Повторный запуск
   сохраняет библиотеку и настройки, повторный ручной импорт не требуется.
5. В другом приватном профиле задать абсолютные XDG_DATA_HOME,
   XDG_CONFIG_HOME и XDG_CACHE_HOME. Проверить размещение БД, QSettings и
   создаваемого кэша; отсутствуют записи в cwd, `/usr` и чужой профиль.
   Логи проверяются, только если существующий механизм их создаёт;
   новый журнал для этого не добавлять. QSettings сохраняет прежние
   organization/application и ключи. Пустой/относительный XDG_DATA_HOME
   уже покрыт T01; это не доказательство поведения иных XDG-переменных.
6. С сохранёнными данными выполнить обновление пакета, затем отдельно
   переустановку и снова запустить приложение: библиотека и preferences
   сохранены, обычный startup не выполняет reset. Для воспроизводимого
   upgrade-path подготовить в этой же приватной среде предыдущую упаковочную
   ревизию с теми же согласованными исходниками и меньшим pkgrel, затем
   обновить до финального пакета T05. Явно записать, что это проверка
   пакетного обновления alpha, а не миграция с несуществовавшего старого релиза.
   Подготовительная ревизия не публикуется и не меняет финальный pkgrel=1.
7. Свести R1–R10: использовать реальные свидетельства T05 для clean build,
   тега, зависимостей и лицензий; реальные результаты этой карточки —
   для KDE, импорта/звука, XDG и сохранности данных. Для каждого требования
   указать выполнено/не проверено/обнаружено расхождение и основание.
   Внести существенные факты и ограничения в спецификацию и affected guides.

Если недоступны KDE, реальный звук, библиотеки или upgrade environment,
сохранить соответствующие критерии непроверенными. Не считать карточку
или весь релиз принятыми по одному Cargo build, offscreen gallery либо
подменённому Realm producer. Дефекты возвращать в соответствующую карточку;
существенные изменения решения — в `$impl-plan` с нужными повторными проверками.

## Отчёт о выполнении

### Пакет, окружение и изоляция

Проверен пакет T05 `target/arch-t05/osu-radio-0.1.0alpha-1-x86_64.pkg.tar.zst`,
SHA-256 **`ba4221bd7f1d4dab0ebed2024705a89ae245bf990d640b19af5dfebbe6ffb608`**.
Хэш пересчитан и совпал с T05; исходный тег/пакет не изменялись.
Все дополнительные артефакты этой проверки — в `target/arch-t06/`.

Использованы установленный runtime root T05, реальная KDE Wayland
(KWin **6.7.5**, Qt **6.12.0**) и аудиовыход **Xonar U7 MKII Analog Stereo**.
`bwrap` предоставляет приложению установленную файловую систему только для
чтения, приватные HOME/cwd и temp, доступ к действующим display/portal/audio
сокетам. Внутри запускаются `/usr/bin/osu-radio` и установленный server;
исходники, build tree, SDK и рабочая БД разработчика недоступны. Это не offscreen,
галерея, smoke probe или mock backend. На хост пакет не устанавливался.

Первый запуск использовал `env -i`, без `.env`, XDG data/config/cache overrides
и переменных настройки osu! radio. Для последующих UI-действий включена только
per-process Qt accessibility; действия выполнялись через реальные AT-SPI controls.
Глобальная accessibility KDE временно включалась для native picker и возвращена
в исходное **IsEnabled=false**. Это не проверка физических клавиш Tab/Space.
Документация изоляции и KWin проверена через Context7 и
[KWin API](https://develop.kde.org/docs/plasma/kwin/api/).

### Результаты шагов 1–6

1. **Частично.** Из `/checks/away` открылось реальное установленное Qt-окно,
   клиент автоматически запустил server, создана
   `/home/tester/.local/share/osu-radio/osu-radio.db` без XDG_DATA_HOME.
   В cwd БД не появилась; терминальное окно приложение не создаёт.
   Свидетельства: `logs/default-first.stdout`, `default-first.png`,
   `real-playback.json`. Реальное меню KDE не проверено: существующая Plasma
   работает с профилем хоста, а пакет установлен в отдельном root. Наличие
   desktop-файла и его проверка T05 не засчитаны за запуск из меню.
2. **Lazer проверен частично; stable не проверен.** По уточнению пользователя
   «сканнером найди» выполнен scanner с явными корнями: HOME shallow,
   `.wine` full, `/run/media/jayko` shallow и full с фильтром stable; дополнительно
   shallow по двум найденным пользовательским дискам. Логи `discovery-*.json`.
   Найден `/home/jayko/.local/share/osu/client.realm`; stable не найден.
   Это не утверждение об отсутствии stable во всех каталогах машины.

   Для проверки создана **копия** настоящего Realm (reflink) в
   `target/arch-t06/fixtures/lazer/client.realm`, затем скопированы исходные файлы
   двух наборов triangles. Это сокращённая тестовая копия реальной библиотеки:
   полный metadata snapshot, но только 12 media/map files; остальные audio
   намеренно отсутствуют. Сам helper не открывал оригинальный Realm.
   Установленный helper экспортировал **13 115** NDJSON records; через штатные
   Settings → Add folder → Add → Apply импортированы **13 115 наборов,
   53 799 карт, 37 728 metadata rows**. Импорт сохранил одну зарегистрированную
   папку; библиотека пережила закрытие и повторные запуски без реимпорта.

   В Songs явно выбраны **triangles — cYsmix**, difficulty **peppy**, и Play.
   Реальная очередь: `mode=playing`, `current_entry_id="3"`, available,
   successful-start listening date; UI показывает Pause. PipeWire подтвердил
   активные FL/FR связи **PipeWire ALSA [osu-radio-qt] → Xonar playback**
   (`logs/real-playback.json`, `playback-pipewire-final.txt`). Подтверждения
   человека, что звук слышен из физического выхода, пока нет.

   Первая попытка выбрала другой одноимённый набор без скопированного audio и
   корректно получила unavailable. Его реальные media затем добавлены в копию;
   изменения fixture самим harness отражены отдельным baseline
   `lazer-before-playback.json`. Первоначальные три файла после импорта совпали
   с `lazer-before.json`; все **13 файлов** конечной fixture и соответствующие
   оригинальные файлы osu! совпали по SHA-256 после playback
   (`logs/lazer-after.json`). Новые файлы в fixture не появились.

   В минимальном root T05 отсутствовал desktop ALSA plugin: без него playback
   дал `Unknown PCM default`. В root добавлен установленный на хосте
   **pipewire-alsa 1:1.6.9-1** с 18 зависимостями из подписанного системного cache,
   с частным Arch keyring T05. Финальный playback прошёл без ALSA ошибок.
   Это подготовка desktop audio environment, не изменение PKGBUILD/зависимостей
   приложения. Логи — `desktop-audio-setup-final.log`, `default-third.stderr`.
   Вручную размещённая тестовая копия не зарегистрирована в pacman;
   отдельного импорта реальной stable-установки нет.
3. **Частично; обнаружен сбой окружения.** Настоящий KDE folder picker открылся
   (`logs/kde-picker.png`), однако попытка управлять его полем через AT-SPI
   закончилась disconnect: journal в **23:10:42 MSK** зафиксировал
   **SIGSEGV/core-dump xdg-desktop-portal-kde**, также crashes kioworker.
   Выбор папки через portal не завершён и не засчитан. Импорт выполнен из
   candidate, найденного существующим discovery в изолированном root.
   `logs/kde-picker-journal.txt` сохраняет сбой; причина падения portal
   не установлена, дефектом osu! radio это не объявляется. Повторная ручная
   проверка исправного KDE portal остаётся обязательной.

   About и case-insensitive поиск реально отображают **0.1.0-alpha**, **MIT** и
   правильный URL (`logs/installed-about.png`). Project получает accessibility
   focus; его активация отправила настоящий **OpenURI** с URL проекта
   (`logs/project-openuri.txt`). Загрузка страницы в стандартном браузере
   и физическая клавиатурная навигация не подтверждены.
4. **Проверено в указанном объёме.** Через UI включены Unicode titles/artists;
   настройки записаны в прежние `display/use_unicode_*` ключи
   `osu-radio/osu-radio-qt.conf`. После restart библиотека/папка сохранены.
   Нормальное Close window завершило Qt с exit 0 и удалило принадлежащий ему
   server. Для audio cleanup сохранён открытый fd каталога temp: до close был
   `.tmphvuAoI`, после close его нет, хотя сам mount доступен через fd.
   Это отличает удаление клиентом от исчезновения temp namespace.
   Свидетельство — `logs/normal-close-cleanup.json`.
5. **Проверено для абсолютных XDG.** Второй профиль с абсолютными
   `/checks/t06/{data,config,cache}` создал БД в data, прежний QSettings-файл
   в config и реальный **Mesa shader cache** в cache. HOME и cwd остались
   без файлов; runtime `/usr` read-only. Отдельная библиотека пуста и не
   заимствует первый профиль. Обе preferences после второго запуска восстановлены
   checked в native UI (`logs/xdg-layout.json`, `xdg-restored-ui-state.json`).
   Runtime logs приложения в файлы не создавались; test stdout/stderr сохраняет
   harness. Пустой/относительный XDG config/cache здесь не проверялся.
6. **Проверено для упаковочной ревизии alpha.** Из готовых исходников/build T05
   штатный `makepkg --repackage` подготовил только для теста
   **`0.1.0alpha-0.1`**, без изменения окончательного pkgrel=1.
   Все установленные файлы совпали побайтово с финальным пакетом
   (`logs/repackage.log`, `upgrade-payload-check.txt`). В приватном root выполнены
   подготовительная установка меньшей ревизии, её запуск, затем реальное
   `pacman -U` **0.1.0alpha-0.1 → 0.1.0alpha-1**, запуск, отдельная переустановка
   **0.1.0alpha-1 → 0.1.0alpha-1** и повторный запуск.

   Полные row hashes **12 persisted tables**, включая зарегистрированные папки,
   библиотеку, tags, audio settings, playlists и migrations, плюс байты QSettings
   совпали с исходным baseline. Это больше, чем сравнение количества строк.
   Очередь/history исключены: их runtime state закономерно меняется при recovery.
   Первая версия harness ошибочно включала `playback_queue`; после выявления
   штатного изменения её revision сравнение исправлено, исходный baseline
   сохранён в `profile-stable.json`, library baseline выведен из него.
   Финальные свидетельства — `logs/library-baseline.json`,
   `profile-after-upgrade-start.json`, `profile-after-reinstall.json`,
   `profile-after-reinstall-start.json`, `upgrade-final.log`, `reinstall-final.log`.
   Это не проверка миграции с ранее выпущенного релиза; прежняя ревизия
   не публиковалась. Финальный root содержит исходный пакет T05.

### Изменения и открытые проверки

Код приложения, schema, протоколы, рецепт и лицензии не менялись. Обновлены эта
карточка, таблица общего плана, фактическое состояние спецификации и относящиеся
к результатам разделы frontend/development/test-coverage. Прежние пользовательские
изменения сохранены. Вспомогательные harness/fixtures/logs остаются под `target/`.

**T06 и релиз целиком не приняты.** Нужны native menu с отдельным KDE-профилем,
реальная stable-библиотека, повторная проверка picker без сбоя KDE portal,
браузер/физическая клавиатура и подтверждение слышимого звука. Запрос подтверждения
звука отправлен пользователю; положительный ответ не предполагается автоматически.
Windows не проверялась. Cargo suites/Clippy не повторялись: продуктовые исходники
не менялись; выполнялась проверка установленного пакета.
