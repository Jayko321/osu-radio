# Обновление UI Qt: план реализации

Статус: решения согласованы пользователем, в том числе по mute и фокусу
поиска; подготовлены карточки T01–T19. Все карточки выполнены, ожидают ручной приёмки
(список в [отчёте T19](ui-refresh/T19.md#отчёт-о-выполнении)).
Состояние каждой карточки указано в таблице ниже.

## Источник и цель

Отдельной спецификации нет. Источником служат ревизия UI и интерактивный
предпросмотр, согласованные с пользователем. Предпросмотр сохранён как
[preview.html](ui-refresh/preview.html): откройте файл в браузере, это окно
приложения в натуральных размерах с переключателем «Сейчас / После» для каждого
изменения. Решения ниже важнее предпросмотра, если они расходятся.

Цель: привести Qt-интерфейс (`apps/osu-radio-qt/qml`) к единому виду: единые
меню и попапы, переходы вместо мгновенных появлений, обратная связь и
подтверждение опасных действий, улучшенные списки, плеер, очередь и настройки.
Это презентационная работа в QML. Границы клиента, адаптеров и сервера
не меняются, кроме двух явно названных мест (T13: роль секции очереди, T12: mute).

## Согласованные решения

Принято пользователем (в скобках то, что он уточнил):

1. **Анимации.** Все поверхности получают короткие переходы; значения в T01 и T04.
   Подсказок с горячими клавишами в меню нет. Настройки «Reduce motion» нет;
   есть только внутренний флаг `Theme.motion`.
2. **Меню.** Один `AppContextMenu` и один `AppMenuItem`, одна поверхность попапов
   (`Theme.popup`) с тенью. Выпадающие списки (`AppMenu`) без затемнения окна.
3. **Меню трека:** Play, Add to end, Play next, разделитель, Add to playlist…
   В меню трека плейлиста дополнительно красный Remove from playlist.
4. **Карточка плейлиста:** правый клик открывает то же меню, что «⋮»;
   глиф «⋮» заменяется SVG-иконкой.
5. **Громкость и Mods.** Иконка громкости зависит от уровня; в попапе подпись
   «This track» или «All tracks»; колесо мыши на кнопке меняет громкость на 5%.
   Клик по иконке открывает попап, как сейчас. У кнопки Mods при активном моде
   акцентный цвет и бейдж со скоростью.
6. **Mute:** кнопка в попапе громкости и клавиша M. Хранится на клиенте как
   общее состояние плеера на время сессии, отдельно от громкости: не меняет
   и не сохраняет громкость (T12).
7. **Подтверждение и тосты.** Удаление плейлиста и «Clear all» очереди идут через
   диалог. «Clear upcoming» без диалога. Тост 1 секунда, **без Undo**, при
   добавлении в очередь, удалении плейлиста и очистках.
8. **Баннер подключения** не сдвигает окно: оверлей, различает «подключаюсь»
   и «ошибка».
9. **Длительность** показывается в карточках Songs и плейлиста.
10. **Выбранная карточка:** акцентная рамка 1 px **как сейчас** плюс лёгкая
    подсветка фона; в карточке плейлиста та же рамка вместо белой с голубым
    свечением. Фокус клавиатуры на карточках не менять.
11. **Убрать** фильтры All musics и Tags. **Оставить** Shuffle и Repeat
    (неактивные).
12. **Пустые состояния,** скелетоны загрузки, кнопка очистки в поиске,
    иконка-заглушка вместо пустой обложки.
13. **Плеер:** заливка прогресса акцентом (сейчас это баг), зона перемотки
    24 px, время под курсором, Space и стрелки ←/→ (±5 с), M. Фокус на поле
    поиска только явно: по клику или по Ctrl+F (поле активной вкладки), при
    входе в Songs он не переносится. Плавная смена обложки.
14. **Очередь** остаётся модальной, без мини-плеера и без индикатора
    «играет». Секции History / Now playing / Up next, приглушённая история,
    действия по наведению, счётчик в заголовке, иконка и счётчик на кнопке очереди.
15. **Шапка открытого плейлиста:** число треков, Add to queue, Play.
16. **Settings:** один шрифт и стиль заголовков, группы в карточках, пояснения.
17. **Окно папок:** статус словами (Will be added / removed / refreshed),
    без ссылки «Need help?», подпись «Refresh import» на английском.
    Цвета бейджей STABLE и LAZER **не меняются**.
18. **Тултипы и полосы прокрутки** в общем стиле. Кольца фокуса у кнопок
    **не добавлять**: пользователь убрал их намеренно.
19. **Токены:** цвета и длительности в `Theme`; исчезают одиночные литералы
    `#c142b0` и `#69c9ff`.

Отклонено пользователем: индикатор «сейчас играет» и эквалайзер где-либо;
любые изменения контраста (акцент `#9366ed`, muted `#767982`, цвета бейджей
остаются как есть); мини-плеер в очереди; Undo.

Вне объёма: настройка «Reduce motion», подсказки горячих клавиш в меню,
общая длительность очереди и плейлиста (нет числовых данных), изменение
перетаскивания очереди, немодальная очередь.

Известные расхождения предпросмотра с решениями (в карточках приоритет у решений):
в предпросмотре иконки очереди и вкладки Playlists почти одинаковы, в реализации
они разные (T13); предпросмотр показывает общую длительность и бейдж очереди,
для них нужны данные, которых может не быть (T13, T14).

## Общие правила для всех карточек

Прочитать перед работой: [AGENTS.md](../../AGENTS.md),
[docs/agent/frontend.md](../agent/frontend.md),
[процедуру GUI](../../.agents/skills/osu-radio-gui/SKILL.md).

- Рабочее дерево на момент планирования чистое, HEAD `74c119a`. Перед правкой
  выполнить `git status`; чужие незавершённые изменения не трогать.
- Qt 6.8, QtQuick.Controls.Basic (`import QtQuick.Controls.Basic as Basic`),
  нативные контролы; клавиатурное поведение и фокус контролов сохранять.
  Для API Qt использовать актуальную документацию через Context7 по
  [процедуре проекта](../agent/development.md#context7-and-source-evidence).
- Новые QML-файлы в `apps/osu-radio-qt/qml/` подхватываются `build.rs`
  автоматически (`files_under("qml")`); `qml/components/qmldir` описывает только
  синглтон `Theme`. Новые ассеты в `assets/` попадают в ресурсы автоматически,
  но требуют записи в манифест декодирования (см. T02).
- Предпросмотр охватывает не все кнопки приложения. Если карточка меняет общий
  компонент или шаблон, нужно найти все места использования (`rg` по
  `apps/osu-radio-qt/qml`) и применить изменение единообразно, включая
  `Gallery.qml`, который использует те же компоненты.
- Сохранять `objectName`, на которые ссылаются пробы в
  `apps/osu-radio-qt/tests/` (`AdapterProbe.qml`, `VisualProbe.qml`,
  `launch_smoke.rs`). Если поведение карточки обоснованно меняет ожидание
  пробы, обновить пробу и описать это в отчёте.
- Границы не менять: клиентские VM, адаптеры, сервер и протокол не трогать,
  если карточка не говорит обратного. Если без этого не обойтись, остановиться
  и вынести вопрос владельцу.
- Не использовать `--all-features`.
- Визуальную и десктопную проверку выполняет пользователь. Офскрин-пробы
  не проверяют размытие, GPU и работу оконного менеджера. Невыполненное
  записывать в отчёт как непроверенное.
- Утверждения в `docs/agent/frontend.md`, которые карточка сделала неверными,
  править в той же карточке минимально; итоговую сверку выполняет T19.

## Общие проверки

Команды из [development.md](../agent/development.md) (раздел Qt frontend), из
корня репозитория:

```sh
cargo test -p osu-radio-client --lib --locked
cargo test -p osu-radio-client --features mock --lib --locked
cargo test -p osu-radio-qt --locked -- --test-threads=1
python3 -B -m unittest discover -s apps/osu-radio-qt/tests -p 'test_*.py' -v
cargo build -p osu-radio-qt --locked
apps/osu-radio-qt/scripts/lint-qml.sh            # после сборки
cargo clippy -p osu-radio-client --features mock -p osu-radio-qt --all-targets --locked -- -D warnings
cargo fmt -p osu-radio-client -p osu-radio-qt --check
```

Галерею (`cargo run -p osu-radio-qt --locked -- --component-gallery`) не нужно
запускать агенту, если нет доступного графического сеанса. Набор проверок
под конкретную карточку указан в ней; перед сдачей прогонять минимум
`lint-qml.sh` и связанные `offline_*` тесты.

все). Такие карточки выполнять последовательно, в порядке номеров, или
разводить по разным веткам с осторожным слиянием.

Рекомендуемый порядок: T01, T02, T03, T04, затем T05–T11 и T14–T18 в любом
порядке с учётом зависимостей, T12 после T11, T13 после T06, T19 последней.
