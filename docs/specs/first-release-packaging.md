# Установщики и Linux-пакеты первого релиза osu! radio

Статус: объём пересогласован 2026-10-29; реализация и независимая проверка T10 частичные, итоговая приёмка ожидает окончательный комплект T09.
Основание: обсуждения с пользователем 2026-10-27 и 2026-10-29 через SDD.

Первый релиз включает только Windows Setup, Arch `osu-radio-bin` и `osu-radio-git`.
Windows — основная пользовательская платформа. AppImage и поддержка Ubuntu
отложены; отдельный бинарный архив для Arch `-bin` остаётся обязательным.

## Сценарий и результат

Пользователь получает osu! radio для Windows или Arch Linux, устанавливает либо
запускает готовый комплект, добавляет существующую установку osu!stable или
osu!lazer через текущий интерфейс, импортирует библиотеку и слушает музыку.
Подготовка `.env`, ручной запуск сервера и отдельная настройка БД не нужны.

Версия приложения и релиза остаётся **`0.1.0-alpha`**, включая согласованные
текущие доработки. Все поставляемые варианты предназначены для **x86_64**.

Эта задача расширяет [прежнюю Arch-спецификацию](arch-linux-release.md).
Её материалы и свидетельства переиспользуются; они не доказывают готовность
нового комплекта. В новой задаче отменяется прежнее исключение иконки,
добавляются Windows, Arch-варианты `-git`/`-bin` и переход помощника
на .NET 10. Идентификаторы R ниже относятся к этому документу.

## Согласованные требования

### R1. Windows Setup.exe

- Поддерживаются Windows 10 22H2, Windows 10 LTSC 2021 и Windows 11, x86_64.
  Эти версии уже согласованы в техническом плане; матрица Windows сохраняется.
- Поставляется один Setup.exe. По умолчанию установка выполняется для текущего
  пользователя; доступен выбор установки для всех пользователей с необходимыми
  правами.
- Установщик доставляет приложение, локальный сервер, помощник lazer,
  необходимые Qt/QML-компоненты, плагины и прочие зависимости запуска.
  Пользователь не устанавливает средства разработки и не настраивает runtime
  вручную; необходимые компоненты доставляются выбранным способом упаковки.
- Приложение доступно в меню «Пуск» и в штатном списке установленных программ
  Windows с возможностью удаления.
- Обновление существующей установки заменяет компоненты приложения с
  сохранением пользовательских данных по R6.

### R2. Обычный Arch-пакет `osu-radio` — исключён

По решению пользователя от 2026-10-27 обычный source-пакет в первый релиз не входит.
Arch покрывают `osu-radio-git` и `osu-radio-bin` (R3). Номер R2 сохранён, чтобы
не менять ссылки на R3–R9.

### R3. Arch-пакеты `osu-radio-git` и `osu-radio-bin`

- `osu-radio-git` собирает актуальную основную ветку из Git; пакетная версия
  различает ревизии исходников и корректно отражает их порядок.
- `osu-radio-bin` устанавливает готовые бинарники конкретного релиза для актуального Arch x86_64,
  проверяя контрольные суммы. Rust, C++ и .NET SDK для установки не нужны.
  Необходимые системные runtime-зависимости объявлены в пакете.
- Для `-bin` поставляется отдельный бинарный архив для системной установки
  в Arch с приложением, сервером и helper. Сборка и проверка выполняются в Arch
  с системными зависимостями; переносимость на другие дистрибутивы не требуется.
- Оба Arch-варианта предоставляют одно приложение, имеют корректные
  `provides`/`conflicts`, устанавливают одинаковые команды запуска и используют
  существующие пользовательские данные. Одновременно варианты не устанавливаются.
- Каждый вариант имеет собственную актуальную `.SRCINFO` и инструкцию.
  Смена варианта не выполняет reset БД. Совместимость данных при переходе
  между разными ревизиями определяется существующими миграциями; произвольный
  откат схемы не добавляется.

### R4. AppImage — отложен

По решению пользователя от 2026-10-29 AppImage, база Ubuntu 22.04 и матрица
других Linux-дистрибутивов не входят в первый релиз. Номер R4 сохранён;
отложенное требование не считается выполненным. Готовые бинарники для Arch
по-прежнему обязательны по R3. Возвращение к переносимому Linux-комплекту —
отдельная задача, без обещания совместимости текущего архива с другими ОС.

### R5. Запуск и полный пользовательский сценарий

- Каждый вариант запускается от обычного пользователя из произвольного рабочего
  каталога, без `.env` и переменных настройки osu! radio.
- Приложение автоматически запускает принадлежащий ему локальный сервер;
  используется SQLite, каталог и БД создаются при первом запуске.
- Компоненты работают после удаления исходников и каталога сборки.
- Через текущий UI отдельно добавляются stable и lazer, импортируется библиотека
  и воспроизводится трек с реальным аудиовыходом.
- Исходные файлы osu! читаются без изменения. Сохраняются текущие владение
  дочерним сервером, завершение процессов и очистка временного аудио.

### R6. Пользовательские данные

- Windows использует подходящие пользовательские каталоги для БД и прочих
  создаваемых данных; существующие ключи и способ хранения Qt-настроек сохраняются.
  Linux сохраняет текущие XDG-каталоги и поддерживаемые переопределения.
- Данные не записываются в каталог установленной программы.
- Обновление, переустановка и штатное удаление приложения сохраняют библиотеку,
  пользовательские плейлисты и настройки.
- Обычный запуск и пакетные операции не выполняют reset БД. Несовместимая база
  не удаляется и не заменяется новой автоматически; существующая политика
  миграций и явного reset сохраняется.

### R7. Релизный комплект и воспроизводимость источника

- Релизные Windows- и Linux-артефакты собираются из одних окончательно
  зафиксированных исходников. `-git` является отдельным вариантом из ветки.
- Версия Qt-приложения, сервера, сведений «О приложении» и релиза —
  `0.1.0-alpha`. Arch использует существующее представление `0.1.0alpha`;
  `-git` дополнительно отражает ревизию.
- Получение артефактов автоматизировано в CI. Комплект включает Setup.exe,
  бинарный архив для Arch `-bin`, два Arch-рецепта (`-git`, `-bin`) с `.SRCINFO`, SHA-256,
  необходимые лицензии и краткие инструкции установки, обновления и удаления.
- Лицензионные материалы сверяются с фактически поставляемыми компонентами,
  включая добавленные Qt/.NET runtime-файлы; старый список системных зависимостей
  Arch сам по себе не описывает новый комплект.
- Идентификатор исходного commit и параметры сборки позволяют установить,
  из чего получен каждый артефакт. Решение по существующему тегу приведено ниже.

### R8. Помощник lazer на .NET 10 LTS

- В задачу входит проверка совместимости существующего Realm-помощника с
  .NET 10 LTS и переход при успешной проверке.
- Проверка охватывает реальное чтение Realm, NDJSON-контракт, нативные библиотеки
  Windows/Linux и сохранность входных файлов. Генератор тестовых Realm-фикстур
  и связанные инструкции/рецепты приводятся в соответствие с выбранным runtime.
- Если совместимость не подтверждается, R8 остаётся незавершённым: фиксируются
  препятствие и необходимое решение пользователя. Вернуться к .NET 8 и объявить
  требование выполненным нельзя.
- Причина перехода: поддержка .NET 8 заканчивается 10 ноября 2026 года,
  см. [официальную политику Microsoft](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

### R9. Временная иконка

- Переиспользуется существующее
  [лого lazer](../../apps/osu-radio-qt/assets/logos/lazer.png).
- Из него подготавливаются необходимые пакетные представления для Windows,
  Arch desktop entry. Новый дизайн не требуется.
- Сохраняются существующие сведения о происхождении и разрешении на
  распространение из [описания ассетов](../../apps/osu-radio-qt/assets/SOURCES.md)
  и [лицензионных материалов](../../packaging/arch/licenses/README.md).

## Приёмка

Уточнение пользователя 2026-10-29: для проверки T08 достаточно фактической
сборки и проверки настоящего установщика через Wine; нативная Windows-проверка
отдельно отмечается как непроведённая. Проверка фиктивного пустого установщика
не подтверждает работу приложения. Остальные требования к составу и функциям
комплекта сохраняются; это уточнение не доказывает совместимость с матрицей ОС.

Проверки выполняются на отдельных профилях/БД и явно выбранных тестовых
установках osu!, без неограниченного поиска по всем дискам. Нужны Windows 10 22H2,
LTSC 2021 и Windows 11, чистое актуальное Arch-окружение, stable/lazer-библиотеки и
реальный аудиовыход. Конкретные версии тестовых ОС фиксируются в результатах.

| Требование | Проверка и ожидаемый результат |
| --- | --- |
| R1 | На чистых Windows 10/11 без SDK и Qt проверить оба режима установки, запуск из меню, обновление и штатное удаление. Зависимости доступны без ручной подготовки пользователем. |
| R2 | Исключён из первого релиза; проверка не требуется. |
| R3 | Собрать и установить оба варианта отдельно (с проверкой `.SRCINFO`, checksum, состава, desktop entry и запуска после удаления build tree); проверить источник и версии, отсутствие SDK у `-bin`, пакетные конфликты и смену варианта при совместимой схеме без потери данных. |
| R4 | Отложено за пределы первого релиза решением от 2026-10-29; проверка не требуется. |
| R5 | Для каждого установленного варианта: запуск без настройки → импорт stable → слышимый звук; отдельно lazer. Закрытие завершает принадлежащие приложению процессы, повторный запуск успешен, исходники osu! не изменены. |
| R6 | Сохранить библиотеку, плейлист и настройки; проверить restart, update, reinstall, uninstall/reinstall. Проверить прежние XDG overrides, Windows-пути с пробелами/кириллицей и отказ без сброса несовместимой БД. |
| R7 | Сверить commit, версии и SHA-256 артефактов, инструкции, `.SRCINFO` и фактические лицензии; повторить автоматизированную сборку из зафиксированного источника. |
| R8 | Существующие тесты протокола/реальных Realm-фикстур на .NET 10 и нативный установленный helper на Windows/Linux; затем настоящий lazer import из готового комплекта. |
| R9 | Проверить иконку в Windows-меню и списке программ, Arch desktop entry; сверить provenance/notices. |

Расширять существующие тесты конфигурации и поиска helper только для новых
правил путей, приоритетов и ошибок. Риски взаимодействия runtime, Qt, launcher
и helper проверяются на установленном комплекте. Сборка или offscreen-галерея
не заменяет native GUI, реальный импорт и слышимый звук.
Следовать [матрице разработки](../agent/development.md#verification-matrix);
несовместимые backend features не объединять через `--all-features`.

## Границы и публикация

- AppImage, Ubuntu и переносимость на остальные Linux-дистрибутивы отложены
  решением от 2026-10-29. deb/rpm, Windows ZIP и ARM64 также вне первого релиза.
- Существующий `v0.1.0-alpha` в Arch-рецепте указывает на прежние исходники.
  Пользователь подтвердил включение текущих доработок при той же версии
  приложения. Перед публикацией требуется зафиксировать финальный commit и
  выполнить уже выбранный в плане перенос `v0.1.0-alpha` на него по отдельному
  поручению. Сохранить прежние commit/checksums и проверить новую привязку
  исходников по R3/R7; старый архив нельзя выдавать за новый код.
- Этот документ не подтверждает перенос тега, commit/push, публикацию GitHub
  Release или AUR. Здесь согласованы требования к подготовке комплекта.
- Если совместимость Realm или целевых Windows/Arch недостижима выбранным
  способом сборки, фиксируется препятствие; требования не сужаются молча.

## Фактическое состояние

- При подготовке документа проверены существующие пути и механизмы в исходниках,
  версии приложений, `net8.0`/Realm `20.1.0` и наличие лого lazer.
- Существующие результаты прежнего Arch-релиза остаются в
  [его спецификации](arch-linux-release.md); на новый комплект не переносятся.
- Действующие R1, R3, R5–R9 пока не приняты по этой задаче; R2 исключён, R4 отложен. При подготовке документа сборки,
  установка, .NET 10, целевая Linux-матрица и пользовательские сценарии
  не выполнялись; результаты реализации добавляются ниже.
- При реализации сюда добавляются для каждого R место реализации, выполненная
  проверка и фактический результат, с отдельным указанием непроверенных сред.

2026-10-27, [T01](../impl/first-release-packaging/T01.md), часть R7/R8:
helper и генератор переведены на .NET 10 с Realm 20.1.0; Linux CI выбирает SDK 10.
На Arch Linux x64 прошли build-script проверки, real-helper набор для dev/FDD/SCD,
проба self-contained без системного .NET с неизменными Realm SHA-256, Clippy и fmt.
Оба Windows publish-каталога собраны через cross-publish, нативно не запускались.
R8 остаётся незавершённым: Windows-среды нет; установленный комплект и настоящая
lazer-библиотека ещё не проверены. Версии и подробные свидетельства — в T01.

2026-10-29, изменение объёма: остаются Windows Setup и два Arch-варианта.
T01–T04 сохраняют выполненную работу и пределы проверок. Старый Ubuntu-кандидат
T05 сохранён как историческое свидетельство; новый архив для Arch ещё нужно
собрать и проверить. T06 отложена, T07/T09/T10 приведены к новой матрице.
Падения старых Qt 6.8.3-проб не закрыты, но воспроизведение именно на Ubuntu
больше не является критерием релиза; на целевых Windows/Arch завершение GUI
и дочерних процессов остаётся обязательной проверкой. При пересмотре объёма
проверены документы и ссылки; сборки и пользовательская приёмка не запускались.
