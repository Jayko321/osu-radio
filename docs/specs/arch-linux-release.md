# Релиз osu! radio для Arch Linux

Статус: требования согласованы; упаковка и изменения приложения ещё не реализованы и не проверены в рамках этой задачи.
Основание: обсуждение с пользователем 2026-10-17.

## Сценарий и результат

Пользователь работает на Arch Linux с графической средой и уже установленным
osu!stable либо osu!lazer. Он получает полный комплект упаковки, собирает пакет,
устанавливает его и открывает osu! radio из меню приложений KDE. Через существующий
интерфейс добавляет свою установку osu!, импортирует библиотеку и слушает музыку.

Первый релиз — `0.1.0-alpha`. Обычный запуск не требует подготовки `.env`, настройки
адреса базы или отдельного запуска сервера. SQLite используется по умолчанию.

Итоговый путь: **собрал → установил → открыл из меню → добавил osu! → слушаешь**.

## Согласованные требования

### R1. Полная сборка на чистом Arch Linux

- Полный PKGBUILD позволяет собрать и установить пакет командой `makepkg -si`.
- Исходное окружение содержит Arch Linux, графическую среду, установленный osu!
  и стандартный для сборки пакетов `base-devel`. Дополнительные зависимости сборки
  и запуска объявлены в метаданных пакета; необходимые шаги описаны в инструкции.
- Первичная загрузка исходников и зависимостей требует доступа к интернету.
- Сборка не зависит от личных каталогов разработчика, его кэшей, `.env`
  или ранее собранных файлов.

### R2. Полный комплект установленных компонентов

Пакет доставляет Qt-приложение, локальный сервер и помощник чтения базы lazer
со всеми необходимыми для выбранного способа поставки файлами и зависимостями.
Установленное приложение работает после удаления исходников и каталога сборки.
Пути к компонентам ведут к установленным файлам, а не к результатам сборки
на машине разработчика.

### R3. Запуск без ручной настройки; SQLite по умолчанию

- Приложение запускается из меню KDE и терминала от обычного пользователя.
- Локальный сервер запускается автоматически существующим механизмом приложения.
- По умолчанию используется SQLite; отдельный сервер БД не нужен.
- Каталог и файл локальной базы создаются автоматически при первом запуске.
- Пользователю не требуется создавать или редактировать `.env`, задавать
  переменные окружения, адрес базы или локального сервера.
- Запуск не зависит от текущего рабочего каталога.

### R4. Существующие установки stable и lazer

Через текущий интерфейс можно добавить существующую установку osu!stable
либо osu!lazer, импортировать библиотеку и воспроизвести трек.
Подходит также установка osu!, выполненная вручную, без пакета Arch/AUR.
Приложение сохраняет доступ к исходным файлам osu! только для чтения.

### R5. Рекомендуемые зависимости osu!

Подходящие пакеты osu!stable и osu!lazer указываются в `optdepends`
с пояснениями. Их отсутствие в пакетной базе системы не блокирует сборку
или установку osu! radio. Не требуется устанавливать одновременно оба варианта.

`optdepends` информирует пользователя о дополнительных пакетах; автоматическая
установка osu! не входит в задачу. Wine не требуется самому osu! radio для чтения
файлов stable; окружение запуска игры относится к выбранному способу установки osu!.
Точные актуальные имена рекомендуемых пакетов проверяются при подготовке PKGBUILD.

### R6. Релизный комплект и пункт меню KDE

- Релизный комплект содержит PKGBUILD, `.SRCINFO`, `.desktop`, необходимые лицензии
  и короткую инструкцию сборки, установки и обновления.
- `.desktop` устанавливается в `/usr/share/applications/`.
- В меню KDE виден osu! radio с корректным названием и категорией аудиоприложений.
- Запись запускает установленное приложение без открытия терминала.
- Собственной иконки пока нет: этот релиз поставляется без неё. Создание
  или подбор иконки в задачу не входит.

### R7. Приёмка установленного приложения

Необходимо отдельно проверить чистую сборку и пользовательский сценарий
установленного приложения: запуск из меню KDE, импорт stable/lazer, реальное
воспроизведение, повторный запуск и сохранение данных при обновлении.
Успешная сборка или запуск офлайн-галереи сами по себе не доказывают готовность
релиза. Матрица проверок приведена ниже.

### R8. Версионный релиз 0.1.0-alpha

- Имя пакета — `osu-radio`.
- Версия приложения и релиза — `0.1.0-alpha`.
- Пакет собирается из конкретного тега релиза, а не из изменяемого состояния ветки.
- Для PKGBUILD версия представляется как `pkgver=0.1.0alpha`: дефис в `pkgver`
  недопустим. Это представление той же версии в формате Arch.

### R9. Пользовательские каталоги и сохранность данных

- База, настройки, кэш и журналы, если они создаются, размещаются
  в соответствующих пользовательских каталогах XDG с учётом переменных XDG.
- Обновление и переустановка пакета сохраняют библиотеку и пользовательские настройки.
- Временные аудиофайлы очищаются существующим механизмом клиента.
- Обычный запуск, обновление и переустановка не сбрасывают существующую базу.
- Этот пункт не вводит новую систему журналирования или новый контракт хранения
  настроек. Существующие ключи QSettings и границы владения данными сохраняются.

### R10. Информация о приложении

В настройках или небольшом окне «О приложении» доступны версия `0.1.0-alpha`,
лицензия и ссылка на проект. Версия соответствует поставляемому релизу.
Конкретное размещение определяется при технической проработке в рамках текущего UI.

## Границы и отложенные функции

- Задача охватывает Arch Linux: упаковку, необходимые изменения запуска,
  размещения данных, сведения о версии и связанную документацию.
- Сохраняются [утверждённая архитектура](../agent/architecture.md), существующий UI
  добавления osu!, импорт, воспроизведение и владение дочерним сервером.
- Новые onboarding и ограничение приложения одним экземпляром не входят в alpha.
- Собственная иконка откладывается до её появления у пользователя.
- Новая обработка ошибок, диагностический UI и новая система журналирования
  в эту задачу не входят. Существующая обработка ошибок сохраняется.
- Существующее закрытие приложения сохраняется и проверяется: специально
  переделывать его в рамках релиза не требуется.
- MPRIS отложен пользователем на следующий релиз.
- Публикация в AUR, создание удалённого тега/релиза и отправка изменений
  не поручены этой спецификацией.

Пользовательских вопросов по результату не осталось. Способ поставки .NET-помощника,
точный состав зависимостей и пути установленных компонентов требуют технической
проработки; эта спецификация не выбирает новые зависимости или архитектуру.

## Приёмка

Сборка проверяется в чистом Arch chroot, работа приложения — отдельно в реальной
графической сессии KDE. Для приёмки нужны доступный аудиовыход, тестовые библиотеки
stable и lazer с воспроизводимыми треками и отдельный пользовательский профиль
или изолированные каталоги данных. Проверки не используют рабочую БД разработчика.
Следовать [матрице разработки](../agent/development.md#verification-matrix),
не объединять несовместимые backend features через Cargo `--all-features`.

| Требование | Проверка и ожидаемый результат |
| --- | --- |
| R1 | Собрать пакет в чистом Arch chroot без личных кэшей и предварительных артефактов. Все зависимости известны упаковке; ручная правка исходников и установка необъявленных зависимостей не нужны. |
| R2 | Установить пакет в отдельное окружение и удалить исходники/каталог сборки. Запуск приложения, сервера и реального помощника lazer остаётся рабочим. |
| R3 | В чистом пользовательском профиле без `.env` и переменных настройки osu! radio открыть приложение из меню и терминала из произвольного каталога. Сервер запускается автоматически; создаётся SQLite-база. |
| R4 | Отдельно добавить stable и lazer через существующий UI, импортировать и воспроизвести трек с реальным аудиовыходом. Проверить сохранность исходных файлов. Повторить с установкой osu!, не зарегистрированной как пакет. |
| R5 | Проверить `optdepends` и итоговые метаданные пакета. Пакет собирается и устанавливается без пакетов osu!/Wine; это не подменяет отдельную проверку воспроизведения на существующей библиотеке. |
| R6 | Проверить `.SRCINFO`, комплект лицензий и инструкцию, валидность `.desktop`; после установки найти и запустить osu! radio из меню KDE без терминала. Собственная иконка не требуется. |
| R7 | Пройти весь путь «собрал → установил → открыл из меню → добавил osu! → слушаешь». Закрыть приложение, проверить существующее завершение принадлежащего ему сервера и повторный запуск. |
| R8 | Проверить источник конкретного тега, версию релиза `0.1.0-alpha` и пакетную версию `0.1.0alpha`; состояние текущей ветки не меняет собираемый релиз. |
| R9 | Проверить стандартные каталоги и переопределённые XDG-пути. Сохранить импортированную библиотеку и настройки, перезапустить, обновить и переустановить пакет: данные остаются. Проверить очистку временного аудио после нормального завершения. |
| R10 | В установленном приложении открыть сведения о приложении: доступны корректные версия, лицензия и ссылка на проект. |

## Фактическое состояние и свидетельства

- В рамках подготовки спецификации изучены сборка Qt, запуск сервера,
  конфигурация БД и построение/вызов помощника lazer.
- Правила `pkgver`, `optdepends` и пользовательских каталогов сверены
  с [PKGBUILD(5)](https://man.archlinux.org/man/PKGBUILD.5),
  [Desktop Entry Specification](https://specifications.freedesktop.org/desktop-entry/latest/)
  и [XDG Base Directory Specification](https://specifications.freedesktop.org/basedir/latest/).
- Создана только эта спецификация. Упаковка и исходный код приложения не изменены.
- Ни один критерий R1–R10 ещё не отмечен выполненным: чистая сборка, установка,
  реальная KDE-сессия, импорт/звук и обновление пакета в этой задаче не проверялись.

Существенные уточнения обсуждения: SQLite по умолчанию; запуск без `.env`;
`.desktop` без собственной иконки; стандартные каталоги XDG; сведения о версии;
onboarding и один экземпляр отложены; существующее закрытие сохраняется;
новая обработка ошибок/журналирование исключены; MPRIS перенесён на следующий релиз.
