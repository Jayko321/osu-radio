# Поиск по библиотеке osu!radio

Статус: спецификация согласована для сохранения; реализация и её приёмка не выполнены.
Дата: 2026-11-06.

## Сценарий и результат

Пользователь вводит в поиске Songs обычный текст, условия по полям или их
сочетание. Приложение показывает подходящие аудиотреки, сохраняя текущую
сортировку и все связанные с найденным аудио сложности.

Основание: исследование поиска osu!lazer и последующие решения пользователя:

- сохранить совпадения на уровне аудиофайла, включая совпадения в разных
  связанных сложностях и наборах;
- не вводить отдельную поддержку `UserTags`;
- исключить OD, HP/DR, AR, CS;
- включить текстовые поля, кавычки, исключения, BPM, длительность, сыгранность,
  последнее проигрывание, online ID набора, stars, статусы и даты
  ranked/submitted;
- для `played`/`lastplayed` использовать импортированные даты osu!;
- для `length` использовать полную длительность аудио.

Источник для сравнения — официальный
[ppy/osu, ревизия 77df204df2e217cdbf884cf4ce9aaa442ce21e07](https://github.com/ppy/osu/tree/77df204df2e217cdbf884cf4ce9aaa442ce21e07):
[парсер](https://github.com/ppy/osu/blob/77df204df2e217cdbf884cf4ce9aaa442ce21e07/osu.Game/Screens/Select/FilterQueryParser.cs),
[текстовые условия](https://github.com/ppy/osu/blob/77df204df2e217cdbf884cf4ce9aaa442ce21e07/osu.Game/Screens/Select/FilterCriteria.cs#L195-L266),
[сопоставление](https://github.com/ppy/osu/blob/77df204df2e217cdbf884cf4ce9aaa442ce21e07/osu.Game/Screens/Select/BeatmapCarouselFilterMatching.cs).
Требования ниже определяют поведение osu!radio; полная совместимость со всеми
особенностями lazer не заявляется.

## Требования

### R1. Единица результата — аудиотрек

Сохраняется существующая группировка по `audio_source_id`. Разные слова и
условия могут совпасть в разных сложностях или наборах, связанных с одним
аудио. Поиск не сокращает список сложностей найденного трека до совпавших.

### R2. Обычный текст

Каждое слово должно встретиться хотя бы в одном доступном поле: исполнитель,
название, mapper, источник `source`, название сложности или существующие теги
osu!radio. Для исполнителя и названия проверяются обычное и Unicode-написание
независимо от настроек отображения.

Между словами действует **И**, между полями для одного слова — **ИЛИ**.
Сохраняется Unicode-приведение к нижнему регистру; транслитерация и удаление
диакритики не добавляются.

### R3. Поиск по текстовым полям

| Поле | Область поиска |
| --- | --- |
| `artist` | Исполнитель, включая Unicode-вариант |
| `title` | Название трека, включая Unicode-вариант |
| `creator`, `author`, `mapper` | Имя автора карты |
| `diff` | Название сложности |
| `source` | Источник из метаданных карты |
| `tag` | Существующие теги osu!radio |

Условие проверяет только указанное поле. Совпадение `xi` в тегах не
удовлетворяет `artist=xi`.

Отдельная семантика lazer `UserTags` не вводится. Существующий импорт, который
объединяет обычные и пользовательские теги, сохраняется; разделять или удалять
уже импортированные теги эта задача не должна.

### R4. Кавычки и текстовые операторы

| Запрос | Значение |
| --- | --- |
| `artist=xi` | Подстрока в исполнителе |
| `artist="xi"` | Отдельное слово или фраза в исполнителе |
| `artist="xi"!` | Полное совпадение поля |
| `"freedom dive"` | Цельная фраза в одном из полей обычного поиска |
| `artist!=xi` | Исключение исполнителя, содержащего `xi` |

Сопоставление не учитывает регистр. Границы слов для кавычек соответствуют
Unicode-границам `\b`, как в lazer. Символ `!` после закрывающей кавычки означает
полное совпадение.

Поддерживаются `=` и его синоним `:`, а также `!=` и `!:`. Между именем поля,
оператором и значением пробелы не ставятся. Пробелы внутри значения допускаются
в кавычках.

### R5. Совместное применение условий

Свободный текст и распознанные условия объединяются через **И**. Повторные
условия также должны выполняться совместно; они не перезаписывают друг друга.

Отрицательное текстовое условие исключает весь аудиотрек, если совпадение
найдено хотя бы в одной связанной записи. Например, наличие другой сложности
с пустым исполнителем не позволяет обойти `artist!=xi`.

Границы одного числового диапазона проверяются на одном значении: аудио с BPM
100 и 300 не удовлетворяет `bpm>=180 bpm<=200`.

### R6. Числовые фильтры

| Поле | Значение |
| --- | --- |
| `bpm` | Импортированный BPM карты |
| `star`, `stars`, `sr` | Сохранённый рейтинг сложности исходного игрового режима без модов |
| `length` | Полная длительность аудиофайла, включая части вне игровой карты |

Поддерживаются `=`, `!=`, `<`, `<=`, `>`, `>=` и соответствующие варианты с `:`.

Для BPM равенство использует допуск ±0,5 BPM с включёнными границами:
`bpm=180` соответствует диапазону `[179,5; 180,5]`. `!=` означает дополнение
этого диапазона среди известных значений. Операторы `<`, `<=`, `>` и `>=`
сравнивают с указанным числом без допуска; сдвиг этих границ из lazer не
переносится.

Stars перед сравнением усекаются вниз до двух знаков. Отсутствующий или
нерассчитанный рейтинг не считается нулём; самостоятельный пересчёт stars не
входит в задачу.

`length` принимает секунды, `m:ss`, `h:mm:ss` и значения с единицами `ms`, `s`,
`m`, `h`. Значения переводятся в одну единицу и сравниваются по фактической
длительности. Скорость воспроизведения и аудиомоды не меняют значения фильтров.

### R7. Статусы карт

Поддерживается `status` с именами `ranked`, `approved`, `qualified`, `loved`,
`pending`, `wip`, `graveyard`, `locallymodified`, `none`, без учёта регистра.

`status=ranked,loved` означает любой из перечисленных статусов.
`status!=ranked,loved` исключает аудио, имеющее связанные карты с этими
статусами. `none` означает неизвестный статус; значения разных источников
приводятся к общему смыслу, а не сопоставляются по необработанным числовым кодам.

Временное правило для stable: исходный код 2 объединяет `pending`, `wip` и
`graveyard` и нормализуется в `pending`; код 1 (`unsubmitted`) — в `none`.
Точные `wip`/`graveyard` различаются только при наличии этих сведений в
источнике. Ограничение нужно пересмотреть при изменении или удалении поддержки
stable; само удаление stable в эту задачу не входит.

### R8. Даты ranked/submitted

Поддерживаются:

- `ranked` — дата ранкинга набора;
- `submitted`, `created` — дата публикации набора.

Форматы: год, год-месяц, год-месяц-день; разделители `-`, `/` или `.`.
Календарные границы определяются в UTC.

Равенство обозначает целый период: `ranked=2024` — весь год,
`submitted=2024-03` — весь март. Соответственно, `ranked>2024` означает начиная
с 2025 года.

Неизвестная дата не удовлетворяет сравнению, включая `!=`. Дата импорта,
изменения файла или локального создания не подставляется вместо
ranked/submitted.

### R9. Сыгранность в osu!

`played` и `lastplayed` используют исключительно импортированные данные osu!,
отдельно от истории прослушивания osu!radio.

Последнее проигрывание аудио — наиболее поздняя известная дата среди связанных
сложностей.

- `played=true` — есть импортированная дата игры;
- `played=false` — такой даты нет;
- `lastplayed<7d` — последняя игра была менее семи суток назад.

Для `played` также принимаются `yes/no` и `1/0`. Для `lastplayed` число без
единицы означает дни; доступны `s`, `m`, `h`, `d`, `w`. Треки без известной даты
не удовлетворяют числовым условиям `lastplayed`.

`played=false` означает отсутствие сохранённой даты, а не доказательство, что
пользователь никогда не играл карту.

### R10. Online ID набора

Если весь свободный запрос — одно целое положительное число, дополнительно
проверяется online set ID связанных наборов. Обычные текстовые совпадения
этого числа сохраняются. Локальные ID базы и online ID отдельной сложности
в эту возможность не входят.

### R11. Неполные запросы и неизвестные данные

Неизвестное поле, неподдерживаемый оператор или невалидное значение остаются
обычным поисковым текстом. Ошибка ввода не должна ломать поиск или незаметно
превращать условие в отсутствие фильтра.

Неизвестные числовые значения не заменяются нулём и не удовлетворяют числовым
сравнениям. Неизвестные ranked/submitted в stable остаются неизвестными:
автоматическое получение недостающих данных из интернета не входит в задачу.

### R12. Совместимость

Сохраняются:

- пустой запрос показывает библиотеку;
- текущая сортировка, выбор трека и поведение воспроизведения;
- задержка поиска 200 мс, отмена предыдущего запроса и защита от устаревших
  ответов;
- общий смысл `q` для `/api/tracks` и `/api/beatmap-sets`;
- поддержка SQLite и PostgreSQL;
- библиотека, плейлисты и история при добавлении необходимых данных.

Поиск плейлистов и поиск настроек не меняются.

## Примеры

| Ввод или данные | Ожидаемый результат |
| --- | --- |
| `artist="xi"`; `xi` есть только в тегах | Трек не найден |
| `artist="xi"`; исполнитель `xi feat. …` | Трек найден |
| `artist="xi"!`; исполнитель `xi feat. …` | Трек не найден |
| `artist="xi" freedom` | Исполнитель соответствует условию, `freedom` найден в любом поле обычного поиска |
| `creator="Some Mapper"` | Поиск по имени mapper, без совпадений только по тегам |
| `easy hard`; слова находятся в разных сложностях одного аудио | Один трек со всеми его сложностями |
| `artist!=xi`; одна связанная запись содержит `xi` | Всё аудио исключено |
| `bpm>=180 bpm<=200`; значения связанных карт 100 и 300 | Трек не найден |
| `length>3m`; карта длится 2 минуты, аудио — 4 | Трек найден |
| `stars>=5 stars<6` | Есть связанная сложность с рейтингом в этом диапазоне |
| `status=ranked,loved submitted=2024` | Выполняются оба условия |
| `lastplayed>7d`; одна сложность сыграна месяц назад, другая вчера | Трек не найден |
| `ranked>=2024`; дата неизвестна | Трек не найден |
| Очистка строки | Возвращается библиотека с прежней сортировкой |

Переиспользуются:

- [метаданные](../../crates/radio-db/src/model/beatmap_metadata.rs),
  [модель карты](../../crates/radio-db/src/model/beatmap.rs) и
  [модель набора](../../crates/radio-db/src/model/beatmap_set.rs);
- [импорт тегов](../../crates/radio-services/src/tag.rs);
- импортированные даты osu! и их
  [существующий контракт](../agent/database.md#listening-history);
- существующее [определение длительности аудио](../../apps/osu-radio-server/src/routes/media.rs);
- [контракты поиска](../../crates/radio-services/src/tests/search.rs).

Stars, статусы, ranked/submitted и пригодная для поиска длительность потребуют
расширения существующих механизмов данных. Конкретная схема хранения и способ
подготовки длительности относятся к техническому плану.

В текущем [stable reader](../../crates/radio-scanner/src/stable/reader.rs)
данные о статусе и таблицах stars читаются с пропуском значений; отдельные
ranked/submitted в поддержанном локальном `osu!.db` отсутствуют.
[Lazer helper](../../tools/osu-lazer-realm-parser/Program.cs) пока не экспортирует
новые поля stars/status/ranked/submitted. Сохранённые stars могут отличаться от
свежего пересчёта lazer.

## Границы

Исключены:

- OD, HP/DR, AR, CS;
- divisor и mania-фильтры;
- отдельная семантика `UserTags`;
- логические `OR` и скобки;
- новая сортировка и изменения воспроизведения;
- самостоятельный пересчёт stars и автоматическое сетевое обогащение данных.

Локальные исходники osu! остаются доступны только для чтения. Полная
совместимость со всеми особенностями lazer не заявляется: в частности,
группировка по аудио, длительность полного аудиофайла, существующие теги и
совместное применение повторных условий определены требованиями osu!radio.

## Приёмка

Поведение R1–R12 реализовано и проверено в указанном ниже объёме. Автоматические
проверки не заменяют пользовательскую приёмку, native Windows или физическое
воспроизведение.

| Требования | Проверка |
| --- | --- |
| R1–R5 | Сервисные сценарии обычного текста, полей, Unicode, кавычек, исключений, повторных условий и совпадений между связанными сложностями; все сложности найденного аудио сохранены |
| R6 | Границы BPM/stars, диапазон на одном значении, неизвестные значения, форматы длительности и отличие полной длительности аудио от длины карты; независимость от аудиомодов |
| R7–R8 | Статусы и их списки, соответствие исходных значений общему смыслу, календарные границы UTC, неизвестные даты и отсутствие подмены локальными датами |
| R9 | Импортированные даты osu!, наиболее поздняя дата аудио, относительное время, отсутствие даты и независимость от истории osu!radio |
| R10–R11 | Online set ID вместе с текстовыми совпадениями, неизвестные/неполные условия, невалидные значения и отсутствие молчаливого снятия фильтра |
| R12 | Одинаковая семантика обоих HTTP endpoints, передача операторов и кавычек, сохранение сортировки, пустого запроса, отмены и отбрасывания устаревших ответов |
| R6–R9, R11–R12 | Импорт новых полей из stable/lazer и сохранность библиотеки, плейлистов и истории при обновлении схемы |

Основные сценарии поиска выполняются на сервисном уровне для SQLite и
PostgreSQL с переиспользованием существующих фикстур. HTTP-проверки покрывают
передачу запроса и контракт endpoints, не дублируя всю матрицу поиска.

Нужен один сквозной сценарий ввода в Songs: запрос с полем и кавычками,
проверка результата, очистка и восстановление списка с прежней сортировкой.
Проверка импорта использует явно заданные тестовые источники, без
неограниченного обхода пользовательских дисков.

Числовые требования к производительности пока не заданы. Сборка и количество
прошедших тестов сами по себе не подтверждают пользовательские сценарии.

Существующей библиотеке нужен Refresh для новых source-полей; stable объединяет
часть статусов в pending. Длительность поиска относится к последнему снимку,
а импорт дополнительно читает аудиофайлы. Числового требования к скорости нет.
Совместимость с пользовательскими установками, native Windows, визуальная и
пользовательская приёмка, физическое воспроизведение не проверены. CLI `store`
с относительным `--marker` сохраняет относительный путь, который последующий
Refresh отклоняет; проверка Refresh в T08 использовала абсолютный путь.
